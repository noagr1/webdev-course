קופה של בית קפה: מאפס ועד GitHub

משתנים תנאים לולאות פונקציות Git

בעמוד הזה נחבר את כל מה שלמדנו בשיעור לתוכנית אחת: קופה של בית קפה. הקופה יודעת כמה עולה כל מוצר, מחשבת את סכום ההזמנה, נותנת הנחה לסטודנטים ובשעת השמחה (Happy Hour), מוסיפה מע״מ ומדפיסה קבלה מסודרת. בסוף נעביר את הקוד לקבצים ב-VS Code ונשמור אותו ב-GitHub.

נבנה את הקופה בשלבים. בכל שלב יש עורך JavaScript עם כל הקוד עד אותו שלב. התוספת של השלב מסומנת בהערה // חדש, כך שקל לראות מה השתנה. לחצו "▶ הרצה" (או Ctrl+Enter) ותראו את הפלט בחלון השחור.

👀 לקוד הסופי

מה נתרגל כאן

  • לפרק בעיה גדולה לחלקים קטנים, ולכתוב פונקציה לכל חלק
  • להשתמש בקבועים (const) במקום "מספרי קסם" שמפוזרים בקוד
  • לקבל החלטות עם if ו-switch
  • לבנות מחרוזות עם template literals ולחזור על פעולות עם לולאה
  • לבדוק קלט לא תקין ולצאת מפונקציה מוקדם עם return
  • להעביר קוד לקבצים אמיתיים, להריץ אותו בדפדפן ולשמור אותו ב-Git

בכיתה מומלץ לבנות את שלבים 1–4 יחד, בקצב של הכיתה (כ-20 דק׳), ולהשאיר את שלבים 5–8, האתגרים ומשימת ההגשה לבית. כדאי לעצור אחרי כל שלב ולשאול "מה הפונקציה הבאה שחסרה לנו?" לפני שמראים אותה. זה מתרגל את החשיבה של פירוק בעיה, שהיא החשובה ביותר בשיעור.

מחוון לבדיקת משימת ההגשה מופיע בסוף העמוד, בהערת מרצה.

שלב 0: מתכננים לפני שכותבים

לפני שכותבים שורת קוד, מתארים במילים פשוטות מה התוכנית צריכה לעשות. כך נראה התיאור של הקופה שלנו:

  1. בתפריט יש שני מוצרים: קפה ב-12 ₪ ועוגה ב-18 ₪ (המחירים לפני מע״מ).
  2. הלקוח מזמין כמה כוסות קפה וכמה פרוסות עוגה.
  3. סטודנטים מקבלים 10% הנחה. בשעת השמחה, בין 16:00 ל-18:00, כולם מקבלים 20% הנחה. ההנחות לא מצטברות: מקבלים את הגדולה מביניהן.
  4. אחרי ההנחה מוסיפים מע״מ של 18%.
  5. מדפיסים קבלה: שם בית הקפה, המוצרים, ההנחה, המע״מ והסכום לתשלום.
  6. אם הכמות לא הגיונית (למשל ‎-1 כוסות קפה), מציגים הודעת שגיאה ולא מדפיסים קבלה.

עכשיו מחפשים בתיאור את הפעולות. כל פעולה תהפוך לפונקציה קטנה עם שם ברור:

priceOf(item)כמה עולה מוצר אחד?
calculateTotal(coffees, cakes)כמה עולה כל ההזמנה, לפני הנחה?
discountRate(isStudent, hour)כמה אחוז הנחה מגיע ללקוח?
roundMoney(amount) ‏+ formatPrice(amount)עיגול לאגורות והצגה יפה: ‎₪49.56
printReceipt(...)מחברת את הכול ומדפיסה קבלה

למה כל כך הרבה פונקציות קטנות? לפונקציה קטנה קל לתת שם, קל לבדוק אותה לבד (מריצים אותה עם כמה ערכים ומסתכלים על התוצאה), וקל לתקן אותה בלי לשבור דברים אחרים. כשבית הקפה יעלה את מחיר הקפה, נשנה מקום אחד בלבד.

שלב 1: קבועים לתפריט

מתחילים מהנתונים שלא משתנים בזמן שהתוכנית רצה: שם בית הקפה והמחירים. שומרים אותם ב-const.

שימו לב לשמות: נהוג לכתוב קבועים "של הגדרות" באותיות גדולות עם קו תחתון, למשל COFFEE_PRICE. זה אומר לכל מי שקורא את הקוד: "זה ערך קבוע של התוכנית, לא משתנה רגיל".

למה לא לכתוב פשוט 2 * 12 + 18? המספר 12 לבד הוא "מספר קסם": מי שקורא את הקוד לא יודע מה הוא אומר. ואם המחיר ישתנה, נצטרך למצוא כל 12 בקוד ולנחש אם הוא מחיר קפה או משהו אחר. עם COFFEE_PRICE הקוד מסביר את עצמו, ומשנים את המחיר בשורה אחת.

נסו בעצמכם:

  • שנו את מחיר הקפה ל-14 והריצו שוב. כמה השתנה הסכום?
  • נסו לכתוב COFFEE_PRICE = 15; בסוף הקוד. איזו שגיאה מקבלים? למה?
  • חשבו בעצמכם הזמנה של 3 קפה ו-2 עוגות. תוצאה נכונה: 72.

שלב 2: כמה עולה מוצר? ‏priceOf

הפעולה הראשונה ברשימה שלנו: מקבלים שם של מוצר ומחזירים את המחיר שלו. זו החלטה עם כמה אפשרויות לפי ערך אחד, ולכן switch מתאים כאן במיוחד.

כמה דברים לשים לב אליהם:

  • אין צורך ב-break: ‏return יוצא מהפונקציה מיד, אז הוא גם יוצא מה-switch.
  • default תופס כל ערך שלא התאים לאף case. בלעדיו, הפונקציה הייתה מחזירה undefined עבור "פיצה".
  • ההשוואה היא בדיוק כמו ===: ‏'קפה ' עם רווח בסוף הוא כבר לא 'קפה'. נסו!
איך זה נראה עם if במקום switch? 
function priceOf(item) {
  if (item === 'קפה') return COFFEE_PRICE;
  if (item === 'עוגה') return CAKE_PRICE;
  return 0;
}

שתי הגרסאות נכונות. ‏switch נוח כשבודקים ערך אחד מול הרבה אפשרויות. ‏if גמיש יותר, כי אפשר לבדוק בו כל תנאי, למשל price > 100.

נסו בעצמכם: הוסיפו לתפריט מוצר שלישי, 'כריך' במחיר 28 ₪. צריך גם קבוע חדש וגם case חדש.

שלב 3: סכום ההזמנה ‏calculateTotal

עכשיו פונקציה שמקבלת כמויות: כמה כוסות קפה וכמה פרוסות עוגה. היא משתמשת ב-priceOf שכתבנו, כך שכל המחירים עדיין מגיעים ממקום אחד.

ככה בודקים פונקציה: מחשבים בראש (או במחשבון) את התשובה לכמה מקרים, כותבים אותה בהערה, ומשווים לפלט. כדאי לבדוק גם מקרי קצה, כמו הזמנה ריקה (0, 0). מתכנתים עושים את זה כל הזמן, ובהמשך הקורס נלמד לעשות את זה אוטומטית עם בדיקות.

‏return לעומת console.log

שימו לב ש-calculateTotal מחזירה את הסכום עם return ולא מדפיסה אותו. זה חשוב: מספר שחוזר מפונקציה אפשר להמשיך לחשב איתו (להוריד הנחה, להוסיף מע״מ). הדפסה רק מציגה טקסט על המסך, ואי אפשר לעשות איתה שום דבר אחר.

const subtotal = calculateTotal(2, 1); // 42, אפשר להמשיך לחשב
console.log(subtotal * 2);            // 84

🤔 בדקו את עצמכם: מה ידפיס הקוד הזה?

function total(coffees) {
  console.log(coffees * 12);
}
console.log(total(2) + 10);
  • 34
  • 24 ואחריו 34
  • 24 ואחריו NaN
  • שגיאה, והקוד נעצר

‏total(2) מדפיסה 24, אבל לא מחזירה כלום, כלומר מחזירה undefined. ואז undefined + 10 הוא NaN (Not a Number). אם נחליף את console.log בתוך הפונקציה ב-return, יודפס רק 34.

הבלבול בין return ל-console.log הוא הטעות הנפוצה ביותר בשיעור הזה. כדאי להדגים בכיתה גרסה של calculateTotal שמדפיסה במקום להחזיר, ואז להריץ console.log(calculateTotal(2, 1) * 2). הפלט יהיה 42 ואחריו NaN, וזו נקודה טובה לשאול את הכיתה למה.

שלב 4: הנחות ‏discountRate

נחזור לחוקי ההנחה מהתכנון: סטודנטים מקבלים 10%. בשעת השמחה (מ-16:00 ועד לפני 18:00) כולם מקבלים 20%. ההנחות לא מצטברות.

נכתוב שתי פונקציות:

  • isHappyHour(hour): מחזירה true או false. זו פונקציה קצרה מאוד, אז נכתוב אותה כ-arrow function.
  • discountRate(isStudent, hour): מחזירה את שיעור ההנחה כמספר עשרוני: ‏0.2, ‏0.1 או 0.

מה קורה כאן?

  • פרמטרים עם ברירת מחדל: ‏isStudent = false ו-hour = 12. אם קוראים ל-discountRate() בלי ערכים, הפונקציה משתמשת בברירות המחדל. זה מאפשר לכתוב discountRate(true) כשהשעה לא משנה.
  • הסדר של ה-if חשוב: בודקים קודם את שעת השמחה, כי ההנחה שלה גדולה יותר. אם היינו בודקים קודם את הסטודנט, סטודנט בשעה 17:00 היה מקבל רק 10%. נסו להחליף את הסדר ולראות מה משתנה בפלט.
  • return מוקדם: ברגע שמצאנו תשובה יוצאים מהפונקציה. לכן אין צורך ב-else.
  • ‏>= ו-<: השעה 16 בפנים, והשעה 18 בחוץ. כשכותבים טווח, תמיד כדאי לבדוק את הקצוות.

איך הייתי חושב על זה: כשיש כמה חוקים, אני כותב טבלה קטנה של מקרים ומה התשובה הנכונה בכל אחד (בדיוק כמו ההערות ליד ה-console.log למעלה), ורק אז כותב את ה-if-ים. אחרי ההרצה אני משווה את הפלט לטבלה. כל שורה שלא מתאימה מראה לי איפה הבאג.

שלב 5: מע״מ ועיגול כסף

אחרי ההנחה מוסיפים מע״מ של 18%. בדרך נגלה בעיה מפתיעה של מספרים עשרוניים במחשב:

המחשב שומר מספרים עשרוניים בבסיס 2, ולכן חלק מהם, כמו 0.1, נשמרים רק בקירוב. בדרך כלל זה לא מורגש, אבל בכסף רואים את זה מיד: אף אחד לא רוצה לקבל הנחה של ‎₪9.600000000000001. הפתרון: מעגלים לאגורות אחרי כל חישוב.

‏Math.round לעומת toFixed

roundMoney(x)x.toFixed(2)
מה מחזיר?מספר: ‏6.91מחרוזת: ‏'6.91'
אפשר להמשיך לחשב?כןלא כדאי: ‏'6.91' + 1 נותן '6.911'
מתי משתמשים?באמצע החישוביםרק בסוף, כשמציגים למשתמש

לכן ב-formatPrice משתמשים ב-toFixed: היא תמיד מראה שתי ספרות, גם כשהסכום עגול (‎₪42.00 ולא ‎₪42).

בעורך הזה הקוד משלבים קודמים מוצג בקיצור (כולל ternary מקונן), כדי שהשלב יתמקד בעיגול. כדאי לציין בכיתה שזה רק לצורך הקיצור, ושב-ternary מקונן כמו כאן עדיף בקוד אמיתי להשתמש ב-if. בשלב הבא חוזרים לגרסה המלאה.

שלב 6: מדפיסים קבלה ‏printReceipt

יש לנו את כל החלקים. עכשיו פונקציה אחת שמחברת אותם ומדפיסה קבלה. נצטרך גם קו מפריד מ-30 מקפים. במקום להקליד 30 מקפים, נבנה אותו בלולאה.

מה חדש כאן?

  • הלולאה ב-line: מתחילים ממחרוזת ריקה ומוסיפים מקף אחד בכל סיבוב. אחרי 30 סיבובים יש 30 מקפים. זו תבנית שתחזור הרבה: מתחילים מערך ריק ומוסיפים לו בלולאה. בדיוק כך סוכמים מספרים, רק עם 0 במקום ''.
  • if בשורה אחת: ‏if (cakes > 0) console.log(...). כשיש פקודה אחת בלבד אפשר לוותר על הסוגריים המסולסלים. ככה לא מדפיסים "עוגה ×0".
  • template literals עם ${...} בתוך גרשיים הפוכים מרכיבים את כל השורות. אפשר לשים בתוך ה-${} כל ביטוי, גם קריאה לפונקציה.
  • פונקציה שקוראת לפונקציות: ‏printReceipt לא מחשבת כמעט כלום בעצמה. היא "מנהלת" את הפונקציות הקטנות. כך נראה קוד מסודר.

קיצור דרך: ל-JavaScript יש פעולה מוכנה שעושה את מה שעושה line: ‏'-'.repeat(30). כאן כתבנו את הלולאה בעצמנו כדי לתרגל, אבל בקוד אמיתי משתמשים ב-repeat.

נסו בעצמכם: הוסיפו לקבלה שורה שמציגה את השעה, למשל שעה: 17:00. רמז: יש כבר משתנה hour בתוך הפונקציה.

שלב 7: מה אם הקלט לא תקין?

מה יקרה אם מישהו יקרא ל-printReceipt(-1, 2)? או ל-printReceipt(1.5, 0)? או אפילו ל-printReceipt('שתיים', 1)? נסו בעורך של שלב 6. התוכנית תדפיס קבלה עם סכומים מוזרים, או עם NaN. קופה אמיתית צריכה לסרב.

נוסיף פונקציה שבודקת אם כמות תקינה: מספר שלם, 0 או יותר. אם הכמות לא תקינה, calculateTotal תדפיס שגיאה ותחזיר null. ‏printReceipt תבדוק את זה ותצא מיד, בלי להדפיס קבלה.

שלושה רעיונות חשובים

  1. Number.isInteger מחזירה true רק למספר שלם. עבור 1.5, עבור '2' (מחרוזת) ועבור NaN היא מחזירה false. כך בדיקה אחת תופסת שלושה סוגים של קלט שגוי.
  2. console.error מדפיס הודעה באדום. משתמשים בו לשגיאות, כדי שיבלטו בין שאר ההודעות. יש גם console.warn שמדפיס בצהוב, לאזהרות.
  3. יציאה מוקדמת (early return): בודקים את המקרים הבעייתיים בתחילת הפונקציה ויוצאים מיד. ככה שאר הפונקציה יכולה להניח שהכול תקין, ולא צריך לעטוף את כל הקוד ב-if ענק.

למה null ולא 0? הזמנה ריקה (0 קפה, 0 עוגות) היא הזמנה תקינה שעולה 0. אם היינו מחזירים 0 גם על שגיאה, לא היינו יודעים להבדיל בין שני המקרים. ‏null אומר "אין כאן ערך", וזה בדיוק מה שקרה.

נסו בעצמכם: שנו את priceOf (בעורך של שלב 6) כך שעבור מוצר שלא קיים בתפריט היא תדפיס אזהרה עם console.warn, למשל 'אין בתפריט: פיצה', לפני שהיא מחזירה 0.

שלב 8: מעבירים ל-VS Code ול-GitHub

העורך באתר נועד לניסויים. תוכנית אמיתית נמצאת בקבצים במחשב. ‏JavaScript של דף אינטרנט רץ בדפדפן, ולכן צריך דף HTML שיטען את הקוד.

1

יוצרים תיקייה ופותחים אותה ב-VS Code

$ mkdir cafe-cashier
$ cd cafe-cashier
$ code .

אם הפקודה code לא מוכרת, פתחו את VS Code ובחרו בתפריט File ← Open Folder.

2

יוצרים index.html שטוען את הסקריפט

index.html

  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  • src="app.js": הקובץ שבו נמצא הקוד. השם צריך להתאים בדיוק לשם הקובץ.
  • defer: "הורד את הקובץ עכשיו, אבל הרץ אותו רק אחרי שכל ה-HTML נטען". זו הדרך המומלצת לטעון סקריפטים, ובשיעורים הבאים נראה למה זה חשוב.

יוצרים app.js

פותחים בדפדפן ומסתכלים בקונסול

פותחים את index.html עם Live Server (כפתור ימני ← Open with Live Server). בדף עצמו רואים רק כותרת. הקבלות מופיעות בקונסול: לוחצים F12 (ב-Mac: ‏Cmd+Option+J) ועוברים ללשונית Console.

אם הקונסול ריק, כמעט תמיד הבעיה היא אחת משתיים: שם הקובץ ב-src לא תואם, או שיש שגיאה באדום בקונסול. לחיצה על שם הקובץ שליד השגיאה (למשל app.js:12) קופצת לשורה הבעייתית.

אפשר גם לקרוא לפונקציות ישירות מהקונסול! הקלידו שם printReceipt(3, 3, true) ולחצו Enter.

שומרים ב-Git ומעלים ל-GitHub

בדיוק כמו בשיעור 1 (חלק ג׳: Git ו-GitHub). מומלץ commit אחרי כל שלב שעובד:

$ git init
$ git add index.html app.js
$ git commit -m "Add cafe cashier with prices and totals"
# אחרי שמוסיפים הנחות, קבלה ובדיקות קלט:
$ git add .
$ git commit -m "Add discounts, receipt and input validation"
# יוצרים ב-GitHub ריפו ריק בשם cafe-cashier, ואז:
$ git branch -M main
$ git remote add origin https://github.com/USERNAME/cafe-cashier.git
$ git push -u origin main

‏USERNAME מחליפים בשם המשתמש שלכם ב-GitHub. אחרי ה-push, רעננו את דף הריפו ב-GitHub. שני הקבצים אמורים להופיע שם.

זו הפעם הראשונה שהסטודנטים מריצים JavaScript מחוץ לאתר. בעיות נפוצות: קובץ בשם app.js.txt ב-Windows (כשהסיומות מוסתרות), תגית <script> שהודבקה בתוך app.js, ושכחה לשמור את הקובץ (העיגול הלבן בלשונית של VS Code). כדאי להפעיל את File ← Auto Save כבר עכשיו.

אתגרים

ארבעה אתגרים, מהקל לקשה. בכל אתגר כתבו את הקוד, לחצו "▶ הרצה" כדי לראות מה קורה, ואז "✓ בדיקה". הבדיקה קוראת לפונקציה שלכם עם הרבה ערכים שונים, ואומרת לכם מה עוד לא עובד.

לולאה אינסופית? אם כתבתם לולאת while שהתנאי שלה אף פעם לא נהיה false, העמוד ייתקע. זה קורה לכולם 🙂. סגרו את הלשונית או רעננו את העמוד. הקוד שלכם נשמר, והוא לא ירוץ שוב עד שתלחצו "▶ הרצה". לפני שמריצים, בדקו שמשהו בתוך הלולאה משנה את התנאי.

אתגר 1: שנה מעוברת קל

בלוח הגרגוריאני, שנה מעוברת (עם 29 בפברואר) נקבעת כך:

  • שנה שמתחלקת ב-4 היא מעוברת. למשל 2024.
  • חוץ משנה שמתחלקת ב-100, שהיא לא מעוברת. למשל 1900.
  • חוץ משנה שמתחלקת ב-400, שהיא כן מעוברת. למשל 2000.

כתבו פונקציה isLeapYear(year) שמחזירה true או false.

רמז: "מתחלק ב-4" בקוד זה year % 4 === 0. מתחילים מהחוק הכי ספציפי (400), כמו שעשינו בהנחות בשלב 4.

אתגר 2: המחשב מנחש מספר בינוני

המחשב צריך לנחש מספר סודי בין 1 ל-100. אחרי כל ניחוש הוא שומע "גבוה מדי" או "נמוך מדי". השיטה החכמה: תמיד לנחש את האמצע של הטווח שנשאר.

  • מתחילים עם low = 1 ו-high = 100.
  • הניחוש הוא האמצע: Math.floor((low + high) / 2).
  • אם הניחוש גבוה מדי, המספר נמצא מתחת לו: high = guess - 1. אם נמוך מדי: low = guess + 1.
  • ממשיכים בלולאת while עד שהניחוש שווה למספר הסודי.

כתבו פונקציה guessNumber(secret) שמדפיסה כל ניחוש, למשל 50: גבוה מדי, ובסוף 37: מצאתי!. היא צריכה להחזיר את מספר הניסיונות.

למה אף פעם לא צריך יותר מ-7 ניסיונות?

כל ניחוש מוריד בערך חצי מהטווח: 100 ← 50 ← 25 ← 12 ← 6 ← 3 ← 1. אחרי 7 חצאים נשאר מספר אחד. השיטה הזו נקראת חיפוש בינארי, והיא אחת השיטות החשובות במדעי המחשב. עם מיליון מספרים צריך רק 20 ניסיונות.

אתגר 3: מספרים ראשוניים בינוני

מספר ראשוני הוא מספר שלם גדול מ-1, שמתחלק בלי שארית רק ב-1 ובעצמו. למשל 2, ‏3, ‏5, ‏7 ו-11 ראשוניים. ‏9 לא ראשוני, כי הוא מתחלק ב-3.

  1. כתבו פונקציה isPrime(n) שמחזירה true אם n ראשוני, ו-false אחרת. מספרים קטנים מ-2 (כולל 0 ומספרים שליליים) אינם ראשוניים.
  2. כתבו פונקציה printPrimes(limit) שמדפיסה את כל הראשוניים מ-2 ועד limit, כל מספר בשורה נפרדת (console.log אחד לכל מספר). היא צריכה להשתמש ב-isPrime.
  3. קראו ל-printPrimes(50).

רמז ל-isPrime: עוברים בלולאה על כל המספרים מ-2 ועד n - 1. אם n מתחלק באחד מהם (n % i === 0), מחזירים מיד false. אם הלולאה הסתיימה ולא מצאנו מחלק, המספר ראשוני.

שיפור: אפשר לעצור הרבה יותר מוקדם

אם למספר יש מחלק, לפחות אחד מהמחלקים שלו קטן או שווה לשורש שלו. לכן מספיק לבדוק עד Math.sqrt(n): ‏for (let i = 2; i * i <= n; i++). עבור 1,000,003 זה 1,000 בדיקות במקום מיליון.

אתגר 4: מתי הכסף יוכפל? קשה

שמים סכום בבנק עם ריבית שנתית קבועה. בסוף כל שנה הבנק מוסיף את הריבית לסכום, ובשנה הבאה הריבית מחושבת על הסכום החדש (ריבית דריבית). למשל 1,000 ₪ בריבית של 10%: אחרי שנה 1,100 ₪, אחרי שנתיים 1,210 ₪ וכן הלאה.

כתבו פונקציה yearsToDouble(amount, ratePercent) שמחזירה כמה שנים צריך לחכות עד שהסכום יגיע לפחות לכפול מהסכום ההתחלתי. ‏ratePercent הוא אחוז: 10 אומר 10%.

  • בכל שנה, הדפיסו שורה כמו שנה 1: ₪1100.00.
  • אם ratePercent הוא 0 או שלילי, הכסף אף פעם לא יוכפל. במקרה כזה החזירו -1 מיד, לפני הלולאה.

לדוגמה: ‏yearsToDouble(1000, 10) מחזירה 8, ו-yearsToDouble(1000, 7) מחזירה 11.

למה הבדיקה לא בודקת ריבית 0? אם הפונקציה שלכם לא מטפלת בריבית 0, הלולאה לא תיגמר לעולם, והבדיקה עצמה הייתה תוקעת את העמוד. לכן את המקרה הזה בדקו בעצמכם, אבל רק אחרי שהוספתם את ה-if בתחילת הפונקציה: ‏console.log(yearsToDouble(1000, 0)) צריך להדפיס ‎-1. זה בדיוק התפקיד של בדיקת קלט: להגן על הקוד ממקרים שהוא לא בנוי להם.

אתגר 4 הוא הזדמנות טובה לדבר על "כלל ה-72" שבנקאים משתמשים בו: מספר השנים להכפלה הוא בערך 72 חלקי אחוז הריבית (72 / 10 ≈ 7.2, ובפועל 8 שנים שלמות). אפשר לבקש מהסטודנטים להשוות את הנוסחה לתוצאה של הפונקציה עבור כמה ריביות.

משימת הגשה: מחשבון ציונים וקבלה לקורס

מה מגישים

תוכנית שמחשבת את הציון של סטודנט ומחליטה אם הוא התקבל לקורס המשך. התוכנית נמצאת בריפו ב-GitHub בשם grades-calculator, עם index.html ו-app.js, ומדפיסה את התוצאות בקונסול. מגישים קישור לריפו.

החוקים

  • לכל סטודנט יש שלושה ציונים: תרגילים (20%), פרויקט (30%) ומבחן (50%). כל ציון הוא בין 0 ל-100.
  • הציון הסופי הוא הממוצע המשוקלל, מעוגל למספר שלם.
  • אם ציון המבחן נמוך מ-56, הציון הסופי הוא ציון המבחן בלבד ("מבחן עובר" הוא תנאי חובה).
  • דירוג במילים: 90 ומעלה "מצוין", 80–89 "טוב מאוד", 70–79 "טוב", 56–69 "עובר", מתחת ל-56 "נכשל".
  • מתקבלים לקורס ההמשך עם ציון סופי של 80 ומעלה. מי שהגיש את כל התרגילים בזמן מתקבל כבר מ-75.

מחוון מוצע (100 נק׳): נכונות החישובים (ממוצע משוקלל, חוק המבחן, דירוג וקבלה) 35, בדיקת קלט ו-early return ‏15, חלוקה לפונקציות ושימוש ב-return ‏20, קבועים וקוד קריא 15, ‏Git (לפחות 3 commits עם הודעות משמעותיות) 10, הרצה תקינה מתוך index.html ‏5. בונוס: עד 10 נק׳.

בדיקה מהירה: לפתוח את index.html מהריפו, ובקונסול להריץ finalGrade(90, 80, 70) (צריך לצאת 77), ‏finalGrade(100, 100, 50) (צריך לצאת 50), ‏gradeLabel(80) ו-isAccepted(75, true). ארבע הקריאות האלה חושפות את רוב הטעויות הנפוצות: עיגול, החוק של המבחן, טווחים בקצוות וברירת מחדל.

סיכום שיעור 2

  • משתנים: ‏const כברירת מחדל, ו-let רק כשהערך צריך להשתנות. קבועים של הגדרות כותבים באותיות גדולות.
  • טיפוסים: מחרוזות, מספרים, בוליאניים, null ו-undefined. מספרים עשרוניים לא תמיד מדויקים, ולכן מעגלים כסף.
  • תנאים: ‏if, ‏else if, ‏switch ו-ternary. הסדר של התנאים חשוב.
  • לולאות: ‏for כשיודעים כמה פעמים, ו-while כשממשיכים עד שמשהו קורה. תמיד לוודא שהלולאה תיגמר.
  • פונקציות: מפרקים בעיה לפונקציות קטנות עם שמות ברורים. פונקציה מחזירה ערך עם return, ובודקת את הקלט שלה בהתחלה.

בשיעור הבא: מערכים ואובייקטים. הקופה שלנו יודעת רק על קפה ועוגה, כי כל מוצר הוא משתנה נפרד. בשיעור 3 נשמור את כל התפריט ברשימה אחת, נעבור עליה עם map ו-filter, ונטען נתונים אמיתיים מהאינטרנט עם fetch.
