תנאים ולולאות

עד עכשיו הקוד שכתבנו רץ שורה אחרי שורה, מלמעלה למטה, תמיד באותו סדר. זה כמו מתכון שבו אין אף "אם": תמיד מוסיפים סוכר, תמיד אופים 30 דקות. אבל תוכנות אמיתיות צריכות להחליט ("אם המשתמש מחובר, הצג את הפרופיל, אחרת הצג כפתור התחברות") ולחזור על פעולות ("שלח מייל לכל אחד מ-500 הלקוחות"). בחלק הזה נלמד את שני הכלים האלה: תנאים ולולאות. אחרי החלק הזה תוכלו לכתוב תוכניות שבאמת "חושבות".

מטרות החלק

בסוף החלק תדעו:

  • להשוות ערכים עם ===, ‏!==, ‏<, ‏> ולהסביר למה לא משתמשים ב-==
  • לשלב תנאים עם &&, ‏|| ו-!
  • להסביר מה זה truthy ו-falsy, ולמנות את כל הערכים ה-falsy
  • לכתוב if, ‏else if, ‏else, אופרטור טרנרי ו-switch
  • לכתוב לולאות for ו-while, ולעקוב אחריהן שלב אחר שלב בטבלה
  • להשתמש ב-break וב-continue, ולעבור על התווים של מחרוזת
  • לזהות דפוסים נפוצים: סכום, ספירה, מקסימום, בניית מחרוזת וחיפוש
  • להבין מה גורם ללולאה אינסופית ואיך יוצאים ממנה

איך לעבוד עם העמוד: בכל דוגמה יש עורך JavaScript. לוחצים ▶ הרצה (או Ctrl+Enter, ובמק Cmd+Enter), ומה שהקוד מדפיס עם console.log מופיע בחלון הפלט. אם יש שגיאה, תופיע הודעה באדום עם מספר השורה והסבר בעברית. שנו כל דוגמה, הריצו שוב, ונסו "לשבור" אותה. ככה לומדים.

תוכנית ל-40 דקות: השוואות ו-=== (5), ‏&&/|| ו-truthy/falsy (5), ‏if/else if/else עם דוגמת הציונים (8), טרנרי ו-switch בקצרה (3), ‏for עם טבלת מעקב על הלוח (8), ‏while ו-break (4), דפוס הסכום והספירה (5), לולאה אינסופית (2). לולאות מקוננות, ‏do...while והאתגרים נשארים לבית. מומלץ לכתוב את טבלת המעקב של לולאת for על הלוח יחד עם הכיתה, שורה אחר שורה: זה הרגע שבו רוב הסטודנטים "מבינים" לולאות.

ערכים בוליאניים והשוואות 5 דק׳

בחלק א׳ פגשנו את הטיפוס boolean (בוליאני): טיפוס שיש לו רק שני ערכים אפשריים, true (אמת) ו-false (שקר). זה נשמע משעמם, אבל כל החלטה שהמחשב מקבל מתחילה בשאלה שהתשובה עליה היא true או false: "האם המשתמש מעל גיל 18?", "האם הסיסמה נכונה?", "האם העגלה ריקה?".

את השאלות האלה שואלים בעזרת אופרטורי השוואה. אופרטור השוואה לוקח שני ערכים ומחזיר true או false:

אופרטורמשמעותדוגמהתוצאה
===שווה (גם בערך וגם בטיפוס)5 === 5true
!==שונה5 !== 3true
>גדול מ-10 > 7true
<קטן מ-10 < 7false
>=גדול או שווה18 >= 18true
<=קטן או שווה17 <= 16false

זהירות: = זה לא ===. סימן = אחד הוא השמה: "שים את הערך הזה בתוך המשתנה". שלושה סימנים === הם שאלה: "האם שני הערכים שווים?". ‏age = 18 משנה את הגיל ל-18. ‏age === 18 רק בודק אם הגיל הוא 18.

הריצו את הדוגמה. שימו לב שתוצאה של השוואה היא ערך לכל דבר: אפשר להדפיס אותה ואפשר לשמור אותה במשתנה.

נסו לשנות: את age ל-18, ואחר כך ל-15. אילו שורות שינו את התשובה שלהן?

השוואה של מחרוזות

אפשר להשוות גם מחרוזות. ‏=== בודק שהן זהות לגמרי, כולל אותיות גדולות וקטנות ורווחים:

‏=== מול ==: למה תמיד שלושה

ב-JavaScript יש שני אופרטורים של שוויון:

  • === (שוויון קפדני): שווה רק אם גם הערך וגם הטיפוס זהים. ‏5 === '5' הוא false, כי אחד מספר והשני מחרוזת.
  • == (שוויון רופף): לפני ההשוואה, JavaScript מנסה "להמיר" את הערכים לאותו טיפוס. ‏5 == '5' הוא true.

נשמע נוח? הבעיה היא שחוקי ההמרה של == מסובכים ומפתיעים, ויוצרים באגים שקשה מאוד למצוא. הריצו ותראו:

הכלל בקורס הזה (ובכל צוות פיתוח מקצועי): משתמשים תמיד ב-=== וב-!==. אם צריך להשוות מספר למחרוזת, ממירים קודם בעצמכם, למשל Number(input) === 5. כך ברור לכל מי שקורא את הקוד מה קורה.

🤔 בדקו את עצמכם: מה ידפיס console.log(10 === '10')?

  • true, כי שניהם 10
  • false, כי אחד מספר והשני מחרוזת
  • שגיאה, אי אפשר להשוות מספר למחרוזת

נכון! ‏=== בודק גם את הטיפוס. ‏10 הוא number ו-'10' הוא string, ולכן התשובה false. אין שגיאה: מותר להשוות כל שני ערכים.

כדאי להריץ את דוגמת 0 == '' מול הכיתה ולתת לתגובות לעשות את העבודה. אין צורך ללמד את חוקי ההמרה של ==: המסר היחיד הוא "תמיד ===". אם עולה שאלה על null == undefined, אפשר לציין שיש מתכנתים שמשתמשים בזה בכוונה, אבל בקורס לא נצטרך את זה.

אופרטורים לוגיים: &&, ‏||, ‏! 5 דק׳

הרבה פעמים שאלה אחת לא מספיקה. "אפשר להיכנס למסיבה אם גם יש כרטיס וגם הגיל מעל 18". "מקבלים הנחה אם או שאתם סטודנטים או שאתם פנסיונרים". בשביל זה יש שלושה אופרטורים לוגיים:

בדיקת טווח: "בין 1 ל-10"

טעות נפוצה של מתחילים היא לכתוב 1 <= x <= 10 כמו במתמטיקה. ב-JavaScript זה לא עובד (זה תמיד true!). צריך לפרק לשתי שאלות ולחבר עם &&:

למה 1 <= x <= 10 תמיד true?

JavaScript מחשב משמאל לימין. קודם 1 <= 50, שזה true. אחר כך true <= 10. כשמשווים בוליאני למספר, ‏true הופך ל-1, ו-1 <= 10 זה true. מבלבל, נכון? בדיוק בגלל זה כותבים שתי השוואות מפורשות.

🤔 בדקו את עצמכם: const a = 5; מה התוצאה של a > 3 && a < 4?

  • true
  • false

נכון! ‏a > 3 הוא true, אבל a < 4 הוא false. ב-&& מספיק צד אחד שקרי, ולכן הכול false. אם היה כתוב ||, התשובה הייתה true.

‏truthy ו-falsy

עד עכשיו כל תנאי החזיר בדיוק true או false. אבל ב-JavaScript אפשר לשים כל ערך במקום שבו מצפים לתנאי: מספר, מחרוזת, כל דבר. JavaScript פשוט מחליטה אם הערך "נחשב אמת" (truthy) או "נחשב שקר" (falsy).

החדשות הטובות: הרשימה של הערכים ה-falsy קצרה, ואפשר ללמוד אותה בעל פה. כל השאר truthy.

ערך falsyמה זה
falseהשקר עצמו
0 (וגם -0)המספר אפס
''מחרוזת ריקה (בלי אף תו, גם לא רווח)
null"אין ערך", בכוונה
undefined"עוד לא קיבל ערך"
NaN"לא מספר", למשל התוצאה של Number('שלום')

כמה ערכים שנראים "ריקים" אבל הם דווקא truthy: '0' (מחרוזת עם התו אפס), ' ' (מחרוזת עם רווח), ‏'false' (מחרוזת עם המילה false).

כדי לראות אם ערך truthy או falsy, אפשר להמיר אותו לבוליאני עם Boolean(...):

למה זה שימושי? כי אפשר לכתוב תנאים קצרים. למשל "אם המשתמש הקליד שם" אפשר לבדוק פשוט עם if (name): אם השם ריק, הוא falsy. נראה את זה בפעולה מיד, כשנלמד if.

🤔 בדקו את עצמכם: איזה מהערכים הבאים הוא truthy?

  • 0
  • ''
  • '0'
  • null

נכון! ‏'0' היא מחרוזת עם תו אחד, ולכן היא לא ריקה. כל מחרוזת לא ריקה היא truthy. ‏0 המספר, המחרוזת הריקה ו-null נמצאים ברשימת ה-falsy.

מספיק להציג את רשימת ששת הערכים ה-falsy ואת המלכודת של '0'. כדאי לבקש מהכיתה לנחש לפני ההרצה של כל שורה: "truthy או falsy?". זה עובד טוב כמשחק קצר של דקה–שתיים.

‏if: לעשות משהו רק אם 4 דק׳

עכשיו, כשאנחנו יודעים לשאול שאלות, אפשר לתת לקוד להחליט. ‏if (בעברית: "אם") מריץ קטע קוד רק אם התנאי truthy. אם התנאי falsy, הקוד בפנים פשוט מדולג.

if (תנאי) {
  // הקוד כאן רץ רק אם התנאי truthy
}

החלקים:

  • if: מילה שמורה בשפה.
  • ( ): בתוך הסוגריים העגולים כותבים את התנאי. הסוגריים חובה.
  • { }: בתוך הסוגריים המסולסלים כותבים את הקוד שירוץ אם התנאי מתקיים. זה נקרא בלוק. נהוג להזיח (להכניס פנימה ברווחים) את הקוד שבתוך הבלוק, כדי שיהיה ברור מה שייך ל-if.
❓ התנאי←✅ truthyמריצים את הבלוק←⬇️ ממשיכים בקוד
❓ התנאי←❌ falsyמדלגים על הבלוק←⬇️ ממשיכים בקוד

נסו לשנות: את הטמפרטורה ל-20 והריצו. אילו שורות נעלמו? שימו לב שהשורה הראשונה והאחרונה מודפסות בכל מקרה, כי הן מחוץ לבלוק.

‏if עם truthy ו-falsy

‏else: ואם לא?

הרבה פעמים יש שתי אפשרויות: "אם יורד גשם קח מטריה, אחרת קח משקפי שמש". בשביל ה"אחרת" יש את else. הבלוק של else רץ רק אם התנאי של ה-if נכשל. תמיד ירוץ בדיוק אחד מהשניים: או זה, או זה, לעולם לא שניהם ולעולם לא אף אחד.

❓ התנאי←✅ truthyבלוק ה-if /❌ falsyבלוק ה-else

נסו לשנות: את הגיל ל-18 ול-25. ואז ל-17. האם אי פעם מודפסות שתי השורות?

דוגמה פתורה: זוגי או אי-זוגי

האופרטור % (שארית, modulo) מחזיר את השארית של חלוקה. ‏7 % 2 הוא 1 (כי 7 = 2×3 + 1), ו-10 % 2 הוא 0. מספר זוגי הוא מספר שהשארית שלו בחלוקה ב-2 היא 0:

‏else if: יותר משתי אפשרויות 4 דק׳

מה אם יש שלוש אפשרויות או יותר? למשל, ציון במבחן: 90 ומעלה זה "מצוין", 80 ומעלה "טוב מאוד", 60 ומעלה "עובר", ומתחת ל-60 "נכשל". בשביל זה משרשרים else if:

if (תנאי1) {
  // רץ אם תנאי1 מתקיים
} else if (תנאי2) {
  // רץ אם תנאי1 לא מתקיים, אבל תנאי2 כן
} else if (תנאי3) {
  // רץ אם 1 ו-2 לא מתקיימים, אבל 3 כן
} else {
  // רץ אם אף תנאי לא התקיים
}

JavaScript בודקת את התנאים לפי הסדר, מלמעלה למטה. ברגע שתנאי אחד מתקיים, היא מריצה את הבלוק שלו ומדלגת על כל השאר. ה-else בסוף לא חובה: הוא "רשת הביטחון" לכל מה שלא התאים לשום תנאי.

נסו לשנות: את הציון ל-95, ‏80, ‏60, ‏59 ו-0. מה מודפס בכל פעם?

הסדר חשוב!

שימו לב: ל-85 מתאימים גם התנאי score >= 80 וגם score >= 60. הוא מקבל "טוב מאוד" כי התנאי הזה מופיע קודם. מה יקרה אם נהפוך את הסדר?

כלל אצבע: כשבודקים טווחים עם >=, מתחילים מהערך הגבוה ביותר ויורדים. כשבודקים עם <, מתחילים מהנמוך ביותר ועולים.

🤔 בדקו את עצמכם: const x = 7; מה ידפיס הקוד?
if (x > 5) { console.log('A'); } else if (x > 3) { console.log('B'); } else { console.log('C'); }

  • A בלבד
  • A ואחריו B
  • B בלבד
  • A, ‏B ו-C

נכון! ‏7 גדול מ-5, אז התנאי הראשון מתקיים ומודפס A. אחרי שבלוק אחד רץ, כל ה-else if וה-else שאחריו מדולגים, גם אם 7 גדול מ-3.

הדגמת "הסדר ההפוך" חשובה מאוד: זה הבאג הנפוץ ביותר בתרגילי ציונים. כדאי להריץ אותה, לשאול "למה 95 קיבל רק 'עובר'?" ולתת לסטודנטים להסביר. זו גם הזדמנות טובה להראות שכל if רגיל (בלי else) נבדק בנפרד, בניגוד לשרשרת else if.

🎯 אתגר 1: זוגי או אי-זוגי קל

בשורה הראשונה מוגדר המשתנה number. כתבו קוד שמדפיס בדיוק את המילה זוגי אם המספר זוגי, או אי-זוגי אם הוא אי-זוגי (בלי טקסט נוסף באותה שורה).

הבדיקה תריץ את הקוד שלכם גם עם מספרים אחרים, אז אל תכתבו את התשובה "על יבש". את השורה הראשונה אל תשנו, חוץ מהמספר עצמו.

תנאים מקוננים מול &&

אפשר לשים if בתוך if. זה נקרא קינון (nesting). שתי הדוגמאות הבאות עושות בדיוק אותו דבר:

הגרסה עם && קצרה וקלה יותר לקריאה, ולכן עדיפה כשכל מה שרוצים הוא "גם וגם". קינון שימושי כשבכל שלב רוצים לעשות משהו אחר:

טיפ: אם הקוד מתחיל להיראות כמו מדרגות (if בתוך if בתוך if...), זה סימן שכדאי לנסות לשלב תנאים עם && או לפרק לשרשרת else if. קוד שטוח קל יותר לקרוא.

האופרטור הטרנרי: ? :

לפעמים כל מה שרוצים הוא לבחור בין שני ערכים לפי תנאי. במקום if/else ארוך, אפשר לכתוב שורה אחת:

const result = condition ? valueIfTrue : valueIfFalse;

קוראים את זה כך: "התנאי מתקיים? אם כן, הערך הראשון. אם לא, הערך השני."

נסו לשנות: את items ל-3. שימו לב שהמילה משתנה מ"פריט" ל"פריטים".

נשתמש באופרטור הטרנרי המון ב-React, כי שם הרבה פעמים צריך לבחור מה להציג בתוך ביטוי אחד. אבל אל תגזימו: אם יש יותר משתי אפשרויות, ‏if / else if קריא הרבה יותר מטרנרי בתוך טרנרי.

‏switch: בחירה לפי ערך אחד

כשמשווים משתנה אחד להרבה ערכים אפשריים ("אם היום ראשון..., אם שני..., אם שלישי..."), שרשרת else if נהיית ארוכה ומלאה בחזרות. ‏switch הוא דרך מסודרת יותר לכתוב את זה:

איך זה עובד:

  • switch (day): הערך שבודקים.
  • case 'שישי':: "אם הערך שווה (ב-===) ל-'שישי', התחילו לרוץ מכאן".
  • break: "סיימנו, צאו מה-switch". חשוב מאוד, ראו מיד למה.
  • default: רץ אם אף case לא התאים, כמו ה-else בסוף.
  • כמה case ברצף בלי קוד ביניהם (ראשון עד חמישי) חולקים את אותו קוד.

המלכודת: לשכוח break

בלי break, אחרי שנמצא case מתאים, JavaScript ממשיכה לרוץ לתוך ה-case הבא, וגם לזה שאחריו, עד שתגיע ל-break או לסוף. זה נקרא "נפילה" (fall-through):

ערכי ברירת מחדל: || ו-??

טריק שימושי מאוד: || לא תמיד מחזיר true או false. הוא מחזיר את הצד הראשון אם הוא truthy, ואחרת את הצד השני. ככה אפשר לתת ערך ברירת מחדל:

a ?? bרק null או undefinedמספרים והגדרות, כש-0 הוא ערך חוקי

  • 0

נכון! ‏?? מחליף רק null ו-undefined. ‏0 הוא ערך אמיתי מבחינתו, ולכן נשאר. עם || התשובה הייתה 10, כי 0 הוא falsy.

‏switch ו-?? אפשר להציג בקצרה בכיתה (3 דקות סך הכול) ולהפנות לעמוד. ב-React ‏switch פחות נפוץ, אבל || ו-?? לברירות מחדל יופיעו שוב ושוב, וגם && לתצוגה מותנית ({isLoggedIn && <Profile />}). כדאי לציין שזה יחזור.

למה צריך לולאות? 2 דק׳

נניח שרוצים להדפיס את המספרים 1 עד 5. אפשר לכתוב:

עובד. אבל מה אם צריך עד 1,000? או עד מספר שהמשתמש בוחר, ולא יודעים מראש כמה? כאן נכנסות לולאות (loops): קוד שאומר למחשב "חזור על הפעולה הזו שוב ושוב, כל עוד תנאי מסוים מתקיים". מחשבים מצוינים בזה: הם לא מתעייפים ולא מתבלבלים, גם אחרי מיליון חזרות.

כל לולאה בנויה משלושה רכיבים:

  1. נקודת התחלה: למשל "מתחילים לספור מ-1".
  2. תנאי להמשך: למשל "כל עוד לא עברנו את 5". כשהתנאי נכשל, הלולאה נעצרת.
  3. התקדמות: למשל "אחרי כל סיבוב, הוסיפו 1". בלי התקדמות, התנאי לעולם לא ייכשל והלולאה לא תיגמר!

כל סיבוב של לולאה נקרא איטרציה (iteration).

לולאת for 8 דק׳

לולאת for היא הלולאה הנפוצה ביותר. היא מתאימה כשיודעים כמה פעמים רוצים לחזור (5 פעמים, 100 פעמים, כמספר התווים במילה). כל שלושת הרכיבים כתובים בשורה אחת:

‏break ו-continue

שתי מילים ששולטות בלולאה מבפנים:

  • continue: "דלגו לסיבוב הבא". מפסיקים את הסיבוב הנוכחי (מה שאחרי continue לא רץ), וממשיכים לסיבוב הבא.

לולאות אינסופיות 2 דק׳

לולאה אינסופית היא לולאה שהתנאי שלה אף פעם לא נכשל, ולכן היא לא נגמרת. הדפדפן עסוק כל הזמן בהרצת הלולאה, ולא מספיק לעשות שום דבר אחר: הלשונית "קופאת", הכפתורים לא מגיבים, ואחרי כמה שניות הדפדפן מציע לסגור את הדף.

שלוש הסיבות הנפוצות:

1. שכחנו לקדם

while (i <= 5) {
  console.log(i);
  // שכחנו i++
}

i נשאר 1 לנצח.

2. מקדמים בכיוון הלא נכון

for (let i = 10; i > 0; i++) {
  console.log(i);
}

i רק גדל, ותמיד יהיה גדול מ-0. התכוונו ל-i--.

3. תנאי שתמיד מתקיים

let n = 1;
while (n !== 10) {
  n += 2;   // 1, 3, 5, 7, 9, 11...
}

n מדלג מעל 10 ואף פעם לא שווה לו בדיוק. בטוח יותר: n < 10.

ואם זה קרה לכם? לא נורא, זה קורה לכל מתכנת. כך יוצאים מזה:

  1. באתר הזה: רעננו את העמוד (F5, או Cmd+R במק). אם הדף לא מגיב, סגרו את הלשונית ופתחו אותה מחדש. הקוד ששמרתם לא ירוץ לבד אחרי הרענון. בגלל זה העורכים בעמוד מריצים קוד רק כשלוחצים ▶ הרצה, ולא תוך כדי הקלדה: אחרת, באמצע הקלדה של לולאה, הדף היה נתקע.
  2. בדף שלכם ב-VS Code: סגרו את הלשונית, תקנו את הקוד ושמרו, ורק אז פתחו שוב.
  3. לפני שמריצים לולאה, שאלו את עצמכם: "מה משתנה בכל סיבוב, ומתי בדיוק התנאי ייכשל?"

איך מוצאים באג בלולאה

הלולאה רצה אבל התוצאה לא נכונה? הכלי הכי פשוט וחזק הוא להוסיף console.log בתוך הלולאה, ולהדפיס את כל המשתנים החשובים בכל סיבוב. זו בעצם טבלת המעקב שבנינו קודם, רק שהמחשב ממלא אותה בשבילנו.

בקוד הבא יש באג: הוא אמור לחשב את הממוצע של 1 עד 5 (שהוא 3), אבל יוצא משהו אחר. הריצו והסתכלו על הפלט של כל סיבוב. מצאתם?

הפתרון

בפלט רואים ש-i מגיע רק עד 4. התנאי i < 5 עוצר לפני 5. צריך i <= 5. זו טעות כל כך נפוצה שיש לה שם: off-by-one ("טעות של אחד"). אחרי שמתקנים, כדאי למחוק את הדפסות הדיבאג.

טיפ: כשמדפיסים כמה משתנים, תנו לכל אחד שם בהדפסה (i=${i}) ולא רק את הערך. כשיש 20 שורות פלט, קל להתבלבל איזה מספר שייך למה.

🤔 בדקו את עצמכם: איזו מהלולאות הבאות אינסופית?

  • for (let i = 0; i < 10; i++) { }
  • for (let i = 10; i > 0; i--) { }
  • for (let i = 0; i < 10; i--) { }
  • let i = 0; while (i < 10) { i += 3; }

נכון! ב-i-- המונה רק קטן: 0, ‏-1, ‏-2... הוא תמיד יהיה קטן מ-10, ולכן התנאי לא ייכשל אף פעם. באפשרות האחרונה i מגיע ל-0, 3, 6, 9, 12, וב-12 התנאי נכשל, כי בודקים < ולא !==.

סיכום ומקורות

  • כל החלטה מתחילה בשאלה שהתשובה עליה true או false. שואלים עם === ושאר אופרטורי ההשוואה, ומשלבים עם &&, ‏|| ו-!.
  • ‏if / else if / else בוחר בלוק אחד בלבד, לפי הסדר. הסדר של התנאים חשוב.
  • לולאה חוזרת על קוד: for כשיודעים כמה פעמים, ‏while כשיודעים רק מתי לעצור.
  • לכל לולאה יש התחלה, תנאי והתקדמות. בלי התקדמות נכונה, הלולאה אינסופית.
  • חמשת הדפוסים: סכום, ספירה, מקסימום, בניית מחרוזת וחיפוש.
  • כשמשהו לא עובד: console.log בתוך הלולאה, וטבלת מעקב.

בחלק הבא נלמד פונקציות: איך לארוז קוד כמו בדיקת זוגיות או ציון באותיות בתוך "מכונה" עם שם, ולהשתמש בה שוב ושוב עם ערכים שונים.
