מה זה JavaScript? 5 דק׳

עד עכשיו פגשנו שתי שפות. לכל אחת מהן תפקיד אחר, וכדאי לחשוב עליהן כמו על בית:

‏JavaScript (בקיצור JS) היא שפת תכנות. בניגוד ל-HTML ול-CSS, שמתארים איך דף צריך להיראות, ב-JavaScript כותבים הוראות שהמחשב מבצע אחת אחרי השנייה: "תחשב את זה", "אם המשתמש לחץ, תציג הודעה", "תביא נתונים מהשרת".

איפה JavaScript רצה?

  • בדפדפן: לכל דפדפן (Chrome, ‏Firefox, ‏Safari, ‏Edge) יש "מנוע" שמריץ JavaScript. זה המקום הראשון שבו השפה נולדה, ושם נעבוד בשיעורים הקרובים.
  • במחשב או בשרת, בעזרת Node.js: אותה שפה בדיוק, רק מחוץ לדפדפן. נכיר את Node בשיעור 4 (כשנתחיל React) ונשתמש בו לכתיבת שרת בשיעור 9.

כלומר, אם לומדים JavaScript פעם אחת, אפשר לכתוב איתה גם את מה שהמשתמש רואה (Frontend) וגם את השרת (Backend). זו אחת הסיבות שהיא השפה הפופולרית בעולם.

JavaScript ו-Java הן שתי שפות שונות לגמרי, למרות השם הדומה. השם נבחר בשנות ה-90 מסיבות שיווקיות, כי Java הייתה אז מאוד פופולרית. אין ביניהן קשר, כמו שאין קשר בין "מכונית" ל"מכונת כביסה".

שלוש דרכים להריץ JavaScript 5 דק׳

את אותו קוד אפשר להריץ בשלושה מקומות. כל אחד מתאים למצב אחר:

1. הקונסול של הדפדפן: לניסויים מהירים

בכל דפדפן יש כלי מפתחים (DevTools), ובתוכם לשונית Console. זה מקום שבו מקלידים שורת JavaScript, לוחצים Enter, ומקבלים תשובה מיד.

1

פתחו את Chrome בכל דף שהוא (אפילו בדף הזה).

2

פתחו את כלי המפתחים:

  • Windows: ‏F12, או Ctrl+Shift+J (פותח ישר את הקונסול)
  • Mac: ‏⌘+⌥+J (Command+Option+J)
  • או: לחיצה ימנית על הדף ← Inspect (בדיקה) ← לשונית Console
3

הקליקו בשורה הריקה שליד הסימן >, הקלידו 2 + 2 ולחצו Enter. הקונסול יענה 4. נסו גם 'שלום'.length.

אזהרת Chrome: בפעם הראשונה שמדביקים קוד לקונסול, Chrome עשוי לחסום את ההדבקה ולבקש להקליד allow pasting. זו הגנה מפני נוכלים שמבקשים מאנשים להדביק קוד זדוני. מותר להקליד את זה כשמדביקים קוד שאתם כתבתם או מבינים. לעולם אל תדביקו בקונסול קוד שמישהו זר שלח לכם.

הקונסול מצוין לבדוק "מה יוצא אם...", אבל כל מה שמקלידים בו נמחק כשסוגרים את הלשונית. לתוכנית אמיתית צריך קובץ.

2. קובץ JavaScript שמחובר לדף: הדרך האמיתית

כמו שקובץ CSS מחברים לדף עם <link>, קובץ JavaScript מחברים עם התגית <script>. ככה בנויים כל האתרים. צרו ב-VS Code תיקייה חדשה בשם js-basics, ובתוכה שני קבצים:

js-basics/
├── index.html
└── app.js

index.html

<!DOCTYPE html>
<html lang="he" dir="rtl">
<head>
  <meta charset="UTF-8">
  <title>התרגול הראשון ב-JS</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>פתחו את הקונסול כדי לראות את הפלט</h1>
</body>
</html>

app.js

console.log('הקובץ app.js נטען!');
console.log(10 * 3);

פתחו את index.html עם Live Server (כמו בשיעור 1), ופתחו את הקונסול (F12). תראו שם את שתי ההודעות. כל שינוי ב-app.js ושמירה (Ctrl+S) ירעננו את הדף ויריצו את הקוד מחדש.

כמה פרטים חשובים בשורה <script src="app.js" defer></script>:

  • src הוא הנתיב לקובץ, בדיוק כמו href ב-<link>.
  • התגית חייבת להיסגר ב-</script>, גם כשאין בתוכה כלום. ‏<script src="app.js" /> לא עובד.
  • defer אומר לדפדפן: "תוריד את הקובץ, אבל תריץ אותו רק אחרי שכל ה-HTML נקרא". בלי זה, הקוד ירוץ לפני שהדף קיים, ובהמשך, כשנרצה לגעת באלמנטים של הדף, זה יגרום לשגיאות. כלל אצבע: תמיד לשים defer.

אפשר גם לכתוב קוד ישירות בתוך התגית: <script>console.log('היי')</script>. זה בסדר לדוגמה קטנה, אבל כמו עם CSS, קובץ נפרד מסודר יותר ומאפשר להשתמש באותו קוד בכמה דפים.

3. העורך באתר הזה: ללמידה

העורכים בעמוד הזה עושים בדיוק את מה שהקובץ והקונסול עושים יחד: הקוד רץ בדף קטן ונסתר, וכל console.log מופיע בחלון הפלט. זה המקום הנוח ביותר לתרגל, אבל חשוב לדעת גם את שתי הדרכים האחרות, כי בפרויקטים אמיתיים עובדים עם קבצים.

🤔 בדקו את עצמכם: מה הדרך הנכונה לחבר את app.js לדף?

  • <link rel="script" href="app.js">
  • <script src="app.js" />
  • <script src="app.js" defer></script>

נכון! ‏<link> משמש ל-CSS, ותגית script חייבת תגית סוגרת. ‏defer דואג שהקוד ירוץ אחרי שהדף נטען.

‏console.log: לראות מה קורה בתוך הקוד

‏console.log היא הפקודה שתשתמשו בה יותר מכל פקודה אחרת. היא מדפיסה ערך לקונסול. למשתמש באתר היא לא מראה כלום (הוא לא פותח את הקונסול), אבל לכם, המפתחים, היא מאפשרת "להציץ" לתוך התוכנית.

אפשר להדפיס כמה ערכים בפקודה אחת, עם פסיק ביניהם. הם יודפסו באותה שורה, עם רווח:

‏console.warn ו-console.error עובדים כמו console.log, רק בצבע אחר. נשתמש בהם פחות.

למה זה כלי הדיבאג החשוב ביותר? כשקוד לא עושה את מה שציפיתם, הדבר הראשון שעושים הוא להוסיף console.log ולבדוק: האם הקוד בכלל הגיע לשורה הזו? מה הערך של המשתנה ברגע הזה? מתכנתים מנוסים עושים את זה כל יום. אל תנחשו, תדפיסו.

הערות בקוד

הערה (comment) היא טקסט בקוד שהמחשב מתעלם ממנו. היא מיועדת לבני אדם: להסביר למה הקוד עושה משהו, או "לכבות" זמנית שורה בלי למחוק אותה.

✏️ נסו: מחקו את // בתחילת השורה הרביעית והריצו. עכשיו גם היא מודפסת. ב-VS Code הקיצור Ctrl+/ (במק ⌘+/) הופך שורה להערה ובחזרה.

הוראות ונקודה-פסיק

תוכנית היא רשימה של הוראות (statements). בדרך כלל כל הוראה בשורה משלה, ובסופה נקודה-פסיק ;, כמו נקודה בסוף משפט.

  • JavaScript מבצעת את ההוראות לפי הסדר, מלמעלה למטה.
  • הנקודה-פסיק היא ברוב המקרים לא חובה, כי JavaScript "מנחשת" איפה נגמרת הוראה. אבל יש מקרים נדירים שבהם הניחוש שגוי, ולכן בקורס הזה נשים ; בסוף כל הוראה. ‏Prettier ב-VS Code מוסיף אותן אוטומטית.
  • רווחים ושורות ריקות לא משנים כלום למחשב. משתמשים בהם כדי שהקוד יהיה קריא.
  • JavaScript מבחינה בין אותיות גדולות וקטנות: ‏console.log עובד, ‏Console.Log לא.

משתנים: let ו-const 10 דק׳

תוכנית צריכה לזכור דברים: שם המשתמש, כמה מוצרים יש בעגלה, מה הניקוד במשחק. בשביל זה יש משתנים.

אפשר לחשוב על משתנה כמו על קופסה עם מדבקה. על המדבקה כתוב שם (למשל age), ובתוך הקופסה יש ערך (למשל 25). כשרוצים את הערך, קוראים לקופסה בשם שלה.

הגדרת משתנה עם let

בואו נפרק את השורה let age = 25;:

חלקמה הוא אומר
let"אני יוצר משתנה חדש" (מילה שמורה של השפה)
ageהשם של המשתנה. אנחנו בוחרים אותו
=השמה: "שים בקופסה את הערך שמימין". זה לא "שווה" של מתמטיקה!
25הערך שנכנס לקופסה
;סוף ההוראה

הסימן = הוא פקודה, לא שאלה. במתמטיקה age = age + 1 הוא שטות (מספר לא יכול להיות שווה לעצמו ועוד 1). בתכנות זה אומר: "קח את הערך הנוכחי של age, הוסף 1, ושים את התוצאה בחזרה ב-age". קוראים את זה מימין לשמאל: קודם מחשבים את הצד הימני, ואז שמים בצד השמאלי.

הגדרה בלי ערך

אפשר ליצור משתנה ריק, ולתת לו ערך רק אחר כך. עד שנותנים לו ערך, יש בו undefined (מילה שאומרת "עדיין אין כאן ערך"):

const: משתנה שלא משתנה

לפעמים ערך לא אמור להשתנות אף פעם: מספר הימים בשבוע, שם האתר, שיעור המע״מ. בשביל זה יש const (קיצור של constant, קבוע). אחרי שנותנים לו ערך, אי אפשר לשנות אותו. נסו להריץ:

קיבלתם שגיאה באדום: TypeError: Assignment to constant variable, כלומר "ניסיתם לשנות קבוע". שימו לב שהשורה האחרונה לא הודפסה: כששגיאה קורית, התוכנית נעצרת.

עוד הבדל: ‏const חייב לקבל ערך מיד. ‏const x; לבד היא שגיאה.

אז מתי let ומתי const?

הכלל שמתכנתים משתמשים בו: ברירת המחדל היא const. רק אם יודעים שהערך יצטרך להשתנות (מונה, ניקוד, סכום שמצטבר), משתמשים ב-let.

למה? כי כשקוראים קוד ורואים const, יודעים מיד שהערך הזה לא ישתנה בהמשך. זה מקל על ההבנה, ומונע באגים שבהם משנים משהו בטעות.

ומה עם var?

בקוד ישן ובהרבה מדריכים באינטרנט תראו var age = 25;. זו הדרך הישנה להגדיר משתנים, מלפני 2015. יש לה כמה התנהגויות מבלבלות, ולכן היום לא משתמשים בה. אם תראו var במדריך, אפשר בדרך כלל להחליף אותו ב-let.

  • 15

נכון! מתחילים ב-10, אחרי השורה השנייה 15, ואחרי השלישית 15 × 2 = 30. כל השמה מחליפה את הערך הקודם.

איך לתת שמות למשתנים

חוקים (אם לא שומרים עליהם, יש שגיאה)

  • מותר: אותיות באנגלית, ספרות, _ ו-$.
  • אסור להתחיל בספרה: 2name ❌, ‏name2 ✅.
  • אסור רווחים או מקפים: first name ❌, ‏first-name ❌ (המחשב יחשוב שזה "first פחות name").
  • אסור להשתמש במילים שמורות של השפה: let, ‏const, ‏if, ‏for, ‏function, ‏return, ‏class, ‏new ועוד.

מוסכמות (הקוד יעבוד גם בלי, אבל כולם עושים ככה)

  • camelCase: כשהשם מורכב מכמה מילים, המילה הראשונה באות קטנה וכל מילה אחריה מתחילה באות גדולה: firstName, ‏totalPrice, ‏isLoggedIn. קוראים לזה "גמל" בגלל ה"דבשות".
  • שמות שמסבירים את עצמם: ‏price עדיף על p, ו-studentCount עדיף על x. בעוד חודש לא תזכרו מה זה x.
  • שמות באנגלית. טכנית JavaScript מרשה גם אותיות בעברית (let גיל = 5 עובד!), אבל זה מתנגש עם כיוון הכתיבה ב-VS Code, אף ספרייה לא עובדת ככה, ואף צוות פיתוח לא יקבל את זה. טקסט בעברית שמים בתוך מרכאות, לא בשמות של משתנים.

✏️ נסו לשבור: שנו את firstName בשורה 1 ל-first name (עם רווח) והריצו. תקבלו SyntaxError. החזירו בעזרת ↺ איפוס.

טיפוסים: אילו סוגי מידע יש? 10 דק׳

לכל ערך ב-JavaScript יש טיפוס (type): הסוג שלו. הטיפוס קובע מה אפשר לעשות עם הערך. מספרים אפשר לחבר ולהכפיל, מטקסט אפשר לבקש את האורך או להפוך לאותיות גדולות. אלה חמשת הטיפוסים הבסיסיים:

ההבדל בין undefined ל-null עדין: ‏undefined הוא מה ש-JavaScript שמה כשלא נתתם ערך, ו-null הוא ערך שאתם שמים כדי להגיד במפורש "ריק". בפועל, שניהם אומרים "אין כאן כלום".

יש עוד שני טיפוסים חשובים מאוד, מערך (array, רשימה של ערכים) ואובייקט (object, אוסף של ערכים עם שמות). נלמד אותם לעומק בשיעור 3.

typeof: לשאול "מה הטיפוס של זה?"

'42' ו-42 הם לא אותו דבר. הראשון הוא טקסט שבמקרה כתובות בו ספרות, כמו מספר טלפון. השני הוא מספר שאפשר לחשב איתו. זה מקור לאחד הבאגים הנפוצים ביותר, ונחזור אליו בסעיף "המרות".

‏typeof null מחזיר 'object' בגלל טעות מהגרסה הראשונה של השפה ב-1995. אי אפשר לתקן אותה בלי לשבור אתרים ישנים, אז היא נשארה. פשוט זכרו את זה.

האופרטור % (שארית): למה הוא שימושי?

  • המרת זמנים: ‏130 % 60 הוא 10, כלומר 130 דקות הן שעתיים ו10 דקות.
  • הספרה האחרונה: ‏1234 % 10 הוא 4.

שלושת הסוגים שתפגשו הכי הרבה:

SyntaxError: הקוד לא כתוב לפי חוקי השפה

חסר סוגר, חסרה מרכאה, יש פסיק במקום הלא נכון. המחשב לא מצליח אפילו "לקרוא" את הקוד, ולכן אף שורה לא רצה, גם לא השורות התקינות שלפני הטעות. הריצו:

‏Invalid or unexpected token פירושו "מצאתי משהו שלא ציפיתי לו". לפעמים מספר השורה מצביע על השורה שאחרי הטעות, כי רק שם המחשב הבין שמשהו לא בסדר. ✏️ תקנו את השגיאה והריצו שוב.

ReferenceError: שם שלא קיים

משתמשים במשתנה (או פונקציה) שלא הוגדר. כמעט תמיד זו שגיאת כתיב, או אותיות גדולות/קטנות לא נכונות. כאן הקוד כן מתחיל לרוץ, ונעצר בשורה הבעייתית:

הערך קיים, אבל אי אפשר לעשות איתו את מה שביקשתם: לשנות const, לקרוא למתודה שלא קיימת, או לקרוא מאפיין של undefined:

‏city.toUppercase is not a function: אין מתודה כזו, כי השם הנכון הוא toUpperCase עם C גדולה.

מה עושים כשיש שגיאה, לפי הסדר:

  1. קוראים את ההודעה עד הסוף, לאט.
  2. הולכים לשורה שהיא מציינת (וגם לשורה שלפניה).
  3. בודקים כתיב, אותיות גדולות/קטנות, סוגריים ומרכאות.
  4. לא מבינים? מעתיקים את ההודעה (בלי שמות המשתנים שלכם) לגוגל. כמעט תמיד מישהו כבר שאל על זה ב-Stack Overflow.

🎯 אתגר 6: תקנו את הבאגים בינוני

בקוד הזה יש שלוש שגיאות. הריצו, קראו את ההודעה, תקנו, והריצו שוב, עד שהקוד מדפיס שתי שורות:

מחברת: 48 ש״ח
קניתם עוד אחת. עכשיו יש 5
רמזים (נסו קודם לבד)
  1. ‏SyntaxError בשורה 1: לאיזו מחרוזת חסרה מרכאה סוגרת?
  2. ‏ReferenceError: באיזה שם הוגדר הסכום, ובאיזה שם השתמשו בו?
  3. ‏TypeError: אם quantity צריך להשתנות, איך היה צריך להגדיר אותו?

מומלץ לעשות את אתגר 6 יחד, על המקרן: להריץ, לקרוא את ההודעה בקול, לתקן ולהריץ שוב. המטרה היא לנרמל שגיאות ולהראות תהליך, לא רק את הפתרון. כדאי להראות גם את אותה שגיאה בקונסול של Chrome, כדי שהסטודנטים יכירו את הפורמט מחוץ לאתר.

סיכום ומקורות

  • ‏JavaScript היא שפת התכנות של הדפדפן (ועם Node, גם של השרת). היא מבצעת הוראות לפי הסדר.
  • מריצים אותה בקונסול (ניסויים), בקובץ עם <script src="..." defer> (פרויקטים), או בעורך באתר (תרגול).
  • משתנים שומרים ערכים. ‏const כברירת מחדל, ‏let כשהערך משתנה, ו-var לא.
  • הטיפוסים הבסיסיים: מחרוזת, מספר, בוליאני, ‏undefined ו-null. ‏'42' הוא לא 42.
  • ‏Template literals (`...${x}...`) הם הדרך לשלב משתנים בטקסט.
  • שגיאה היא הודעה עם סוג, תיאור ושורה. קוראים אותה, לא מפחדים ממנה.

בחלק הבא נלמד לקבל החלטות בקוד (if) ולחזור על פעולות (לולאות), וכך התוכניות שלנו יתחילו "לחשוב".
