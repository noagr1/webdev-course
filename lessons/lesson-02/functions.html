פונקציות

⏱️ 40 דק׳ בכיתה 📚 3–4 שעות לימוד עצמי 🧩 דרישת קדם: חלקים א׳ ו-ב׳ (משתנים, תנאים ולולאות)

עד עכשיו כתבנו קוד שרץ שורה אחרי שורה, מלמעלה למטה, פעם אחת. אבל בתוכנה אמיתית אותה פעולה צריכה לקרות שוב ושוב: לחשב מחיר עם מע״מ לכל מוצר בחנות, לבדוק אם סיסמה תקינה בכל פעם שמישהו נרשם, להציג ברכה לכל משתמש שנכנס. פונקציה היא הדרך לתת שם לקטע קוד, ולהפעיל אותו מתי שרוצים, כמה פעמים שרוצים, עם נתונים שונים בכל פעם.

פונקציות הן הנושא החשוב ביותר בשיעור הזה, ואולי בכל הקורס: ב-React כל חלק במסך הוא פונקציה. מה שתלמדו כאן ילווה אתכם בכל שיעור מעכשיו.

מטרות החלק

בסוף החלק תדעו:

  • להסביר מה זו פונקציה ולמה משתמשים בה
  • להגדיר פונקציה ולקרוא לה, עם פרמטרים ובלי
  • להבין את ההבדל בין return ל-console.log (הבלבול הנפוץ ביותר אצל מתחילים)
  • להשתמש בערכי ברירת מחדל לפרמטרים
  • להבין מה זה scope: איפה משתנה "חי" ואיפה לא רואים אותו
  • לכתוב arrow functions, הצורה המודרנית שבה נשתמש כל הזמן ב-React
  • להעביר פונקציה לפונקציה אחרת (callback)
  • לתכנן, לכתוב ולבדוק פונקציה בעצמכם, צעד אחר צעד

איך לעבוד עם העמוד: בכל דוגמה יש עורך JavaScript חי. הקוד מימין, והפלט (מה ש-console.log מדפיס) משמאל. לוחצים ▶ הרצה (או Ctrl+Enter) כדי להריץ. אם יש שגיאה, תופיע בפלט הודעה אדומה עם מספר השורה והסבר בעברית.

תוכנית ל-40 דקות: 5 דק׳ למה פונקציות (להראות את הקוד החוזר ואת התיקון), 10 דק׳ הגדרה, קריאה ופרמטרים, 10 דק׳ ‏return מול console.log (לא לדלג!), 10 דק׳ arrow functions, 5 דק׳ אתגר 1 או 2 בכיתה. ‏scope, ‏callbacks וההמשך לבית, או לתחילת שיעור 3 אם נשאר זמן.

פונקציה היא כמו מכונה

הדרך הכי טובה לחשוב על פונקציה: מכונה. מכניסים לה משהו (קלט), היא עושה עבודה, ומוציאה משהו (פלט). מכונת מיץ מקבלת תפוזים ומוציאה מיץ. הפונקציה addVat מקבלת מחיר ומוציאה מחיר כולל מע״מ.

📥 קלט100←⚙️ הפונקציה addVatprice * 1.18←📤 פלט118

אפשר גם לחשוב עליה כמו מתכון: כותבים את המתכון לעוגה פעם אחת במחברת, ומכינים לפיו עוגה כל פעם שרוצים. כתיבת המתכון היא הגדרת הפונקציה, והכנת העוגה היא קריאה לפונקציה. כתיבת מתכון לא מכינה עוגה, וגם הגדרת פונקציה לא מריצה אותה. זה חשוב, ונחזור לזה מיד.

בעצם כבר השתמשתם בפונקציות! console.log(...) היא פונקציה שמישהו אחר כתב. גם Math.round(...), ‏Number(...) ו-'abc'.toUpperCase(). כל פעם שכתבתם שם ואחריו סוגריים, קראתם לפונקציה. עכשיו תלמדו לכתוב פונקציות משלכם.

פרמטרים וארגומנטים

שתי מילים שמבלבלות בהתחלה, אבל ההבדל פשוט:

  • פרמטר הוא השם שכותבים בהגדרה: function addVat(price). זה משתנה ריק שמחכה לערך.
  • ארגומנט הוא הערך האמיתי שמכניסים בקריאה: addVat(100). ברגע הקריאה price מקבל את הערך 100.

אם נחזור למכונת המיץ: הפרמטר הוא הפתח שכתוב עליו "כאן מכניסים פרי", והארגומנט הוא התפוז שהכנסתם הבוקר.

כמה פרמטרים

מפרידים בפסיק. הסדר קובע: הארגומנט הראשון נכנס לפרמטר הראשון, השני לשני, וכן הלאה.

בקריאה האחרונה JavaScript לא "מבין" שהתבלבלנו. היא פשוט שמה את 25 ב-name, כי הוא הראשון. המחשב לא יודע מה התכוונתם, רק מה כתבתם.

מה אם שוכחים ארגומנט?

ב-JavaScript אין שגיאה. הפרמטר שלא קיבל ערך יהיה undefined ("לא מוגדר"). זה מקור נפוץ לבאגים, ולכן חשוב להכיר:

כשרואים undefined בפלט במקום שציפיתם לערך, השאלה הראשונה שכדאי לשאול: "האם העברתי את כל הארגומנטים, ובסדר הנכון?". בהמשך העמוד נלמד ערכי ברירת מחדל, שפותרים את הבעיה הזו.

‏return: הפונקציה מחזירה תשובה 10 דק׳

זה החלק הכי חשוב בעמוד, ולכן נעבור עליו לאט. עד עכשיו הפונקציות שלנו הדפיסו דברים. אבל ברוב המקרים אנחנו לא רוצים שהפונקציה תדפיס, אלא שהיא תחזיר לנו את התוצאה, כדי שנוכל להמשיך לעבוד איתה: לשמור במשתנה, לחבר למספר אחר, להשוות, להציג במסך.

המילה return ("החזר") אומרת: "זו התשובה של הפונקציה". הערך שאחרי return חוזר למקום שבו קראו לפונקציה, ו"מחליף" את הקריאה.

אפשר לחשוב על זה כך: כשהמחשב מגיע ל-addVat(100), הוא מריץ את הפונקציה, מקבל 118, ו"מדביק" את 118 במקום הקריאה. השורה הופכת ל-const total = 118;.

‏return מול console.log: ההבדל הקריטי

הנה שתי פונקציות שנראות כמעט זהות. הראשונה מדפיסה, השנייה מחזירה:

function printDouble(n) {
  console.log(n * 2);   // מדפיס למסך, ולא מחזיר כלום
}

function getDouble(n) {
  return n * 2;         // מחזיר את התשובה, ולא מדפיס כלום
}

כשקוראים להן לבד, נראה שהן עושות אותו דבר. אבל ברגע שמנסים להשתמש בתשובה, ההבדל מתגלה. הריצו ותראו:

אנלוגיה: שולחים חבר לבדוק כמה עולה חלב בסופר. console.log זה החבר שצועק את המחיר בתוך הסופר: הוא "אמר" את התשובה, אבל אתם בבית ולא שמעתם. return זה החבר שחוזר הביתה ואומר לכם את המחיר, ועכשיו אתם יכולים להשתמש בו, למשל לחשב אם יש מספיק כסף.

כלל אצבע: פונקציה שמחשבת משהו צריכה return. את ה-console.log כותבים מחוץ לפונקציה, ברגע שרוצים לראות את התשובה: console.log(getDouble(5)). כך הפונקציה שימושית בכל מקום: גם להדפסה, גם לחישובים, וגם (בהמשך הקורס) להצגה במסך ב-React.

‏return עוצר את הפונקציה

ברגע ש-JavaScript מגיעה ל-return, הפונקציה נגמרת מיד. כל מה שכתוב אחריו בגוף הפונקציה לא ירוץ:

‏return מוקדם (early return)

התכונה הזו שימושית מאוד יחד עם if: בודקים מקרה מיוחד בתחילת הפונקציה, ואם הוא קורה, מחזירים תשובה ויוצאים. כך אין צורך ב-else מקונן:

נסו להוסיף מקרה: חיילים (נניח גיל 18–21) משלמים 15. איפה צריך להוסיף את ה-if כדי שזה יעבוד? (רמז: הסדר חשוב.)

פונקציה שמחזירה true או false

פונקציה יכולה להחזיר כל סוג של ערך: מספר, מחרוזת, או בוליאני. פונקציות שמחזירות true/false נקראות בדרך כלל בשם שמתחיל ב-is ("האם"), והן שימושיות מאוד בתוך if:

שימו לב: לא צריך לכתוב if (age >= 18) { return true; } else { return false; }. הביטוי age >= 18 הוא כבר true או false, אז פשוט מחזירים אותו.

ערכי ברירת מחדל לפרמטרים

ראינו שפרמטר שלא קיבל ערך הופך ל-undefined. אפשר לתת לו ערך ברירת מחדל: ערך שישמש אם לא העבירו ארגומנט. כותבים = והערך, ישר בהגדרה:

טיפ: שימו את הפרמטרים עם ברירת מחדל בסוף הרשימה. כך אפשר פשוט לא לכתוב אותם בקריאה. אם vat היה ראשון, לא הייתה דרך נוחה "לדלג" עליו.

🎯 אתגר 1: ברכה קל

כתבו פונקציה בשם greet שמקבלת שם ומחזירה (לא מדפיסה!) את המחרוזת 'שלום NAME!'. למשל greet('דנה') מחזירה 'שלום דנה!'. אם לא מעבירים שם, היא מחזירה 'שלום אורח!'.

כתבו את הפונקציה, הריצו כדי לראות את התוצאה, ואז לחצו "✓ בדיקה".

‏Scope: איפה משתנה "חי"?

Scope (בעברית: "טווח הכרה") הוא האזור בקוד שבו משתנה קיים ואפשר להשתמש בו. הכלל הבסיסי: משתנה שהוגדר בתוך פונקציה קיים רק בתוך הפונקציה.

משתנה מקומי (local)

הריצו וקראו את השגיאה: secret is not defined. מבחוץ פשוט אין משתנה כזה. גם הפרמטרים של פונקציה הם משתנים מקומיים: price של addVat קיים רק בזמן שהיא רצה.

אנלוגיה: פונקציה היא כמו חדר עם דלת סגורה. מה שמניחים על השולחן בחדר נשאר בחדר. מי שעומד במסדרון לא רואה אותו.

משתנה גלובלי (global)

משתנה שהוגדר מחוץ לכל פונקציה נקרא גלובלי, ואפשר לראות אותו מכל מקום, גם מתוך פונקציות. מהחדר אפשר לראות את מה שנמצא במסדרון:

גם בלוקים של if ו-for הם "חדרים"

משתנים שהוגדרו עם let או const בתוך סוגריים מסולסלים { } של if או של לולאה קיימים רק שם. זה נקרא block scope:

אם צריך את הערך גם אחרי הבלוק, מגדירים את המשתנה לפני הבלוק, ומשנים אותו בפנים:

למה לא לשים הכול בגלובלי?

זה מפתה: אם כל המשתנים גלובליים, רואים אותם מכל מקום ואין שגיאות "not defined". אבל בתוכנה גדולה זה מתכון לבלגן:

  • כל פונקציה יכולה לשנות את המשתנה, וקשה לדעת מי שינה אותו כשמשהו נשבר.
  • שתי פונקציות שבמקרה משתמשות באותו שם (למשל total) ידרסו אחת את השנייה.
  • פונקציה שתלויה במשתנה גלובלי קשה להעתיק לפרויקט אחר ולבדוק לבד.

ראו בדוגמה הזו איך פונקציה אחת "מקלקלת" לשנייה בלי שהתכוונו:

הכלל: משתנה צריך לחיות ב-scope הקטן ביותר שאפשר. פונקציה טובה מקבלת את מה שהיא צריכה דרך פרמטרים, ומוסרת את התוצאה דרך return, בלי לגעת במשתנים מבחוץ.

  • יודפס undefined

נכון! ‏x הוגדר בתוך f, ולכן הוא מקומי. מחוץ לפונקציה הוא לא קיים בכלל, ולכן מקבלים שגיאה (ולא undefined).

‏scope אפשר להציג ב-5 דקות עם האנלוגיה של החדר והמסדרון, ולהשאיר את הדוגמה של total לבית. מה שחשוב שיישאר: "משתנה שהוגדר בפנים לא קיים בחוץ". הנושא יחזור בשיעור 5 עם state ב-React.

פונקציה בתוך משתנה (function expression)

ב-JavaScript פונקציה היא ערך, בדיוק כמו מספר או מחרוזת. לכן אפשר לשמור אותה במשתנה. זו דרך שנייה לכתוב את אותה פונקציה:

// דרך 1: הצהרה (function declaration), מה שראינו עד עכשיו
function addVat(price) {
  return price * 1.18;
}

// דרך 2: ביטוי (function expression): פונקציה בלי שם, שנשמרת במשתנה
const addVat2 = function (price) {
  return price * 1.18;
};

קוראים לשתיהן בדיוק באותה צורה: addVat(100) או addVat2(100). שימו לב לנקודה-פסיק בסוף דרך 2: זו השמה למשתנה, כמו const x = 5;.

שימו לב להבדל בין addVat ל-addVat(100). בלי סוגריים זו הפונקציה עצמה (המכונה). עם סוגריים זו קריאה לפונקציה, והתוצאה היא מה שהיא מחזירה (המיץ). ההבחנה הזו תהיה חשובה מאוד בהמשך העמוד, וב-React.

‏Arrow functions: הצורה המודרנית 10 דק׳

ב-2015 נוספה ל-JavaScript צורה קצרה יותר לכתוב פונקציות, עם חץ =>. קוראים לה arrow function ("פונקציית חץ"). בקוד מודרני, ובמיוחד ב-React, תראו אותה בכל מקום, אז כדאי להתרגל אליה כבר עכשיו.

מהצורה הרגילה לצורת החץ, צעד אחר צעד

1

מתחילים מ-function expression

const addVat = function (price) {
  return price * 1.18;
};
2

מוחקים את המילה function, ומוסיפים חץ אחרי הסוגריים

const addVat = (price) => {
  return price * 1.18;
};

זו כבר arrow function מלאה ותקינה. קוראים את זה: "‏addVat היא פונקציה שמקבלת price, והולכת אל...".

3

אם כל הגוף הוא רק return, אפשר לקצר לשורה אחת

const addVat = (price) => price * 1.18;

מוחקים את { } ואת המילה return. מה שבא אחרי החץ מוחזר אוטומטית. זה נקרא implicit return ("החזרה מרומזת").

4

עם פרמטר אחד בדיוק, אפשר גם בלי הסוגריים העגולים

const addVat = price => price * 1.18;

זה לא חובה. הרבה צוותים (וגם כלי העיצוב Prettier) מעדיפים להשאיר את הסוגריים תמיד, כי זה אחיד יותר. בקורס נשאיר אותם.

כל ארבע הגרסאות עושות בדיוק אותו דבר. נסו:

מלכודת: סוגריים מסולסלים בלי return

זו הטעות הכי נפוצה עם arrow functions. ברגע שכותבים { } אחרי החץ, ההחזרה האוטומטית נעלמת, וצריך לכתוב return בעצמכם:

כשהגוף ארוך יותר משורה אחת (יש בו if, משתנים, כמה צעדים), חייבים { }, ולכן גם return:

אז באיזו צורה להשתמש?

צורהמתי מתאים
function name() {}פונקציות "ראשיות" בקובץ, עם שם ברור. קל לקרוא, ואפשר לקרוא לה גם לפני השורה שבה היא מוגדרת (ראו מיד).
const name = () => ...פונקציות קצרות, ובמיוחד פונקציות שמעבירים לפונקציה אחרת (callbacks, בהמשך העמוד). זה הסגנון הנפוץ ב-React.

שתיהן נכונות. מה שחשוב הוא לקרוא את שתיהן בלי להתבלבל, כי בקוד אמיתי תפגשו את שתיהן.

הבדל קטן: מתי אפשר לקרוא לפונקציה (hoisting)

פונקציה שהוגדרה עם function name() "מורמת" (hoisted) לראש הקובץ, ולכן אפשר לקרוא לה לפני השורה שבה היא כתובה. פונקציה שנשמרה ב-const קיימת רק מהשורה שבה הוגדרה ואילך, כמו כל משתנה:

הפתרון פשוט: מגדירים פונקציות לפני שמשתמשים בהן. ככה הקוד גם קריא יותר.

🤔 מה תחזיר f(3) אם const f = (x) => { x + 10; };?

  • 13
  • undefined
  • שגיאה
  • x + 10

נכון! ברגע שיש { } אחרי החץ, אין החזרה אוטומטית. החישוב x + 10 קורה, אבל בלי return הפונקציה מחזירה undefined. התיקון: (x) => x + 10 או (x) => { return x + 10; }.

🎯 אתגר 2: המרה לפונקציות חץ קל

שלוש הפונקציות למטה כתובות בצורה הישנה. המירו כל אחת ל-arrow function שנשמרת ב-const, עם אותו שם. נסו לכתוב את square ו-isPositive בשורה אחת, עם החזרה מרומזת.

פונקציה כערך: להעביר פונקציה לפונקציה (callback)

ראינו שפונקציה היא ערך שאפשר לשמור במשתנה. אם היא ערך, אפשר גם להעביר אותה כארגומנט לפונקציה אחרת. פונקציה שמעבירים כך נקראת callback ("פונקציה שקוראים לה בחזרה"): אנחנו לא קוראים לה בעצמנו, אלא נותנים אותה למישהו אחר, והוא יקרא לה מתי שצריך.

זה נשמע מופשט, אז נתחיל בדוגמה. הפונקציה repeat מקבלת מספר ופונקציה, וקוראת לפונקציה הזו כמה פעמים:

למה sayHi ולא sayHi()? אנחנו רוצים לתת ל-repeat את הפונקציה עצמה, כדי שהיא תפעיל אותה. אם נכתוב repeat(3, sayHi()), ‏sayHi תרוץ מיד, פעם אחת, ול-repeat יגיע מה שהיא מחזירה, כלומר undefined. נסו ותראו את השגיאה.

callback עם ארגומנט

הפונקציה שמקבלת callback יכולה גם להעביר לו ערכים. כאן repeat מעבירה לכל קריאה את מספר הסיבוב:

הצורה האחרונה, arrow function שנכתבת ישר בתוך הקריאה, היא הנפוצה ביותר. בשיעור 3 תשתמשו בה כל הזמן עם map ו-filter על מערכים, וב-React עם אירועים כמו onClick={() => ...}.

‏setTimeout: callback שרץ אחר כך

הפונקציה המובנית setTimeout מקבלת callback ומספר מילי-שניות (1000 = שנייה אחת), ומריצה את ה-callback אחרי הזמן הזה. בינתיים שאר הקוד ממשיך לרוץ. הריצו ושימו לב לסדר:

‏JavaScript לא "מחכה" לפיצה. היא רושמת את ה-callback בצד, ממשיכה, וחוזרת להריץ אותו כשהזמן עובר. הרעיון הזה (קוד שרץ "אחר כך") יחזור בגדול בשיעור 3, כשנביא נתונים מהאינטרנט עם fetch.

🤔 יש פונקציה function beep() { console.log('ביפ'); }. איזו קריאה תדפיס "ביפ" חמש פעמים?

נכון! מעבירים את הפונקציה עצמה, בלי סוגריים, ובסדר הפרמטרים של repeat: קודם מספר הפעמים, ואחר כך הפעולה.

פונקציות שקוראות לפונקציות

הכוח האמיתי של פונקציות: בונים פונקציות קטנות ופשוטות, ומרכיבים מהן פונקציות גדולות. כמו קוביות לגו. כל פונקציה קטנה קלה להבין ולבדוק, והפונקציה הגדולה נקראת כמעט כמו משפט בעברית:

שימו לב לשורה formatPrice(roundPrice(withVat)): קריאה בתוך קריאה. קוראים אותה מבפנים החוצה: קודם roundPrice(withVat) רצה ומחזירה מספר מעוגל, והמספר הזה נכנס ל-formatPrice. בדיוק כמו בחשבון: קודם מה שבתוך הסוגריים.

איך נראית פונקציה טובה

פונקציה "טהורה" (pure function)

פונקציה טהורה היא פונקציה ש:

  1. התשובה שלה תלויה רק בפרמטרים שלה. אותו קלט נותן תמיד אותו פלט.
  2. היא לא משנה שום דבר מחוץ לה (לא משתנים גלובליים, לא הדפסות).

addVat ו-square הן טהורות. הפונקציה addToCart מהדוגמה של ה-scope, שמשנה את total הגלובלי, לא טהורה. פונקציות טהורות קלות לבדיקה, לא מפתיעות, ואפשר להשתמש בהן בכל מקום. לא כל פונקציה יכולה להיות טהורה (מישהו צריך להדפיס בסוף), אבל כדאי שרוב הפונקציות שמחשבות דברים יהיו כאלה. ב-React זה עיקרון מרכזי.

דוגמה פתורה: כותבים פונקציה מאפס 5 דק׳

איך ניגשים לכתוב פונקציה כשמקבלים משימה? לא מתחילים להקליד מיד. הנה התהליך, על דוגמה אמיתית.

המשימה: חנות אונליין רוצה לחשב דמי משלוח. משלוח רגיל עולה 30 ₪. הזמנה של 200 ₪ ומעלה מקבלת משלוח חינם. משלוח אקספרס עולה 20 ₪ נוספים, תמיד (גם כשהמשלוח הרגיל חינם).

בכל אתגר כתבו את הפונקציה, הריצו כדי לראות מה היא מחזירה, ולחצו "✓ בדיקה". הבדיקה מריצה את הפונקציה שלכם על הרבה קלטים, גם כאלה שלא כתבתם, אז חשבו על מקרי גבול. כדאי לנסות לפחות 10 דקות לבד לפני שפותחים את הפתרון.

🎯 אתגר 3: זוגי או אי-זוגי קל

כתבו פונקציה isEven(n) שמחזירה true אם המספר זוגי, ו-false אם לא. רמז: האופרטור % מחזיר את השארית של חילוק. מספר זוגי מתחלק ב-2 בלי שארית.

🎯 אתגר 4: הגדול מבין שלושה בינוני

כתבו פונקציה maxOfThree(a, b, c) שמחזירה את המספר הגדול ביותר מבין השלושה. בלי Math.max: השתמשו ב-if. חשבו מה קורה כשיש שני מספרים שווים, או כשכולם שליליים.

🎯 אתגר 5: כמה פעמים מופיעה אות? בינוני

כתבו פונקציה countChar(text, char) שמחזירה כמה פעמים התו char מופיע במחרוזת text. למשל countChar('banana', 'a') מחזירה 3. רמז: לולאת for על המחרוזת, ו-text[i] נותן את התו במקום i.

🎯 אתגר 6: פלינדרום מאתגר

פלינדרום הוא מילה שנקראת אותו דבר מההתחלה ומהסוף: 'abba', ‏'racecar', ‏'אבא'. כתבו פונקציה isPalindrome(word) שמחזירה true אם המילה פלינדרום. היא צריכה להתעלם מאותיות גדולות וקטנות: 'Abba' הוא פלינדרום.

רמזים: word.toLowerCase() הופך הכול לאותיות קטנות. אפשר לבנות מחרוזת הפוכה בלולאה שרצה מהסוף להתחלה, או להשוות את התו הראשון לאחרון, השני לאחד-לפני-האחרון, וכן הלאה.

תרגיל בונוס: מחשבון ציונים בינוני

בלי בדיקה אוטומטית. בנו כמה פונקציות קטנות שעובדות יחד:

  1. average(a, b, c) מחזירה את הממוצע של שלושה ציונים.
  2. getLetter(score) מחזירה 'A' ל-90 ומעלה, ‏'B' ל-80–89, ‏'C' ל-70–79, ו-'F' מתחת ל-70.
  3. getReport(name, a, b, c) מחזירה מחרוזת כמו 'דנה: ממוצע 85, ציון B', ומשתמשת בשתי הפונקציות הקודמות.
  4. בדקו עם הפונקציה check מהדוגמה הפתורה, כולל מקרי גבול (ממוצע של בדיוק 90, בדיוק 70).
הצגת הפתרון 
const average = (a, b, c) => (a + b + c) / 3;

function getLetter(score) {
  if (score >= 90) return 'A';
  if (score >= 80) return 'B';
  if (score >= 70) return 'C';
  return 'F';
}

function getReport(name, a, b, c) {
  const avg = Math.round(average(a, b, c));
  return name + ': ממוצע ' + avg + ', ציון ' + getLetter(avg);
}

console.log(getReport('דנה', 80, 90, 85));  // דנה: ממוצע 85, ציון B

שימו לב: כשבגוף ה-if יש שורה אחת, אפשר לכתוב אותה בלי { }. זה מקובל עם return קצר, אבל אם יש ספק, עדיף עם סוגריים.

דף סיכום

// הצהרה: אפשר לקרוא לה גם לפני השורה הזו
function add(a, b) {
  return a + b;
}

// ביטוי: פונקציה במשתנה
const add2 = function (a, b) {
  return a + b;
};

// arrow function עם גוף
const add3 = (a, b) => {
  return a + b;
};

// arrow function קצרה: מחזירה אוטומטית
const add4 = (a, b) => a + b;

// ברירת מחדל
const greet = (name = 'אורח') => 'שלום ' + name;

// callback: מעבירים פונקציה בלי ()
setTimeout(() => console.log('אחרי שנייה'), 1000);

// קריאה ושמירת התשובה
const sum = add(2, 3);   // 5

סיכום

  • פונקציה היא קטע קוד עם שם, שמגדירים פעם אחת וקוראים לו כמה פעמים שרוצים. הגדרה לבד לא מריצה כלום.
  • פרמטרים הם השמות בהגדרה. ארגומנטים הם הערכים בקריאה. פרמטר שלא קיבל ערך הוא undefined, אלא אם נתתם לו ברירת מחדל.
  • return מחזיר את התשובה למי שקרא לפונקציה, ועוצר אותה. ‏console.log רק מציג. פונקציה בלי return מחזירה undefined.
  • Scope: משתנה שהוגדר בתוך פונקציה (או בלוק) קיים רק שם. עדיף לקבל נתונים בפרמטרים ולהחזיר ב-return, ולא לשנות משתנים גלובליים.
  • Arrow functions ((x) => ...) הן הצורה המודרנית. בלי { } הן מחזירות אוטומטית. עם { } צריך return.
  • פונקציה היא ערך: אפשר להעביר אותה לפונקציה אחרת (callback). ‏f היא הפונקציה, ‏f() היא הקריאה.
  • כותבים פונקציה בשלבים: קלט ופלט, שם, דוגמאות עם תשובות צפויות (כולל מקרי גבול), קוד, בדיקה.

מה הלאה?

בשיעור 3 נלמד מערכים ואובייקטים, ונראה את הכוח של callbacks: ‏map, ‏filter ו-reduce הן פונקציות שמקבלות arrow function ומפעילות אותה על כל פריט ברשימה. לפני כן, נסו את הפרויקט המסכם של השיעור.
