עיצוב עם CSS

⏱️ 35 דק׳ בכיתה 📚 2–3 שעות לימוד עצמי 🧩 דרישת קדם: חלק א׳ (HTML)

בחלק הקודם למדנו לכתוב HTML, כלומר להגיד לדפדפן מה יש בדף: כותרת, פסקה, תמונה, רשימה. הדף עבד, אבל נראה כמו מסמך משנות ה-90: טקסט שחור על רקע לבן, הכול צמוד לשמאל או לימין. בחלק הזה נלמד CSS, השפה שקובעת איך הדף נראה: צבעים, גופנים, ריווחים, סידור של אלמנטים זה ליד זה, והתאמה לטלפון.

מטרות החלק

בסוף החלק תדעו:

  • לחבר קובץ CSS לדף HTML, ולהסביר למה עדיף קובץ נפרד
  • לקרוא ולכתוב חוק CSS: בורר, מאפיין וערך
  • לבחור אלמנטים לפי תגית, ‏class, ‏id ומיקום, ולהבין מי "מנצח" כשיש סתירה
  • להשתמש בצבעים, ביחידות מידה ובגופנים
  • להסביר את מודל הקופסה: ‏content, ‏padding, ‏border ו-margin
  • לסדר אלמנטים בשורה או בעמודה עם Flexbox, ולמרכז כל דבר
  • לגרום לדף להיראות טוב גם בטלפון, בעזרת media queries
  • להשתמש בכלי המפתחים של הדפדפן כדי לבדוק ולתקן עיצוב

איך ללמוד מהעמוד הזה: כמעט בכל נושא יש עורך חי עם שתי לשוניות, HTML ו-CSS. ה-HTML כבר כתוב בשבילכם. עברו ללשונית CSS, שנו ערכים וראו מה קורה בתוצאה. אם משהו נשבר, הכפתור "↺ איפוס" מחזיר את הקוד המקורי.

בכיתה (35 דק׳): אנטומיה של חוק ובוררים (8), צבעים ויחידות בקצרה (4), מודל הקופסה עם DevTools (8), ‏Flexbox עם החוקר האינטראקטיבי (10), ‏media query אחד (5). ‏Grid, משתנים וטבלת המאפיינים נשארים ללימוד עצמי.

כדאי לפתוח בהדגמה מרשימה: לפתוח אתר מוכר (למשל ynet), ובכלי המפתחים לכבות את כל ה-CSS (בלשונית Sources או עם תוסף), או פשוט לשנות צבע רקע בזמן אמת. הסטודנטים מבינים מיד מה התפקיד של CSS.

מה זה CSS ואיך מחברים אותו 5 דק׳

‏CSS הם ראשי תיבות של Cascading Style Sheets, "גיליונות עיצוב מדורגים". זו שפה נפרדת מ-HTML, עם תפקיד אחר:

שפהתפקידדימוי
HTMLהתוכן והמבנה: מה יש בדףהשלד והקירות של הבית
CSSהעיצוב: איך זה נראההצבע על הקירות, הרהיטים, התאורה
JavaScriptההתנהגות: מה קורה כשלוחציםהחשמל והאינסטלציה (נלמד בשיעור 2)

יש שלוש דרכים להוסיף CSS לדף. כדאי להכיר את שלושתן, אבל בפועל משתמשים כמעט תמיד בשלישית.

דרך 1: מאפיין style על התגית (inline)

כותבים את העיצוב ישירות על האלמנט. זה עובד, אבל רק על האלמנט הזה. אם יש 20 כותרות, צריך לכתוב את אותו הדבר 20 פעמים.

דרך 2: תגית <style> בתוך ה-head

כותבים את כל העיצוב במקום אחד בראש הדף. עכשיו חוק אחד משפיע על כל הפסקאות בדף. החיסרון: אם יש לאתר חמישה דפים, צריך להעתיק את ה-CSS לכל אחד מהם.

<head>
  <style>
    p { color: gray; }
  </style>
</head>

דרך 3 (המומלצת): קובץ CSS נפרד עם <link>

יוצרים קובץ בשם style.css לצד index.html, ומחברים אותו בתוך ה-head:

<head>
  <meta charset="UTF-8">
  <title>האתר שלי</title>
  <link rel="stylesheet" href="style.css">
</head>
/* style.css — קובץ שמכיל רק CSS, בלי תגיות HTML */
p {
  color: gray;
}
  • rel="stylesheet" אומר לדפדפן "הקובץ הזה הוא גיליון עיצוב".
  • href="style.css" הוא הנתיב לקובץ, בדיוק כמו בקישורים. אם הקובץ בתיקייה css, כותבים href="css/style.css".
  • קובץ אחד יכול לעצב את כל דפי האתר. משנים צבע במקום אחד, והוא משתנה בכל הדפים.

בעורכים החיים בעמוד הזה, הלשונית CSS מתנהגת כמו קובץ style.css שכבר מחובר לדף. לא צריך לכתוב <link> או <style>.

הדף לא מתעצב? זו התקלה הנפוצה ביותר בהתחלה. בדקו: (1) שם הקובץ זהה בדיוק, כולל אותיות גדולות וקטנות; (2) הקבצים באותה תיקייה; (3) שמרתם את קובץ ה-CSS (נקודה לבנה בלשונית ב-VS Code = לא נשמר); (4) ה-<link> נמצא בתוך <head>.

🤔 בדקו את עצמכם: לאתר יש 10 דפים, ורוצים שכל הכותרות בכולם יהיו כחולות. מה הדרך הנכונה?

  • להוסיף style="color: blue" לכל כותרת
  • להוסיף תגית <style> לכל אחד מעשרת הדפים
  • קובץ style.css אחד עם חוק לכותרות, ו-<link> אליו מכל דף

נכון! קובץ חיצוני אחד = מקום אחד לשנות. מחר רוצים ירוק? משנים שורה אחת.

אנטומיה של חוק CSS 3 דק׳

קובץ CSS הוא רשימה של חוקים (rules). כל חוק אומר: "את האלמנטים האלה, תעצב ככה". הנה חוק אחד, מפורק לחלקים:

h1 {
  color: navy;
  font-size: 32px;
}
חלקבדוגמהמה הוא אומר
בורר (selector)h1על מי החוק חל: כל תגיות ה-h1 בדף
סוגריים מסולסלים{ }בתוכם כל ההגדרות של החוק
מאפיין (property)colorמה משנים: צבע טקסט
ערך (value)navyלמה משנים: כחול כהה
נקודתיים ונקודה-פסיק:   ;נקודתיים בין מאפיין לערך, נקודה-פסיק בסוף כל הגדרה

צמד של מאפיין וערך (color: navy;) נקרא הצהרה (declaration). בחוק אחד אפשר לשים כמה הצהרות שרוצים.

טעויות תחביר נפוצות: שכחתם ; בסוף שורה (ההצהרה הבאה תיכשל), שכחתם לסגור } (כל החוקים שאחריו יישברו), או כתבתם color = red במקום color: red. ב-CSS אין הודעת שגיאה. הדפדפן פשוט מתעלם מהשורה השגויה. נסו בעורך שלמעלה למחוק את הנקודה-פסיק אחרי navy ותראו מה קורה.

בוררים: איך בוחרים מה לעצב 8 דק׳

הבורר הוא החלק הכי חשוב בחוק: הוא קובע על אילו אלמנטים החוק חל. אלה הבוררים שתשתמשו בהם 95% מהזמן.

1. בורר תגית

כותבים את שם התגית בלי הסוגריים המשולשים. החוק חל על כל התגיות מהסוג הזה בדף.

p { color: gray; }        /* כל הפסקאות */
li { margin-bottom: 8px; } /* כל פריטי הרשימות */

2. בורר class (מחלקה) — עם נקודה

נותנים לאלמנט ב-HTML מאפיין class עם שם שבוחרים, ובCSS כותבים נקודה ואז את השם. כך מעצבים רק אלמנטים מסוימים. זה הבורר הנפוץ ביותר.

  • אותו class יכול להופיע על כמה אלמנטים.
  • לאלמנט אחד יכולים להיות כמה classes, מופרדים ברווח: class="card featured".
  • שמות classes באנגלית, בלי רווחים. נהוג להשתמש במקף: main-title.

3. בורר id — עם סולמית

‏id הוא שם ייחודי: מותר שרק אלמנט אחד בדף יחזיק אותו. ב-CSS כותבים # ואז את השם. בפועל, לעיצוב עדיף להשתמש ב-class. ‏id שומרים לקישורים פנימיים (href="#contact") ול-JavaScript.

4. בורר צאצא — רווח בין שני בוררים

nav a פירושו "כל a שנמצא בתוך nav". קישורים במקום אחר בדף לא יושפעו.

5. קיבוץ — פסיק בין בוררים

h1, h2, h3 פירושו "החוק חל על h1, וגם על h2, וגם על h3". חוסך לכתוב את אותו חוק שלוש פעמים.

6. מצבים (pseudo-classes) — נקודתיים

a:hover חל רק כשהעכבר מעל הקישור. יש עוד: :focus (כשהאלמנט בפוקוס, למשל שדה טופס שלחצו עליו), :first-child (הילד הראשון).

העבירו את העכבר מעל הקישורים ב-nav בתוצאה. שימו לב שהקישור "לחצו כאן" נשאר רגיל, כי הוא לא בתוך nav.

כשיש סתירה: מי מנצח? (Cascade ו-Specificity)

מה קורה אם שני חוקים קובעים צבע שונה לאותו אלמנט? יש שני כללים פשוטים:

  1. ספציפיות (specificity): בורר מדויק יותר מנצח. הסדר מהחלש לחזק: תגית < class < id < style על התגית.
  2. סדר (cascade, "מפל"): אם שני הבוררים חזקים באותה מידה, החוק שכתוב אחרון בקובץ מנצח.

שימו לב: למרות ש-p { color: red; } כתוב אחרון, הוא משפיע רק על הפסקה הראשונה, כי לשתי האחרות יש בורר חזק יותר.

ירושה: חלק מהמאפיינים, בעיקר של טקסט (color, font-family, font-size), עוברים בירושה לאלמנטים שבפנים. לכן נהוג לקבוע את הגופן פעם אחת על body, וכל הדף מקבל אותו. מאפיינים של קופסה (border, padding, background) לא עוברים בירושה.

אין צורך להיכנס לחישוב ספציפיות מספרי (0-1-0 וכו׳). מספיק הכלל "id > class > תגית, ובשוויון האחרון מנצח". כדאי להמליץ לסטודנטים לעצב כמעט רק עם classes. כך הם כמעט לא ייתקלו בבעיות ספציפיות. כדאי גם להזכיר שאת !important לא משתמשים, וזו לרוב סימן לבעיה במבנה.

גופן מ-Google Fonts

הגופנים המותקנים על כל מחשב מוגבלים. ב-Google Fonts יש מאות גופנים חינמיים, וחלקם תומכים בעברית (Heebo, ‏Rubik, ‏Assistant, ‏Frank Ruhl Libre). בוחרים גופן, לוחצים "Get embed code", ומעתיקים את ה-<link> ל-head, לפני ה-link לקובץ ה-CSS שלכם:

<link href="https://fonts.googleapis.com/css2?family=Heebo:wght@400;700&display=swap" rel="stylesheet">
<link rel="stylesheet" href="style.css">
body {
  font-family: 'Heebo', sans-serif;
}

עברית וכיווניות: אם בתגית <html> כתוב dir="rtl", הכול מתחיל מימין אוטומטית. לכן עדיף לכתוב text-align: start במקום right: ‏start פירושו "תחילת השורה", וזה נכון גם בעברית וגם באנגלית. מאותה סיבה יש מאפיינים כמו margin-inline-start, שמתהפכים אוטומטית לפי השפה.

padding: 20px;                 /* כל ארבעת הצדדים */
padding: 10px 20px;            /* למעלה ולמטה 10, לצדדים 20 */
padding: 10px 20px 30px 40px;  /* למעלה, ימין, למטה, שמאל (עם כיוון השעון) */
padding-top: 10px;             /* רק צד אחד: top / right / bottom / left */
margin: 0 auto;                /* למעלה ולמטה 0, לצדדים "אוטומטי" (מרכוז! ראו בהמשך) */

border: שלושה ערכים בשורה אחת

border: 2px solid #334155;     /* עובי, סגנון, צבע */
/* סגנונות: solid (קו), dashed (מקפים), dotted (נקודות), none (בלי) */
border-bottom: 1px solid #ddd; /* רק קו תחתון */
border-radius: 12px;           /* פינות מעוגלות */
border-radius: 50%;            /* על ריבוע: עיגול */

box-sizing: border-box: הגדרה שכדאי לשים בכל פרויקט

כברירת מחדל, width קובע רק את רוחב ה-content. אם כתבתם width: 200px והוספתם padding: 20px ו-border: 5px, הקופסה בפועל תהיה ברוחב 200 + 40 + 10 = 250px. זה מבלבל. עם box-sizing: border-box, ה-width כולל גם את ה-padding וה-border, והקופסה תהיה בדיוק 200px.

לכן בראש כמעט כל קובץ CSS מקצועי תמצאו את החוק הזה. * הוא "בורר כוכבית", שבוחר את כל האלמנטים:

* {
  box-sizing: border-box;
}
body {
  margin: 0;   /* לדפדפן יש margin של 8px על body כברירת מחדל */
}

ראו את הקופסאות בעיניים: בדפדפן, לחצו קליק ימני על אלמנט ← "Inspect" (בדיקה). בתחתית הלשונית Styles (או בלשונית Computed) יש תרשים צבעוני בדיוק כמו זה שלמעלה, עם המספרים האמיתיים. ריחוף מעל אלמנט בקוד צובע את ה-padding בירוק ואת ה-margin בכתום. נרחיב על זה בהמשך.

זה הרגע הכי טוב בחלק הזה לפתוח DevTools ולהראות את תרשים הקופסה על אתר אמיתי. כדאי לשנות בזמן אמת את ה-padding של כפתור ולהראות איך הוא גדל. הרבה סטודנטים מתבלבלים בין padding ל-margin. מבחן פשוט: "אם אשים רקע, האם הרווח יהיה צבוע?" אם כן, זה padding.

🤔 בדקו את עצמכם: לכפתור יש רקע כחול. רוצים שהטקסט לא יהיה צמוד לקצוות הכחולים. מה משנים?

  • margin
  • padding
  • border
  • width

נכון! ‏padding הוא הרווח בין התוכן לגבול, והרקע ממלא אותו. ‏margin היה מרחיק את הכפתור מאלמנטים אחרים, והרווח היה שקוף.

🎯 אתגר 2: כרטיס קל

עצבו את הכרטיס (.card) כך שיהיו לו:

  1. ריווח פנימי (padding) של לפחות 16px מכל הצדדים
  2. גבול (border) מלא (solid) בעובי 1px לפחות
  3. פינות מעוגלות (border-radius) של לפחות 8px
  4. צבע רקע שאינו לבן ואינו שקוף

display: איך קופסה מתנהגת ליד אחרות 3 דק׳

בחלק א׳ ראינו שיש אלמנטים של בלוק (כמו div, ‏p, ‏h1), שתופסים שורה שלמה, ואלמנטים שורתיים (כמו span, ‏a, ‏strong), שזורמים בתוך הטקסט. המאפיין display קובע את ההתנהגות הזו, ואפשר לשנות אותה:

ערךמתנהג כמוwidth ו-height?margin למעלה ולמטה?
blockשורה שלמה משלו. הבא אחריו יורד שורה.✓ עובדים✓ עובד
inlineזורם בתוך הטקסט, רוחבו כרוחב התוכן✗ מתעלם✗ מתעלם
inline-blockזורם בשורה כמו inline, אבל מכבד גדלים כמו block✓ עובדים✓ עובד
noneהאלמנט נעלם לגמרי, כאילו לא קיים——
flexמסדר את הילדים שלו בשורה או בעמודה (הנושא הבא!)✓✓

בשורה הראשונה, שימו לב שה-width: 80px לא משפיע (inline מתעלם ממנו), וה-padding של הקישורים "עולה" על השורה שמעליהם.

רוחב, max-width ומרכוז 2 דק׳

אלמנט בלוק תופס כברירת מחדל את כל הרוחב שיש לו. על מסך רחב, שורות טקסט ארוכות מאוד קשות לקריאה. הפתרון המקובל:

  • max-width: "לכל היותר ברוחב הזה". על מסך צר האלמנט יתכווץ, על מסך רחב הוא ייעצר בגבול. עדיף בדרך כלל על width קבוע, שגורם לגלילה לרוחב בטלפון.
  • margin: 0 auto: ‏auto בצדדים מחלק את המקום הפנוי שווה בשווה בין ימין לשמאל, ולכן הקופסה ממורכזת. עובד רק על אלמנט בלוק שיש לו רוחב.

שני מרכוזים שונים: ‏text-align: center ממרכז את הטקסט בתוך הקופסה. ‏margin: 0 auto ממרכז את הקופסה עצמה בתוך ההורה שלה. למרכוז אנכי (למעלה-למטה) נשתמש ב-Flexbox.

Flexbox: סידור אלמנטים בשורה או בעמודה 10 דק׳

עד עכשיו כל בלוק ירד שורה. אבל באתר אמיתי רוצים תפריט עם קישורים זה ליד זה, שלושה כרטיסים בשורה, לוגו בצד אחד וכפתור בצד השני. בשביל זה יש Flexbox, הכלי המרכזי לפריסה ב-CSS המודרני.

שני תפקידים: מכל ופריטים

‏Flexbox עובד תמיד על זוג: אלמנט הורה, והילדים הישירים שלו.

  • המכל (flex container) הוא ההורה. עליו כותבים display: flex ואת רוב ההגדרות.
  • הפריטים (flex items) הם הילדים הישירים שלו. הם מסתדרים אוטומטית.
<div class="container">   <!-- המכל: display: flex -->
  <div>1</div>            <!-- פריט -->
  <div>2</div>            <!-- פריט -->
  <div>3</div>            <!-- פריט -->
</div>

שורה אחת, display: flex, והילדים עברו לשורה אחת. gap קובע את הרווח ביניהם.

שני צירים

כדי להבין Flexbox צריך להבין שיש שני כיוונים:

  • הציר הראשי (main axis): הכיוון שבו הפריטים מסודרים. ב-row (ברירת המחדל) הוא אופקי, ב-column הוא אנכי.
  • הציר המשני (cross axis): הכיוון הניצב לו.

שני המאפיינים החשובים ביותר מתייחסים לצירים האלה:

מאפייןפועל עלשאלה שהוא עונה עליה
justify-contentהציר הראשיאיך לפזר את הפריטים לאורך השורה?
align-itemsהציר המשניאיך ליישר אותם למעלה-למטה בתוך השורה?

בעברית, הכיוון הפוך: בדף RTL, ‏row מתחיל מימין. לכן flex-start = ימין ו-flex-end = שמאל. זה ההיגיון של "התחלה" ו"סוף" במקום "ימין" ו"שמאל".

חוקר 1: justify-content

לחצו על הערכים ותראו איך הפריטים מתפזרים לאורך הציר הראשי. מתחת לחוקר מופיע ה-CSS שמתאים למה שבחרתם.

ערךמה עושהשימוש נפוץ
flex-startכולם בהתחלה (ברירת מחדל)—
centerכולם באמצעמרכוז
flex-endכולם בסוףכפתורים בתחתית טופס
space-betweenהראשון בהתחלה, האחרון בסוף, השאר מתפזרים ביניהםתפריט עליון: לוגו בצד אחד, קישורים בשני
space-around / space-evenlyרווח שווה סביב כל פריטשורת אייקונים

חוקר 2: align-items

לפריטים בחוקר יש גבהים שונים, כדי שתראו את ההבדל. ‏stretch (ברירת המחדל) מותח את כולם לגובה של הגבוה ביותר.

חוקר 3: flex-direction

‏column הופך את הציר הראשי לאנכי. שימו לב: עכשיו justify-content פועל למעלה-למטה, ו-align-items פועל לרוחב!

חוקר 4: flex-wrap ו-gap

כברירת מחדל, כל הפריטים נדחסים לשורה אחת, גם אם אין להם מקום. ‏flex-wrap: wrap מאפשר להם לרדת לשורה הבאה. הוסיפו פריטים עם "+" ונסו את שני הערכים.

חוקר מלא

כל המאפיינים יחד. נסו לבנות: שלושה פריטים ממורכזים לגמרי; פריטים בעמודה בצד שמאל; שורה עם רווחים שווים.

מומלץ להקרין את החוקר המלא ולתת לסטודנטים לנחש לפני כל לחיצה: "מה יקרה אם נבחר space-between?". את flex-direction: column עם החלפת התפקידים של הצירים כדאי להראות לאט. זו נקודת הבלבול העיקרית. לשיעורי בית מומלץ מאוד Flexbox Froggy (יש גרסה בעברית).

🤔 בדקו את עצמכם: במכל עם display: flex (בכיוון row), איזה מאפיין ממקם את הפריטים באמצע הגובה של המכל?

  • justify-content: center
  • align-items: center
  • text-align: center
  • margin: 0 auto

נכון! ב-row, הגובה הוא הציר המשני, ו-align-items אחראי עליו. ‏justify-content היה ממרכז לרוחב.

הגדרות על הפריטים עצמם: flex

עד עכשיו כתבנו הכול על המכל. יש מאפיין אחד חשוב שכותבים על פריט: flex: 1 אומר "קח את כל המקום הפנוי". אם לכמה פריטים יש flex: 1, הם מתחלקים במקום שווה בשווה. ‏flex: 2 מקבל פי שניים.

דוגמה פתורה 1: מרכוז מושלם

פעם, למרכז משהו גם לרוחב וגם לגובה היה אחת הבעיות המפורסמות ב-CSS. עם Flexbox זה שלוש שורות:

דוגמה פתורה 2: תפריט עליון (navbar)

זה הדפוס הנפוץ ביותר באתרים: לוגו בצד אחד, קישורים בצד השני. שימו לב שיש כאן שני מכלי flex: ה-nav מסדר את הלוגו ואת הרשימה, וה-ul מסדר את הקישורים.

דוגמה פתורה 3: שורת כרטיסים

‏flex-wrap: wrap יחד עם flex: 1 ו-min-width יוצרים כרטיסים שמסתדרים לבד: שלושה בשורה על מסך רחב, ויורדים שורה כשאין מקום. לחצו "⤢ הרחבה" ושנו את רוחב החלון כדי לראות.

🎯 אתגר 3: מרכוז קל

הכפתור צריך להיות בדיוק באמצע האזור הכהה, גם לרוחב וגם לגובה. השתמשו ב-Flexbox על .stage. אל תשנו את הגובה שלו.

🎯 אתגר 4: תפריט עליון בינוני

בנו בעצמכם את התפריט מהדוגמה הפתורה, בלי להציץ:

  1. הלוגו והרשימה באותה שורה, הלוגו בצד אחד והקישורים בצד השני (space-between)
  2. הקישורים עצמם בשורה אחת, זה ליד זה
  3. בלי נקודות של רשימה (list-style: none)
  4. רווח של לפחות 12px בין הקישורים

הצצה ל-Grid לבית

‏Flexbox מצוין לסידור בכיוון אחד: שורה או עמודה. כשרוצים טבלה של שורות ועמודות, כמו גלריית תמונות, יש כלי נוסף: CSS Grid. לא נעמיק בו עכשיו, אבל כדאי להכיר את הדפוס הבסיסי:

‏fr היא יחידה של "חלק מהמקום הפנוי". ‏1fr 1fr 1fr = שלושה חלקים שווים. הכלל המעשי: Flexbox לשורה של דברים, Grid לרשת.

רספונסיביות: אתר שנראה טוב גם בטלפון 5 דק׳

יותר ממחצית הגלישה באינטרנט היא מטלפונים. אתר רספונסיבי (responsive) מתאים את עצמו לגודל המסך: שלוש עמודות במחשב, עמודה אחת בטלפון. לשם כך צריך שני דברים.

1. תגית viewport ב-head

בלי השורה הזו, הטלפון "מעמיד פנים" שהוא מסך ברוחב 980px ומקטין את כל הדף, והטקסט יוצא זעיר. היא כבר מופיעה בשלד שלמדנו בחלק א׳. ודאו שהיא תמיד שם:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

2. Media queries: חוקים שפועלים רק בגודל מסוים

‏@media עוטף חוקי CSS בתנאי. החוקים בפנים פועלים רק כשהתנאי מתקיים:

/* פועל רק כשרוחב החלון 600px ומעלה */
@media (min-width: 600px) {
  .cards {
    flex-direction: row;
  }
}
  • min-width: 600px = "מ-600px ומעלה" (מסכים רחבים).
  • max-width: 600px = "עד 600px" (מסכים צרים).
  • החוקים בתוך ה-@media נוספים לחוקים הרגילים. כותבים בפנים רק את מה שמשתנה.
  • את ה-@media כותבים בסוף הקובץ, כדי שינצח את החוקים הרגילים (זוכרים את ה-cascade?).

גישת Mobile First

הגישה המקובלת היום: כותבים קודם את העיצוב לטלפון (בדרך כלל הכי פשוט: הכול בעמודה אחת), ואז מוסיפים @media (min-width: ...) שמשדרגים את הפריסה למסכים רחבים. כך הטלפון, שהוא בדרך כלל החלש, מקבל את הקוד הפשוט.

כאן התוצאה צרה, ולכן הכרטיסים בעמודה. לחצו "⤢ הרחבה": התוצאה תהיה ברוחב מלא, ותראו את הכרטיסים עוברים לשורה ומשנים צבע.

לבדוק איך האתר נראה בטלפון: בכלי המפתחים (F12) לחצו על אייקון הטלפון והטאבלט (Toggle device toolbar, או Ctrl+Shift+M, ב-Mac Cmd+Shift+M). אפשר לבחור דגם טלפון מהרשימה למעלה, או לגרור את הקצה כדי לשנות רוחב.

🤔 בדקו את עצמכם: מתי יפעלו החוקים שבתוך @media (max-width: 700px) { ... }?

  • כשהחלון רחב מ-700px
  • כשהחלון ברוחב 700px או פחות
  • תמיד, אבל רק על טלפונים

נכון! ‏max-width = "עד". הדפדפן לא יודע אם זה טלפון. הוא רק בודק את רוחב החלון.

🎯 אתגר 5: Mobile First בינוני

הגלריה מסודרת כרגע בשורה תמיד. שנו אותה לגישת mobile first:

  1. בחוק הרגיל של .gallery: ‏flex-direction: column (תמונות אחת מתחת לשנייה, לטלפון)
  2. הוסיפו @media עם min-width (למשל 600px), ובתוכו חוק ל-.gallery עם flex-direction: row

הבדיקה קוראת את ה-CSS שכתבתם, כך שהיא עובדת בכל רוחב של התוצאה. אחרי שעובר, לחצו "⤢ הרחבה" וראו את השינוי.

בכיתה מספיק להראות media query אחד ואת מצב הטלפון ב-DevTools. כדאי להסביר למה הבדיקה של אתגר 5 קוראת את ה-CSS ולא את התוצאה: גודל התוצאה תלוי ברוחב המסך של כל סטודנט. זו גם הזדמנות להזכיר שבדיקה אוטומטית לא מחליפה הסתכלות בעיניים.

כלי המפתחים: לראות ולתקן CSS בזמן אמת 3 דק׳

כלי המפתחים (DevTools) הם החבר הכי טוב של מי שכותב CSS. הם מראים בדיוק אילו חוקים חלים על כל אלמנט, ומאפשרים לשנות אותם ולראות את התוצאה מיד, בלי לגעת בקובץ.

1

פותחים

קליק ימני על אלמנט בדף ← Inspect ("בדיקה"). או F12 (ב-Mac: Cmd+Option+I).

2

בוחרים אלמנט

בלשונית Elements רואים את ה-HTML. לחיצה על שורה בוחרת את האלמנט, והוא מודגש בדף. אפשר גם ללחוץ על אייקון החץ בפינה (Ctrl+Shift+C) ואז על משהו בדף.

3

קוראים את החוקים

בחלונית Styles מופיעים כל החוקים שחלים על האלמנט, מהחזק לחלש, ולצד כל אחד שם הקובץ ומספר השורה. הצהרה עם קו חוצה = חוק אחר ניצח אותה. סימן ⚠️ צהוב = שגיאת כתיב בשם המאפיין או בערך.

4

משנים בזמן אמת

לוחצים על ערך ומשנים אותו (חצים למעלה/למטה מגדילים ומקטינים מספרים). תיבת הסימון ליד כל הצהרה מכבה ומדליקה אותה. שימו לב: השינויים לא נשמרים! כשמצאתם את הערך הנכון, העתיקו אותו לקובץ ה-CSS ב-VS Code.

תרגיל: חקירה באתר אמיתי קל

  1. פתחו אתר שאתם אוהבים, ובדקו (Inspect) את הכותרת הראשית שלו.
  2. מצאו ב-Styles את ה-font-family ואת ה-font-size שלה.
  3. שנו את הצבע שלה לאדום, ואת הטקסט שלה (קליק כפול בלשונית Elements) לשם שלכם.
  4. מצאו בתרשים הקופסה (Computed) כמה padding יש לכפתור כלשהו באתר.
  5. רעננו את הדף. מה קרה לשינויים?
הצגת פתרון

אחרי רענון כל השינויים נעלמים. הם היו רק בעותק של הדף שבדפדפן שלכם, לא בשרת. לכן אי אפשר "לפרוץ" לאתר ככה, ולכן אצלכם צריך להעתיק את השינוי לקובץ.

משתני CSS לבית

באתר אמיתי, אותו צבע מותג מופיע ב-20 מקומות. אם רוצים לשנות אותו, צריך למצוא את כולם. משתני CSS (custom properties) פותרים את זה: מגדירים ערך פעם אחת עם שם שמתחיל ב---, ומשתמשים בו עם var().

:root {                  /* :root = כל הדף. מגדירים כאן משתנים גלובליים */
  --brand: #4f46e5;
  --radius: 12px;
}
.button {
  background: var(--brand);
  border-radius: var(--radius);
}
h1 {
  color: var(--brand);   /* משנים את --brand במקום אחד, והכול משתנה */
}

🎯 אתגר 6: צבע מותג במשתנה בינוני

  1. ב-:root, הגדירו משתנה בשם --brand עם צבע לבחירתכם.
  2. השתמשו בו בעזרת var(--brand) גם לצבע הטקסט של h1, וגם לצבע הרקע של .btn.
  3. בונוס: שנו את הערך של --brand ותראו ששני האלמנטים משתנים יחד.

🤔 בדקו את עצמכם: כתבתם .menu li { display: flex; } אבל פריטי התפריט עדיין אחד מתחת לשני. למה?

  • צריך flex-direction: row
  • display: flex צריך להיות על ההורה (.menu), לא על כל li
  • אי אפשר להשתמש ב-flex על רשימות

נכון! ‏Flexbox מסדר את הילדים של המכל. כאן כל li הפך למכל של התוכן שלו, אבל ה-li-ים עצמם לא בתוך מכל flex.

סיכום

  • ‏CSS קובע איך הדף נראה. כותבים אותו בקובץ style.css נפרד ומחברים עם <link>.
  • חוק = בורר + { מאפיין: ערך; }. הבוררים העיקריים: תגית, ‏.class, ‏#id, צאצא, ‏:hover.
  • בסתירה: בורר ספציפי יותר מנצח, ובשוויון האחרון מנצח.
  • כל אלמנט הוא קופסה: content ← padding ← border ← margin. תמיד box-sizing: border-box.
  • ‏display: flex על ההורה מסדר את הילדים. ‏justify-content לאורך, ‏align-items לרוחב, ‏gap לרווחים.
  • רספונסיביות: viewport ב-head, עיצוב לטלפון קודם, ו-@media (min-width) למסכים רחבים.
  • ‏DevTools מראים אילו חוקים חלים ומאפשרים לנסות שינויים בזמן אמת.
