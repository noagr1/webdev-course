HTML מאפס

⏱️ כ-40 דקות בכיתה 📚 2–3 שעות לימוד עצמי 🧑‍🎓 לא נדרש ידע קודם

‏HTML היא השפה שבה כותבים את התוכן והמבנה של כל דף אינטרנט: כותרות, פסקאות, תמונות, קישורים, טפסים. כל אתר שאתם מכירים, מגוגל ועד אינסטגרם, מגיע לדפדפן בסופו של דבר כ-HTML. בעמוד הזה נלמד אותה מאפס, תגית אחרי תגית, ועם המון דוגמאות שאפשר לשנות ולראות את התוצאה מיד.

מטרות החלק

בסוף העמוד תדעו:

  • להסביר מה קורה כשמקלידים כתובת בדפדפן
  • להתקין VS Code ולעבוד איתו עם Live Server
  • להבין מה זו תגית, מה זה אלמנט ומה זה מאפיין
  • לכתוב שלד של דף HTML ולהסביר כל שורה בו
  • להשתמש בכותרות, פסקאות, קישורים, תמונות, רשימות, טבלאות וטפסים
  • להבין את ההבדל בין div ל-span, ומתי משתמשים בתגיות סמנטיות

איך לעבוד עם העמוד: בכל דוגמה יש עורך חי. הקוד מימין, התוצאה משמאל. שנו משהו בקוד והתוצאה תתעדכן מיד. אם משהו נשבר, הכפתור "↺ איפוס" מחזיר את הקוד המקורי.

איך הווב עובד 10 דק׳

לפני שכותבים שורת קוד, כדאי להבין מה קורה כשאתם מקלידים בדפדפן כתובת כמו https://www.ynet.co.il/news ולוחצים Enter.

שני צדדים: לקוח ושרת

  • הלקוח (Client) הוא הדפדפן שלכם: Chrome, ‏Firefox, ‏Safari. הוא מבקש דפים ומציג אותם.
  • השרת (Server) הוא מחשב שנמצא איפשהו בעולם ומחובר לאינטרנט כל הזמן. הוא שומר את קבצי האתר ושולח אותם למי שמבקש.

שלב אחר שלב

1

פירוק הכתובת (URL)

לכתובת יש חלקים, ולכל חלק תפקיד:

חלקבדוגמהמה זה אומר
פרוטוקולhttps://"השפה" שבה הדפדפן והשרת מדברים. ה-s בסוף אומר שהתקשורת מוצפנת (מאובטחת).
דומייןwww.ynet.co.ilהשם של השרת. קל לזכור שם, קשה לזכור מספר.
נתיב/newsאיזה דף בתוך האתר אנחנו רוצים.
2

‏DNS: ספר הטלפונים של האינטרנט

מחשבים לא מבינים שמות כמו ynet.co.il. הם מדברים במספרים שנקראים כתובות IP, למשל 151.101.1.91. הדפדפן שואל שרת DNS "מה המספר של ynet?" ומקבל תשובה. בדיוק כמו שמחפשים שם באנשי הקשר בטלפון ומקבלים מספר.

3

בקשת HTTP

הדפדפן שולח לשרת הודעה שנקראת בקשה (Request): "תן לי בבקשה את הדף /news". השרת מחזיר תשובה (Response) עם קוד מצב וגם עם תוכן הדף. קודי מצב נפוצים:

  • 200: הכול בסדר, הנה הדף.
  • 404: הדף לא נמצא. בטח נתקלתם בזה.
  • 500: תקלה בשרת.
4

הדפדפן מצייר את הדף

התשובה היא קובץ HTML, טקסט רגיל. הדפדפן קורא אותו, מגלה שצריך עוד קבצים (CSS לעיצוב, תמונות, JavaScript), מבקש גם אותם, ובסוף מציג לכם את הדף המעוצב.

שלוש השפות של הדפדפן

שפהתפקידדימוי של בית
HTMLתוכן ומבנה: מה יש בדףהקירות, החדרים, הדלתות
CSSעיצוב: איך זה נראההצבע על הקירות, הריהוט
JavaScriptהתנהגות: מה קורה כשלוחציםהחשמל: מתג שמדליק אור

בחלק הזה נתמקד ב-HTML. ‏CSS נלמד בחלק ב׳, ו-JavaScript בשיעורים 2 ו-3.

נסו בעצמכם: פתחו אתר כלשהו ב-Chrome, לחצו על F12 (ב-Mac: ‏Cmd+Option+I), עברו ללשונית Network ורעננו את הדף. כל שורה היא בקשה אחת שהדפדפן שלח. לחצו על השורה הראשונה ותראו את ה-HTML שהשרת החזיר. אפשר גם ללחוץ קליק ימני על דף ולבחור "הצגת מקור הדף" (View Page Source).

הדגמה מומלצת (5 דק׳): לפתוח את לשונית Network מול הכיתה, לרענן אתר מוכר ולהראות את הבקשה הראשונה, את קוד 200 ואת ה-HTML בתשובה. אחר כך לגלוש לכתובת שלא קיימת באותו אתר ולהראות 404. זה ממחיש שהדפדפן "רק" מבקש קבצים ומציג אותם.

🤔 מה התפקיד של DNS?

  • לעצב את הדף
  • לתרגם שם של אתר (דומיין) לכתובת IP מספרית
  • להצפין את התקשורת
  • לשמור את קבצי האתר

נכון! ‏DNS הוא כמו ספר טלפונים: מקבל שם (ynet.co.il) ומחזיר מספר (כתובת IP). ההצפנה היא תפקיד של ה-s ב-https.

הכלים: VS Code ו-Live Server

את רוב הדוגמאות בעמוד הזה אפשר לנסות ישר באתר. אבל מפתחים אמיתיים כותבים קוד בעורך קוד על המחשב. נעבוד עם VS Code: חינמי, פופולרי מאוד, ועובד ב-Windows וב-Mac.

1

התקנת VS Code

  1. היכנסו ל-code.visualstudio.com ולחצו על כפתור ההורדה הכחול.
  2. Windows: הריצו את הקובץ שהורד. במסך האפשרויות סמנו את Add "Open with Code" action ואת Add to PATH.
  3. Mac: פתחו את קובץ ה-zip וגררו את Visual Studio Code לתיקיית Applications.
2

התקנת תוספים (Extensions)

בסרגל השמאלי של VS Code יש סמל של ארבעה ריבועים (Extensions). חפשו והתקינו:

  • Live Server (של Ritwick Dey): פותח את הדף בדפדפן ומרענן אותו אוטומטית בכל שמירה.
  • Prettier: מסדר את הקוד (רווחים, הזחות) בלחיצה אחת.
3

הדף הראשון

  1. צרו במחשב תיקייה חדשה, למשל my-first-site.
  2. ב-VS Code: ‏File ← Open Folder ובחרו את התיקייה.
  3. לחצו על סמל "קובץ חדש" ליד שם התיקייה וקראו לקובץ index.html. השם index.html מיוחד: זה הדף שנפתח ראשון באתר.
  4. הקלידו ! ולחצו Tab. ‏VS Code ימלא שלד שלם של דף (נסביר אותו בהמשך).
  5. קליק ימני על הקובץ ← Open with Live Server. הדף ייפתח בדפדפן.

‏Emmet: קיצורי דרך לכתיבת HTML

ה-! שהקלדתם הוא חלק מ-Emmet, כלי שמובנה ב-VS Code. כותבים קיצור, לוחצים Tab, ומקבלים קוד מלא:

מקלידיםמקבלים
p + Tab<p></p>
h1 + Tab<h1></h1>
ul>li*3 + Tabרשימה עם 3 פריטים
div.card + Tab<div class="card"></div>

קיצורי מקלדת שכדאי להכיר: שמירה: Ctrl+S (ב-Mac: Cmd+S). סידור הקוד עם Prettier: Shift+Alt+F (ב-Mac: Shift+Option+F). הפיכת שורה להערה: Ctrl+/.

תקלה נפוצה: "שיניתי את הקוד ושום דבר לא השתנה בדפדפן". ברוב המקרים פשוט לא שמרתם. נקודה לבנה ליד שם הקובץ בלשונית אומרת שיש שינויים שלא נשמרו. כדאי להפעיל שמירה אוטומטית: File ← Auto Save.

בכיתה לא כדאי להשקיע זמן בהתקנות. מומלץ לבקש מראש שיגיעו עם VS Code מותקן, ולהדגים רק את ! + Tab ואת Live Server. מי שנתקע בהתקנה יכול לעבוד בינתיים עם העורכים החיים באתר.

מהי תגית?

‏HTML בנויה מתגיות (tags). תגית היא מילה בתוך סוגריים משולשים, שאומרת לדפדפן "מה זה" הטקסט שבתוכה. רוב התגיות באות בזוג: תגית פתיחה ותגית סגירה. בתגית הסגירה יש לוכסן /.

<p>שלום עולם</p>
חלקשםהסבר
<p>תגית פתיחה"כאן מתחילה פסקה"
שלום עולםתוכןמה שיוצג על המסך
</p>תגית סגירה"כאן הפסקה נגמרת"

הכול ביחד, פתיחה + תוכן + סגירה, נקרא אלמנט (element). כשאומרים "אלמנט p" מתכוונים לכל הפסקה.

נסו: שנו את הטקסט, או החליפו את p ב-h1 (גם בפתיחה וגם בסגירה) ותראו מה קורה.

מאפיינים (attributes)

לתגית אפשר להוסיף מאפיינים: מידע נוסף שכותבים בתוך תגית הפתיחה, בצורה שם="ערך". למשל, לקישור צריך לומר לאן הוא מוביל:

<a href="https://google.com">לגוגל</a>
  • a: שם התגית (קישור).
  • href: שם המאפיין.
  • "https://google.com": הערך, תמיד בתוך מירכאות.

לתגית יכולים להיות כמה מאפיינים, מופרדים ברווח: <img src="cat.jpg" alt="חתול">.

תגיות ריקות (void)

יש תגיות שאין להן תוכן, ולכן גם אין להן תגית סגירה. למשל <br> (ירידת שורה), <hr> (קו מפריד), <img> (תמונה) ו-<input> (שדה בטופס). לפעמים תראו אותן כתובות <br />, עם לוכסן. זה אותו דבר, ושתי הצורות תקינות.

קינון: תגית בתוך תגית

אפשר לשים תגיות בתוך תגיות. זה נקרא קינון (nesting). הכלל החשוב: מה שנפתח אחרון נסגר ראשון, כמו קופסה בתוך קופסה.

האלמנטים יוצרים עץ: לכל אלמנט יש "הורה" (האלמנט שעוטף אותו), ויכולים להיות לו "ילדים". בדוגמה למעלה, p הוא ההורה ו-strong הוא הילד. נשתמש במילים האלה הרבה, גם ב-CSS וגם ב-React.

html
├── head
│   └── title
└── body
    ├── h1
    └── p
        └── strong

הערות

הערה היא טקסט שהדפדפן מתעלם ממנו. היא נועדה לאנשים שקוראים את הקוד. כותבים אותה בין <!-- ל--->. ראיתם הערות בדוגמה הקודמת: הן לא מופיעות בתוצאה.

אותיות קטנות: ‏HTML לא מבחינה בין אותיות גדולות לקטנות (<P> ו-<p> זהות), אבל המוסכמה היא לכתוב תמיד באותיות קטנות.

🤔 בקוד <img src="dog.jpg" alt="כלב">, מה זה alt?

  • שם של תגית
  • מאפיין
  • תגית סגירה
  • הערה

נכון! ‏img היא התגית, ו-src ו-alt הם מאפיינים שלה. לתגית img אין תגית סגירה, כי היא תגית ריקה.

שלד הדף, שורה אחרי שורה

כל דף HTML מתחיל באותו שלד. זה מה ש-VS Code יוצר כשמקלידים ! + Tab (עם שינוי קטן לעברית):

<!DOCTYPE html>
<html lang="he" dir="rtl">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>הדף שלי</title>
  </head>
  <body>
    <h1>שלום!</h1>
  </body>
</html>
שורהמה היא עושה
<!DOCTYPE html>מודיעה לדפדפן "זה HTML מודרני (HTML5)". זו לא באמת תגית, וצריכה להיות תמיד השורה הראשונה.
<html lang="he" dir="rtl">האלמנט שעוטף את כל הדף. ‏lang="he" אומר שהשפה עברית (חשוב לקוראי מסך ולגוגל). ‏dir="rtl" אומר שהכיוון מימין לשמאל. בלי זה, דף בעברית ייראה הפוך.
<head>"הראש": מידע על הדף, שלא מוצג בתוכו.
<meta charset="UTF-8">קידוד התווים. בלי השורה הזו, עברית עלולה להופיע כג׳יבריש (סימני שאלה וריבועים).
<meta name="viewport" ...>אומרת לטלפון להציג את הדף ברוחב המסך האמיתי, בלי להקטין אותו. נצטרך אותה כשנעשה את הדף מתאים לטלפון.
<title>הכותרת שמופיעה בלשונית של הדפדפן ובתוצאות החיפוש בגוגל.
<body>"הגוף": כל מה שרואים על המסך נכתב כאן.

הזחה (indentation): שימו לב שכל אלמנט שנמצא בתוך אלמנט אחר מוזז פנימה בשני רווחים. לדפדפן זה לא משנה, אבל לנו זה מאוד עוזר לראות מה נמצא בתוך מה. Prettier עושה את זה בשבילכם.

הערה על העורכים באתר: בעורכים החיים בעמוד הזה לא צריך לכתוב את השלד. כותבים רק את מה שבתוך <body>, והאתר מוסיף את השאר (כולל עברית ו-RTL). בקובץ אמיתי ב-VS Code, צריך תמיד שלד מלא.

כותרות: h1 עד h6

יש שש רמות של כותרות. h1 היא הכותרת הראשית, ו-h6 הכי קטנה. ‏h הוא קיצור של heading (כותרת).

כללים לכותרות

  • ‏h1 אחד בכל דף. זה הנושא של הדף, כמו שם של ספר.
  • לא מדלגים על רמות. אחרי h2 בא h3, לא h5. הכותרות הן כמו תוכן עניינים: פרק (h2), תת-פרק (h3).
  • לא בוחרים כותרת לפי הגודל. רוצים טקסט גדול? משנים את הגודל ב-CSS. בוחרים את רמת הכותרת לפי החשיבות שלה במבנה.

למה זה חשוב? גוגל משתמש בכותרות כדי להבין על מה הדף. אנשים עיוורים שמשתמשים בקורא מסך (תוכנה שמקריאה את הדף בקול) מדלגים בין כותרות כדי לנווט, כמו שאתם מעיפים מבט על הכותרות.

טקסט: פסקאות, הדגשות ושורות

‏p: פסקה

‏p (paragraph) היא התגית הבסיסית לטקסט. כל פסקה מתחילה בשורה חדשה, ויש רווח בינה לבין הפסקה הבאה.

הדפדפן מכווץ רווחים. כמה רווחים ברצף, או ירידת שורה ב-Enter, נהפכים לרווח אחד. זה מבלבל בהתחלה. כדי לרדת שורה משתמשים ב-<br> או מתחילים פסקה חדשה.

‏br ו-hr

  • <br> (break): ירידת שורה בתוך אותה פסקה. מתאים לשירים או לכתובות.
  • <hr> (horizontal rule): קו אופקי שמפריד בין נושאים.

הדגשות בתוך הטקסט

תגיתמשמעותמראה ברירת מחדל
strongחשוב מאודמודגש
emדגש בהקראה (emphasis)נטוי
markמסומן, כמו מרקררקע צהוב
smallהערת שוליים, אותיות קטנותקטן

יש גם b ו-i, שנראות בדיוק כמו strong ו-em. ההבדל הוא במשמעות: strong אומרת "זה חשוב" (וקורא מסך ידגיש את זה בקול), ו-b רק משנה את המראה. כדאי להעדיף את strong ו-em.

🤔 כתבתם בקוד שתי שורות טקסט, אחת מתחת לשנייה, בתוך אותה <p>. מה יופיע בדפדפן?

  • שתי שורות נפרדות
  • שורה אחת, עם רווח אחד במקום ירידת השורה
  • שגיאה

נכון! הדפדפן מכווץ ירידות שורה ורווחים לרווח אחד. כדי לרדת שורה צריך <br> או פסקה חדשה.

🏆 אתגר 1: כרטיס ביקור בטקסט

קל

כתבו בעורך:

  1. כותרת h1 עם השם שלכם
  2. כותרת h2 עם הכיתוב "קצת עליי"
  3. פסקה אחת לפחות, ובתוכה מילה אחת מודגשת עם strong

לחצו "✓ בדיקה" כשסיימתם.

קישורים: התגית a

קישורים הם מה שהופך את הווב ל"רשת". התגית היא a (anchor, עוגן), והמאפיין href אומר לאן הקישור מוביל. הטקסט בין התגיות הוא מה שלוחצים עליו.

התוצאה בעורך החי רצה בסביבה מוגבלת, ולכן חלק מהקישורים לא ייפתחו בה (למשל לשונית חדשה). אם לחצתם על קישור והתוצאה השתנתה, שנו משהו קטן בקוד והיא תחזור. בקובץ אמיתי הקישורים יעבדו כרגיל.

כתובות יחסיות לעומק

כתובת יחסית מחושבת ביחס לתיקייה של הקובץ הנוכחי. נניח שזה מבנה הקבצים של האתר:

קפיצה בתוך הדף עם id

נותנים לאלמנט מאפיין id, שם ייחודי בדף, ומקשרים אליו עם #. ככה עובד תוכן העניינים בצד העמוד הזה.

<a href="#contact">ליצירת קשר</a>

<h2 id="contact">יצירת קשר</h2>

‏target ו-rel

‏target="_blank" פותח את הקישור בלשונית חדשה. משתמשים בזה בקישורים לאתרים אחרים, כדי שהגולש לא יעזוב את האתר שלכם. כשמשתמשים ב-_blank מוסיפים גם rel="noopener", מטעמי אבטחה: זה מונע מהדף החדש לשלוט בלשונית שלכם.

טקסט טוב לקישור: "לחצו כאן" הוא טקסט גרוע. קורא מסך מקריא רשימה של כל הקישורים בדף, ו"לחצו כאן" חמש פעמים לא אומר כלום. עדיף: "לתקנון הקורס".

תמונות: התגית img

‏img היא תגית ריקה (בלי סגירה) עם שני מאפיינים חובה:

  • src (source): הכתובת של קובץ התמונה, מלאה או יחסית, בדיוק כמו ב-href.
  • alt (alternative): תיאור מילולי של התמונה.

שימו לב לתמונה השנייה: הקובץ לא קיים, ולכן הדפדפן מציג במקומה את טקסט ה-alt.

למה alt כל כך חשוב?

  • נגישות: קורא מסך מקריא את ה-alt לאנשים שלא רואים את התמונה.
  • תמונה שלא נטענה: רשת איטית או כתובת שגויה. ה-alt מופיע במקום.
  • גוגל: ככה מנועי חיפוש מבינים מה בתמונה.
‏alt גרוע‏alt טוב
alt="תמונה"alt="גור כלבים שחור מביט למצלמה"
alt="IMG_2041.jpg"alt="הצוות שלנו בכנס 2026"
בלי alt בכללתמונה קישוטית בלבד (קו, צורה)? ‏alt="" ריק, כדי שקורא המסך ידלג עליה

גודל התמונה

אפשר לקבוע גודל עם המאפיינים width ו-height (בפיקסלים, בלי "px"): <img src="cat.jpg" alt="חתול" width="150">. אם נותנים רק אחד, השני מחושב לפי הפרופורציות. בדרך כלל נקבע את הגודל ב-CSS.

תמונה שהיא קישור: שמים את img בתוך a: <a href="gallery.html"><img src="cat.jpg" alt="לגלריה"></a>.

כתובות יחסיות הן המקור מספר אחת לתקלות בשבועות הראשונים ("התמונה לא מופיעה"). כדאי לצייר על הלוח את עץ התיקיות מהדוגמה ולשאול את הכיתה מה כותבים בכל מקרה, במיוחד את ../. אחרי ההעלאה ל-Netlify צצה תקלת האותיות הגדולות והקטנות, כי Windows ו-Mac לא מבחינים בהן ושרתים כן.

🤔 הקובץ blog/post1.html רוצה להציג את images/cat.jpg (שתי התיקיות נמצאות בתיקייה הראשית). מה כותבים ב-src?

  • images/cat.jpg
  • ../images/cat.jpg
  • blog/images/cat.jpg
  • C:/my-site/images/cat.jpg

נכון! מתוך blog עולים תיקייה אחת עם .., ואז נכנסים ל-images.

🏆 אתגר 2: קישור ותמונה

קל
  1. הוסיפו קישור ל-https://github.com עם הטקסט "הפרופיל שלי ב-GitHub", שנפתח בלשונית חדשה (ואל תשכחו את rel).
  2. הוסיפו תמונה מהכתובת https://picsum.photos/id/1025/300/200 עם alt שמתאר אותה (יש בה כלב עטוף בשמיכה). ה-alt צריך להיות לפחות 5 תווים.

רשימות

יש שני סוגים עיקריים של רשימות. בשניהם כל פריט נכתב בתגית li (list item), והפריטים עטופים בתגית של הרשימה.

תגיתשםמתי משתמשים
ulunordered list, רשימה לא ממוספרתכשהסדר לא חשוב: רשימת קניות, תחביבים
olordered list, רשימה ממוספרתכשהסדר חשוב: שלבי מתכון, הוראות, דירוג

נסו: החליפו את ul ב-ol (בפתיחה ובסגירה) ותראו שהנקודות נהפכות למספרים.

רשימה בתוך רשימה

אפשר לקנן רשימה בתוך פריט של רשימה אחרת. שימו לב: הרשימה הפנימית נמצאת בתוך ה-li, לפני שהוא נסגר.

מאפיינים שימושיים ל-ol

  • <ol start="5">: מתחילים למספר מ-5.
  • <ol reversed>: ספירה לאחור (מתאים ל"10 הסרטים הכי טובים").
  • <ol type="a">: אותיות במקום מספרים.

טעות נפוצה: לשים טקסט או תגית אחרת ישירות בתוך ul. בתוך ul ו-ol מותר לשים רק li. כל השאר נכנס לתוך ה-li.

רשימות משמשות להרבה יותר מנקודות: כמעט כל תפריט ניווט באתרים בנוי כ-ul של קישורים. ב-CSS מעלימים את הנקודות ומסדרים את הפריטים בשורה.

🏆 אתגר 3: רשימת תחביבים

קל

צרו כותרת h2 "התחביבים שלי", ומתחתיה רשימה לא ממוספרת עם לפחות 3 תחביבים. אחר כך כותרת h2 "היעדים שלי לקורס" ומתחתיה רשימה ממוספרת עם לפחות 2 יעדים.

🤔 איזו רשימה הכי מתאימה לשלבי התקנה של תוכנה?

  • ul, כי זו רשימה
  • ol, כי הסדר חשוב
  • כמה פסקאות p

נכון! בשלבים הסדר חשוב, ולכן רשימה ממוספרת. ‏ul מתאימה כשאפשר להחליף את סדר הפריטים בלי לשנות את המשמעות.

‏div ו-span: קופסאות בלי משמעות

כל התגיות שראינו עד עכשיו אומרות משהו: h1 היא כותרת, p היא פסקה, a הוא קישור. לפעמים צריך פשוט קופסה שתעטוף כמה דברים, כדי לעצב אותם ביחד או לסדר אותם במקום. בשביל זה יש שתי תגיות שאין להן שום משמעות משלהן:

  • div (division, חלוקה): קופסה גדולה, שתופסת שורה שלמה.
  • span: קופסה קטנה, בתוך שורת טקסט.

ההבדל ביניהן הוא ההבדל החשוב ביותר ב-HTML: block מול inline.

אלמנט block (בלוק)אלמנט inline (בתוך השורה)
איפה מתחילתמיד בשורה חדשהממשיך באותה שורה, כמו מילה בטקסט
רוחבכל הרוחב שישרק כמה שהתוכן צריך
דוגמאותdiv, p, h1–h6, ul, lispan, a, strong, em, img

בדוגמה הבאה הוספנו קצת CSS (בלשונית CSS של העורך) שמצייר מסגרת סביב כל div ו-span, כדי שתראו איפה כל אחד מתחיל ונגמר. את ה-CSS עצמו נלמד בחלק הבא. בינתיים רק תסתכלו על התוצאה:

נסו: החליפו את אחד ה-div ב-span ותראו שהוא "נדבק" לשורה ומתכווץ לגודל הטקסט.

אז מתי משתמשים בהם?

  • ‏div: כדי לקבץ כמה אלמנטים ביחד, למשל כרטיס של מוצר (תמונה + כותרת + מחיר), כשאין תגית סמנטית שמתאימה יותר.
  • ‏span: כדי לתפוס חלק מטקסט ולעצב רק אותו, למשל מחיר באדום בתוך משפט.

כדי לעצב אותם נותנים להם מאפיין class, שם שבחרנו, ואז ב-CSS אומרים "כל מה שה-class שלו card ייראה כך":

‏class לעומת id: ‏class אפשר לתת לכמה אלמנטים (כל הכרטיסים הם card), ולאלמנט אחד יכולים להיות כמה classes: class="card featured". ‏id חייב להיות ייחודי בדף, ומשתמשים בו בעיקר לקישורי עוגן (#contact).

🤔 רוצים לצבוע באדום מילה אחת בתוך פסקה. באיזו תגית לעטוף אותה?

  • div
  • span
  • p
  • h1

נכון! ‏span הוא inline, ולכן המילה תישאר בתוך השורה. ‏div היה שובר את השורה ומעביר את המילה לשורה משלה.

תגיות סמנטיות

"סמנטי" פירושו "בעל משמעות". אפשר לבנות דף שלם רק מ-divים, והוא ייראה בדיוק אותו דבר. אבל ב-HTML5 יש תגיות שעובדות כמו div, וגם אומרות מה התפקיד של כל חלק בדף:

תגיתתפקיד
headerהחלק העליון: לוגו, שם האתר, לפעמים תפריט
navתפריט ניווט: קבוצה של קישורים עיקריים

articleתוכן שעומד בפני עצמו: פוסט, כתבה, כרטיס מוצר
asideתוכן צדדי: סרגל צד, "כתבות קשורות"
footerהחלק התחתון: זכויות יוצרים, פרטי קשר

שני הקודים הבאים נראים אותו דבר בדפדפן. איזה מהם קל יותר להבין?

  • קריאוּת: מי שקורא את הקוד (כולל אתם בעוד חודש) מבין מיד מה כל חלק.
  • נגישות: קורא מסך מאפשר לקפוץ ישר ל-main או ל-nav.
  • גוגל: מבין טוב יותר מה התוכן החשוב בדף.

הנה דף שלם עם מבנה סמנטי. גם כאן יש CSS שמסמן כל אזור, כדי שתראו את המבנה:

איך בוחרים? שואלים: "יש תגית שמתארת את התפקיד של החלק הזה?" אם כן, משתמשים בה. אם לא, ורק צריך קופסה לעיצוב, משתמשים ב-div. ‏div הוא לא "אסור", הוא פשוט ברירת המחדל האחרונה.

זה הרגע לחבר בין HTML לבין React: בשיעור 4 כל קומפוננטה תחזיר בדיוק עץ כזה של אלמנטים. כדאי לבקש מהכיתה לפתוח אתר חדשות ולזהות בכלי המפתחים (לשונית Elements) את ה-header, ה-nav וה-footer. ברוב האתרים יימצא גם "מרק div", וזו הזדמנות טובה לדיון.

🏆 אתגר 4: מ-div לסמנטי

בינוני

הקוד בעורך בנוי כולו מ-divים. החליפו כל div בתגית הסמנטית שמתאימה לו (ה-class של כל div רומז על התפקיד), כך שבסוף יהיו בדף header, ‏nav, ‏main, שני article ו-footer, ולא יישאר אף div. אפשר למחוק את ה-classes.

טבלאות

טבלאות מיועדות לנתונים בטבלה: מערכת שעות, מחירון, תוצאות. בנייה של טבלה נעשית שורה אחרי שורה:

תגיתמה היא
tableעוטפת את כל הטבלה
trtable row: שורה
thtable header: תא כותרת (מודגש וממורכז)
tdtable data: תא רגיל
thead, tbodyמחלקים את הטבלה לראש ולגוף. לא חובה, אבל מומלץ
captionכותרת לטבלה כולה

נסו להוסיף שורה שלישית לשעה 12:30. העתיקו <tr> שלם עם כל ה-td שבתוכו.

מיזוג תאים

‏colspan="2" גורם לתא להתפרס על פני שתי עמודות, ו-rowspan="2" על פני שתי שורות. למשל: <td colspan="2">יום ספורט</td>.

לא משתמשים בטבלאות לעימוד. פעם (לפני 20 שנה) בנו דפים שלמים מטבלאות כדי לסדר דברים בעמודות. היום עושים את זה עם CSS (‏Flexbox ו-Grid). טבלה מיועדת רק לנתונים שבאמת יש להם שורות ועמודות.

טפסים

טפסים הם הדרך של הגולש לשלוח מידע: הרשמה, התחברות, חיפוש, יצירת קשר. בשלב הזה נלמד לבנות את הטופס. מה עושים עם המידע שנשלח נלמד ב-JavaScript ובשיעורי React.

אבני הבניין

תגיתתפקיד
formעוטפת את כל הטופס
labelהתווית: הטקסט שמסביר מה למלא בשדה
inputשדה קלט. תגית ריקה. הסוג נקבע במאפיין type
textareaשדה טקסט ארוך, עם כמה שורות
select + optionרשימה נפתחת
buttonכפתור

‏label: למה זה כל כך חשוב

לכל שדה צריכה להיות תווית. מחברים בין השניים כך: נותנים לשדה id, ול-label מאפיין for עם אותו ערך בדיוק.

החיבור הזה עושה שני דברים: לחיצה על התווית מעבירה את הסמן לשדה (נוח מאוד בטלפון, כשהשדות קטנים), וקורא מסך מקריא "שם משתמש" כשנכנסים לשדה. בלי label, משתמש עיוור לא יודע מה למלא.

המאפיין name הוא השם שבו המידע יישלח לשרת. ‏id מיועד ל-label, ו-name מיועד לשליחה. לרוב נותנים לשניהם אותו ערך.

סוגים של input

אותה תגית input נראית ומתנהגת אחרת לפי ה-type. בטלפון, סוגים כמו email ו-tel גם פותחים מקלדת מתאימה.

‏placeholder הוא טקסט אפור שמופיע בשדה ריק, כרמז. הוא לא תחליף ל-label, כי הוא נעלם ברגע שמתחילים להקליד.

כפתורי בחירה (radio)

כפתורי radio מאפשרים לבחור אפשרות אחת בלבד מתוך קבוצה. מה שהופך אותם לקבוצה הוא אותו name. נסו למחוק את ה-name מאחד מהם ותראו שאפשר לבחור את שניהם.

טופס שלם

  • required: השדה חובה. הדפדפן לא ישלח את הטופס אם הוא ריק, ויציג הודעה. בקובץ אמיתי נסו ללחוץ "שליחה" עם שדות ריקים.
  • type="email" בודק גם שהערך נראה כמו כתובת מייל (יש בו @).
  • <button type="submit"> שולח את הטופס. ‏type="button" יוצר כפתור שלא שולח כלום (נשתמש בו עם JavaScript).

בכיתה אפשר לדלג על טבלאות ועל רוב הטפסים ולהשאיר אותם ללימוד עצמי. שווה רק להדגים את הקשר בין label for ל-id (הלחיצה על התווית תמיד מפתיעה סטודנטים), ואת name המשותף ב-radio. בשיעור 6 נחזור לטפסים עם React.

🏆 אתגר 5: טופס הרשמה

בינוני

בנו טופס הרשמה לסדנה, בתוך form, עם:

  1. שדה טקסט לשם, ושדה email לאימייל. שניהם required.
  2. שני כפתורי radio לבחירת מסלול ("בוקר" ו"ערב") עם אותו name.
  3. לכל שדה (כולל כל radio) תהיה label שמחוברת אליו עם for ו-id.
  4. כפתור שליחה.

🤔 יש שלושה כפתורי radio, ואפשר לסמן את שלושתם ביחד. מה כנראה הבעיה?

  • חסר להם label
  • יש להם name שונה (או שאין להם name)
  • חסר required
  • צריך להחליף אותם ב-checkbox

נכון! כפתורי radio עם אותו name הם קבוצה אחת, ובקבוצה אפשר לבחור רק אחד.

נגישות: צ׳קליסט

נגישות (Accessibility, בקיצור a11y) פירושה שכל אחד יכול להשתמש באתר: אנשים עיוורים עם קורא מסך, אנשים שמנווטים רק במקלדת, אנשים עם ראייה חלשה. בישראל זו גם חובה בחוק לרוב האתרים. החדשות הטובות: רוב הנגישות מגיעה בחינם, אם כותבים HTML נכון.

  • ☐ ‏<html lang="he" dir="rtl">, כדי שקורא המסך ידבר עברית.
  • ☐ ‏h1 אחד, וכותרות לפי הסדר בלי לדלג על רמות.
  • ☐ לכל img יש alt שמתאר אותה (או alt="" לתמונה קישוטית).
  • ☐ לכל שדה בטופס יש label מחוברת.
  • ☐ טקסט של קישור אומר לאן הוא מוביל (לא "לחצו כאן").
  • ☐ משתמשים בתגיות סמנטיות: header, ‏nav, ‏main, ‏footer.
  • ☐ כפתור הוא button וקישור הוא a, ולא div שעושה את עצמו כפתור.

נסו בעצמכם: פתחו את הדף שלכם ונסו להשתמש בו רק עם המקלדת: Tab עובר לאלמנט הבא, Enter לוחץ. אם אפשר להגיע לכל קישור ולכל שדה, אתם בכיוון הנכון. ב-Chrome יש גם בדיקה אוטומטית: כלי המפתחים ← לשונית Lighthouse ← Accessibility.

🏆 אתגר 6: דף מתכון

מאתגר

בנו דף מתכון שלם, עם כל מה שלמדנו. הדרישות:

  1. ‏header ובו h1 עם שם המתכון.
  2. ‏main ובו:
    • תמונה עם alt (אפשר להשתמש ב-https://picsum.photos/id/292/400/250)
    • כותרת h2 "מצרכים" ורשימה לא ממוספרת עם לפחות 4 מצרכים
    • כותרת h2 "אופן ההכנה" ורשימה ממוספרת עם לפחות 3 שלבים
    • טבלה קטנה עם שורת כותרת (th) ולפחות שורת נתונים אחת (למשל זמן הכנה ומספר מנות)
  3. ‏footer ובו קישור למקור המתכון.
בינוני

תרגיל בית: עמוד "אודות" ב-VS Code

צרו בתיקייה חדשה שני קבצים: index.html ו-about.html, עם שלד מלא. בכל אחד מהם שימו nav עם קישורים יחסיים לשני הדפים, כך שאפשר לעבור ביניהם. פתחו עם Live Server ובדקו שהקישורים עובדים.

הצגת פתרון 
<!DOCTYPE html>
<html lang="he" dir="rtl">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>אודות</title>
  </head>
  <body>
    <header>
      <nav>
        <a href="index.html">בית</a> |
        <a href="about.html">אודות</a>
      </nav>
    </header>
    <main>
      <h1>אודות</h1>
      <p>כאן כותבים קצת על עצמכם.</p>
    </main>
  </body>
</html>

ב-index.html אותו דבר, רק עם כותרת ותוכן אחרים. שני הקבצים באותה תיקייה, ולכן הכתובת היא רק שם הקובץ.

אתגר 6 מתאים כתרגול עצמי בסוף השיעור או בבית. מי שמסיים מהר יכול לקבל משימה נוספת: להעביר את המתכון לקובץ ב-VS Code עם שלד מלא. בפרויקט של השיעור (דף הפרופיל) הסטודנטים ישתמשו בכל התגיות האלה שוב, הפעם עם עיצוב.

סיכום

  • הדפדפן מבקש קבצים מהשרת ב-HTTP ומציג אותם. ‏HTML הוא התוכן, CSS העיצוב, JavaScript ההתנהגות.
  • אלמנט = תגית פתיחה + תוכן + תגית סגירה. מאפיינים נותנים מידע נוסף: href, ‏src, ‏alt.
  • כל דף מתחיל בשלד: DOCTYPE, ‏html lang dir, ‏head עם charset ו-title, ו-body.
  • אלמנטי block מתחילים שורה חדשה (div, ‏p), ואלמנטי inline נשארים בשורה (span, ‏a).
  • בוחרים תגית לפי המשמעות, לא לפי המראה. את המראה קובעים ב-CSS.
  • ‏HTML נכון הוא HTML נגיש: alt, ‏label, כותרות מסודרות ותגיות סמנטיות.

בחלק הבא נלמד לעצב את כל זה עם CSS.
