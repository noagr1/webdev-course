Git ו-GitHub: שומרים, מגבים ומשתפים קוד

⏱️ 25 דק׳ בכיתה 📚 שעתיים–שלוש לימוד עצמי טרמינל Git GitHub Netlify

עד עכשיו כתבנו קבצים ושמרנו אותם עם Ctrl+S. בחלק הזה נלמד את הכלי שכל מפתח ומפתחת בעולם משתמשים בו כל יום: Git. נלמד גם לעבוד עם GitHub, האתר שבו שומרים את הקוד בענן. בסוף החלק הדף שלכם יהיה שמור, מגובה ומפורסם באינטרנט.

אם אף פעם לא פתחתם טרמינל, זה בסדר גמור. נתחיל מהבסיס ממש, ונסביר כל פקודה וכל הודעה שהמחשב מחזיר.

מטרות החלק

בסוף החלק תדעו:

  • להסביר מה זה ניהול גרסאות, ומה ההבדל בין Git ל-GitHub
  • לעבוד בטרמינל: לנווט בין תיקיות, ליצור תיקיות ולהריץ פקודות
  • ליצור מאגר Git, לשמור שינויים (commit) ולראות את ההיסטוריה
  • לבטל טעויות ולהשתמש בקובץ .gitignore
  • להעלות פרויקט ל-GitHub, ולהוריד ממנו פרויקטים
  • לפרסם אתר ב-Netlify, כך שכל push יעדכן אותו
  • לזהות את התקלות הנפוצות ולפתור אותן לבד

בכיתה (25 דק׳): מסבירים בקצרה למה צריך Git, שלושת האזורים והמושגים (5 דק׳). אחר כך מדגימים מול הכיתה את כל התהליך, מ-git init ועד git push (10 דק׳). בעשר הדקות האחרונות כל הסטודנטים עושים push ראשון. המטרה היחידה שחייבת להתממש בכיתה היא push ראשון מוצלח אצל כולם. כל השאר (ביטולים, ענפים, ‏clone, תקלות) מיועד ללמידה עצמית.

מומלץ לשמור את העמוד הזה פתוח על מסך נוסף בזמן ההדגמה, ולהפנות לסעיף "תקלות נפוצות" כשמשהו נתקע.

למה צריך ניהול גרסאות?

נניח שאתם כותבים עבודה סמינריונית. אחרי כמה שבועות, התיקייה נראית כך:

עבודה.docx
עבודה_מתוקן.docx
עבודה_מתוקן_2.docx
עבודה_סופית.docx
עבודה_סופית_v3_באמת_סופי.docx
עבודה_סופית_v3_באמת_סופי_אחרי_הערות_המנחה.docx

מוכר? עכשיו תחשבו על פרויקט תוכנה עם מאות קבצים ועם כמה אנשים שעובדים עליו בו זמנית. אי אפשר לנהל אותו ככה. כאן נכנס Git, מערכת לניהול גרסאות (Version Control System). היא פותרת ארבע בעיות:

בעיהאיך Git פותר אותה
🕰️ היסטוריה: "מה השתנה, ומתי?"כל שמירה (commit) נרשמת עם תאריך, מי עשה אותה והסבר קצר. אפשר לראות בדיוק אילו שורות השתנו.
↩️ ביטול: "שברתי משהו, ואתמול זה עבד!"אפשר לחזור לכל גרסה קודמת, של קובץ אחד או של כל הפרויקט.
👥 עבודת צוות: "שנינו שינינו את אותו קובץ"‏Git יודע לשלב שינויים של כמה אנשים, ומתריע כשיש התנגשות.
☁️ גיבוי: "המחשב נפל ונשבר"מעלים עותק של כל ההיסטוריה ל-GitHub. אפשר להוריד אותו לכל מחשב, בכל רגע.

למה זה חשוב לכם כבר עכשיו? ‏Git הוא כלי חובה בכל משרת פיתוח. בנוסף, פרופיל GitHub עם פרויקטים מסודרים הוא חלק מקורות החיים של כל מפתח: מעסיקים נכנסים אליו. כל פרויקט בקורס יישמר שם.

Git לעומת GitHub

השמות דומים, וקל להתבלבל. אבל אלה שני דברים שונים:

GitGitHub

אנלוגיה: ‏Git הוא כמו מצלמה, ו-GitHub הוא כמו אלבום תמונות בענן (Google Photos). אפשר לצלם בלי להעלות לענן, אבל ההעלאה שומרת על התמונות ומאפשרת לשתף אותן.

ל-GitHub יש מתחרים שעובדים באותה צורה בדיוק, למשל GitLab ו-Bitbucket. מה שתלמדו כאן מתאים לכולם.

איזה מהמשפטים הבאים נכון?

  • אי אפשר להשתמש ב-Git בלי חשבון GitHub
  • ‏Git עובד במחשב שלכם גם בלי אינטרנט, ו-GitHub הוא אתר שמאחסן עותק בענן
  • ‏Git ו-GitHub הם שני שמות לאותה תוכנה

‏Git הוא תוכנה מקומית, ואפשר להשתמש בו לבד לגמרי. ‏GitHub הוא שירות שמתחבר ל-Git ושומר עותק בענן.

מילון מושגים

לפני שמקלידים פקודה ראשונה, נכיר את המילים. אל דאגה, נחזור על כל אחת מהן בהמשך עם דוגמאות.

מושגמה זהאנלוגיה
Repository (ריפו, מאגר)תיקיית פרויקט ש-Git עוקב אחריה, כולל כל ההיסטוריה שלהאלבום התמונות של הפרויקט
Commit"תמונת מצב" של הפרויקט ברגע מסוים, עם הודעה שמסבירה מה השתנהנקודת שמירה במשחק מחשב: אפשר תמיד לחזור אליה
Staging area (אזור ההכנה)המקום שבו מסמנים אילו שינויים ייכנסו ל-commit הבאארגז לפני משלוח: מכניסים מה ששולחים, ורק אז סוגרים ושולחים
Branch (ענף)קו פיתוח נפרד, שמאפשר לנסות משהו בלי לגעת בגרסה הראשיתטיוטה נפרדת של העבודה
Remoteעותק של הריפו שנמצא במקום אחר, בדרך כלל ב-GitHub. השם המקובל שלו הוא originהאלבום בענן
Pushהעלאת commits מהמחשב ל-remoteהעלאת תמונות לענן
Pullהורדת commits חדשים מה-remote למחשבסנכרון תמונות חדשות מהענן לטלפון
Cloneהורדה ראשונה של ריפו שלם מ-GitHub למחשבהורדת אלבום שלם בפעם הראשונה
HEADמצביע ל-commit שאתם "נמצאים" בו עכשיו (בדרך כלל האחרון)"אתם נמצאים כאן" במפה

הטרמינל למתחילים

הטרמינל (נקרא גם שורת הפקודה, Command Line או Shell) הוא חלון שבו נותנים למחשב הוראות בטקסט, במקום ללחוץ עם העכבר. בהתחלה הוא נראה מפחיד, אבל מספיקות כ-10 פקודות כדי להסתדר מצוין.

איך פותחים טרמינל?

מערכתאיך פותחים
Windowsאחרי התקנת Git יש תוכנה בשם Git Bash (מחפשים אותה בתפריט התחל). אפשר גם PowerShell. בקורס נעבוד עם Git Bash, כי הפקודות בו זהות לפקודות ב-Mac.
Macלוחצים Cmd+רווח, מקלידים Terminal ולוחצים Enter.
VS Code (מומלץ!)בתוך VS Code לוחצים Ctrl + ` (המקש שמתחת ל-Esc), או בוחרים בתפריט Terminal ← New Terminal. הטרמינל נפתח ישר בתיקיית הפרויקט.

Windows + VS Code: כדי שהטרמינל ב-VS Code יהיה Git Bash, לוחצים על החץ הקטן ליד הסימן + בחלון הטרמינל, ובוחרים Select Default Profile ← Git Bash.

האנטומיה של פקודה

כל פקודה בנויה מאותם חלקים:

$ git commit -m "Add navbar"
# git       ← הפקודה (התוכנה שמריצים)
# commit    ← תת-פקודה: מה רוצים ש-git יעשה
# -m        ← דגל (flag): אפשרות שמשנה את ההתנהגות. m = message
# "Add navbar" ← ארגומנט: הערך של הדגל. יש מרכאות כי יש רווח

הסימן $ בתחילת השורה נקרא prompt. הוא מסמן שהטרמינל מחכה לפקודה. לא מקלידים אותו. באתר הזה, שורה שמתחילה ב-$ היא פקודה, ושורה בלי $ היא מה שהמחשב מחזיר.

נתיב מוחלט ונתיב יחסי

  • נתיב מוחלט מתחיל מהשורש של המחשב, למשל /Users/dana/Documents. הוא עובד מכל מקום.
  • נתיב יחסי מתחיל מהמקום שבו אתם נמצאים, למשל web-course או ../Downloads. בדיוק כמו נתיבים יחסיים בקישורים ב-HTML (חלק א׳).

טריקים שחוסכים זמן

  • Tab: מקלידים את תחילת השם של תיקייה או קובץ ולוחצים Tab, והטרמינל משלים לבד. חוסך טעויות הקלדה.
  • חץ למעלה ↑: מחזיר את הפקודה הקודמת. לחיצות נוספות מחזירות פקודות ישנות יותר.
  • Ctrl+C: עוצר פקודה שרצה או "תקועה". (בטרמינל זה לא העתקה!)
  • העתקה והדבקה: ב-Mac: ‏Cmd+C ו-Cmd+V. ב-Git Bash: לחיצה ימנית ← Copy או Paste, או Ctrl+Insert ו-Shift+Insert. בטרמינל של VS Code: ‏Ctrl+C ו-Ctrl+V עובדים כשיש טקסט מסומן.
  • שמות עם רווחים צריך לעטוף במרכאות: cd "My Projects". לכן עדיף לתת לתיקיות שמות בלי רווחים, למשל my-projects.

תרגיל קצר: סיור בטרמינל קל

  1. פתחו טרמינל והציגו באיזו תיקייה אתם נמצאים.
  2. היכנסו לתיקיית Documents (או Desktop).
  3. צרו תיקייה בשם web-course והיכנסו אליה.
  4. צרו בתוכה תיקייה בשם lesson-01, היכנסו אליה, וצרו קובץ ריק בשם index.html.
  5. הציגו את תוכן התיקייה, ואז חזרו שתי תיקיות למעלה.
הצגת פתרון 
$ pwd
$ cd Documents
$ mkdir web-course
$ cd web-course
$ mkdir lesson-01
$ cd lesson-01
$ touch index.html
$ ls
index.html
$ cd ../..
$ pwd

‏cd ../.. עולה שתי רמות בפקודה אחת. אפשר גם להריץ cd .. פעמיים.

הרבה סטודנטים לא פתחו טרמינל אף פעם. כדאי להראות על המסך ש-ls מציג בדיוק את מה שרואים ב-Finder או בסייר הקבצים: "זה אותו דבר, רק בטקסט". טעות נפוצה היא להקליד גם את ה-$. טעות נוספת היא לעבוד בתיקייה הלא נכונה. כדאי להרגיל את הכיתה להריץ pwd כשלא בטוחים איפה הם נמצאים.

הגדרה ראשונית: מי אתם?

כל commit שומר את השם והמייל של מי שיצר אותו. לכן, לפני ה-commit הראשון, צריך לספר ל-Git מי אתם. עושים את זה פעם אחת בלבד בכל מחשב:

$ git config --global user.name "Dana Cohen"
$ git config --global user.email "dana@example.com"
$ git config --global init.defaultBranch main
שורהמה היא עושה
user.nameהשם שיופיע ליד כל commit. כדאי באנגלית.
user.emailהמייל. השתמשו באותו מייל שאיתו נרשמתם ל-GitHub, כדי ש-GitHub יקשר את ה-commits לפרופיל שלכם.
init.defaultBranch mainהענף הראשי בכל ריפו חדש ייקרא main (זה השם המקובל היום, וגם GitHub משתמש בו).
--globalההגדרה חלה על כל הפרויקטים במחשב, ולא רק על התיקייה הנוכחית.

אפשר לבדוק מה הוגדר:

$ git config --global --list
user.name=Dana Cohen
user.email=dana@example.com
init.defaultbranch=main

הפקודות האלה לא מחזירות שום הודעה כשהן מצליחות. זה נורמלי! בטרמינל, שקט = הצלחה. הודעה מופיעה בדרך כלל רק כשמשהו השתבש.

שלושת האזורים של Git

זה הרעיון הכי חשוב בחלק הזה. מי שמבינים אותו, מבינים את Git. כל קובץ בפרויקט נמצא באחד משלושה "אזורים":

אזורמה יש בואיך מגיעים אליו
📝 Working Directory (תיקיית העבודה)הקבצים כמו שהם עכשיו בתיקייה, כולל שינויים שעוד לא נשמרו ב-Gitעורכים קובץ ב-VS Code ושומרים (Ctrl+S)
📦 Staging Area (אזור ההכנה)השינויים שבחרתם להכניס ל-commit הבאgit add
🗄️ Repository (המאגר)כל ה-commits, כלומר ההיסטוריה השמורהgit commit
  עריכה ושמירה            git add              git commit
  ───────────────►  📝  ───────────────►  📦  ───────────────►  🗄️
                  עבודה                 הכנה                 מאגר

אנלוגיה של צילום משפחתי: תיקיית העבודה היא כל האנשים בחדר. ‏git add הוא לקרוא לאנשים שייכנסו לתמונה. ‏git commit הוא ללחוץ על הכפתור ולצלם. אפשר לבחור לצלם רק חלק מהאנשים.

למה צריך שלב הכנה? כי לפעמים שיניתם חמישה קבצים, אבל רק שלושה מהם שייכים לאותו שינוי. אזור ההכנה מאפשר ליצור commit מסודר שעוסק בדבר אחד. בהתחלה, ברוב המקרים תוסיפו פשוט הכול.

ערכתם את style.css, שמרתם ב-VS Code והרצתם git add style.css. איפה השינוי נמצא עכשיו?

  • רק בתיקיית העבודה
  • באזור ההכנה (staging). הוא ייכנס להיסטוריה רק אחרי git commit
  • ב-GitHub

‏git add רק מכין את השינוי. ‏commit שומר אותו בהיסטוריה המקומית, ורק git push מעלה אותו ל-GitHub.

הריפו הראשון שלכם, צעד אחר צעד

עכשיו נעבור על כל התהליך בפועל. פתחו טרמינל ועבדו יחד עם העמוד. נשתמש בתיקייה מהתרגיל הקודם (web-course/lesson-01). אם תרצו, אפשר לעבוד ישר על תיקיית הפרויקט מעמוד הפרויקט.

1

2

‏Git יצר תיקייה מוסתרת בשם .git. בה הוא שומר את כל ההיסטוריה. אפשר לראות אותה עם ls -a. לא נוגעים בה ולא מוחקים אותה: מחיקה שלה מוחקת את כל ההיסטוריה.

מריצים git init פעם אחת בלבד לכל פרויקט, ובתיקיית הפרויקט עצמה. לעולם לא בתיקיית הבית (~) ולא ב-Desktop כולו. אחרת Git ינסה לעקוב אחרי כל הקבצים במחשב.

3

בודקים מצב: git status

$ git status

No commits yet

Untracked files:

	index.html

nothing added to commit but untracked files present (use "git add" to track)

מה Git אומר כאן?

  • On branch main: אתם על הענף הראשי.
  • No commits yet: עוד אין היסטוריה.
  • Untracked files: קבצים ש-Git רואה אבל עוד לא עוקב אחריהם. בטרמינל הם מופיעים באדום.

‏git status היא הפקודה הכי חשובה. הריצו אותה כל הזמן: לפני כל פקודה ואחריה. היא אף פעם לא משנה כלום, רק מראה מה המצב, ובדרך כלל גם מציעה מה לעשות הלאה.

4

	new file:   index.html

עכשיו הקובץ מופיע תחת Changes to be committed, בירוק. הוא מוכן ל-commit.

אפשרויות נפוצות:

פקודהמה מוסיפה

git add .כל השינויים בתיקייה הנוכחית ובתיקיות שבתוכה. הנקודה פירושה "התיקייה הזאת". זו הפקודה שתשתמשו בה הכי הרבה.
5

שומרים בהיסטוריה: git commit

$ git commit -m "Add first HTML page"
[main (root-commit) 3f2a9c1] Add first HTML page
 1 file changed, 12 insertions(+)
 create mode 100644 index.html

פענוח ההודעה:

  • main: ה-commit נוצר על הענף main. ‏root-commit פירושו שזה ה-commit הראשון.
  • 3f2a9c1: המזהה (hash) של ה-commit. לכל commit יש מזהה ייחודי. אפשר להשתמש בו כדי לחזור לגרסה הזאת.
  • 1 file changed, 12 insertions(+): קובץ אחד השתנה, ונוספו לו 12 שורות.

שכחתם את -m? ‏Git יפתח עורך כדי שתכתבו הודעה. אם הגדרתם VS Code כעורך, ייפתח קובץ: כתבו בשורה הראשונה את ההודעה, שמרו וסגרו את הלשונית. אם נפתח Vim (מסך שחור עם ~ בכל שורה), לחצו Esc, הקלידו :q! ולחצו Enter, ואז הריצו שוב את הפקודה עם -m.

עוד שינוי, עוד commit

עכשיו עובדים כרגיל: ערכו את index.html (למשל הוסיפו פסקה), צרו קובץ style.css ושמרו. ואז:

	style.css

שימו לב להבדל: modified הוא קובץ ש-Git כבר מכיר ושהשתנה. ‏Untracked הוא קובץ חדש לגמרי. ‏git add . מטפל בשניהם.

המעגל היומיומי (תשננו אותו):

# 1. עובדים: עורכים קבצים ושומרים

# 2. חוזרים לעבוד... וחוזר חלילה

בהדגמה בכיתה כדאי להריץ git status אחרי כל פקודה ולהקריא את הפלט בקול. ככה הסטודנטים מתרגלים לקרוא את מה ש-Git אומר במקום לפחד ממנו. כדאי גם להראות בכוונה את המצב שבו שוכחים git add ומקבלים nothing added to commit.

לראות מה השתנה: git diff

‏git status אומר אילו קבצים השתנו. ‏git diff מראה מה בדיוק השתנה בהם, שורה אחרי שורה:

$ git diff
diff --git a/index.html b/index.html
--- a/index.html
+++ b/index.html
@@ -8,7 +8,7 @@
   <body>
-    <h1>שלום עולם</h1>
+    <h1>דנה כהן: מפתחת ווב</h1>
     <p>ברוכים הבאים לדף שלי</p>
  • שורה שמתחילה ב-- (באדום) נמחקה.
  • שורה שמתחילה ב-+ (בירוק) נוספה.
  • שינוי של שורה מופיע כמחיקה של הישנה והוספה של החדשה.
  • @@ -8,7 +8,7 @@ אומר באיזה מקום בקובץ נמצא השינוי (שורה 8).
פקודהמה מראה
git diffשינויים שעוד לא הוספתם עם git add
git diff --stagedשינויים שכבר נמצאים באזור ההכנה, ושייכנסו ל-commit הבא

אם הפלט ארוך, הטרמינל מציג אותו בעמודים. החצים גוללים, ו-q יוצא. (זה נכון גם ל-git log.)

איך כותבים הודעת commit טובה

בעוד חודש, ההודעות יהיו הדרך היחידה שלכם להבין מה עשיתם. גם מעסיקים שמסתכלים ב-GitHub שלכם קוראים אותן.

❌ לא טוב✅ טוב
updateAdd contact section with email link
fixFix navbar overflow on mobile
asdfghChange hero background to gradient
lots of changesכמה commits קטנים, כל אחד על דבר אחד

כללי אצבע:

  • כותבים באנגלית, בציווי ("Add", "Fix", "Remove"), כאילו משלימים את המשפט: "If applied, this commit will…"
  • שורה אחת קצרה, עד כ-50 תווים.
  • commit אחד = שינוי הגיוני אחד. עדיף הרבה commits קטנים מאשר אחד ענק בסוף היום.
  • מתי לעשות commit? בכל פעם שמשהו עובד: סיימתם את ה-navbar? ‏commit. הוספתם כרטיס? ‏commit.

ביטול טעויות

הסיבה העיקרית להשתמש ב-Git: אפשר לבטל כמעט כל דבר. הנה המצבים הנפוצים, מהקל לכבד:

1. "הרסתי קובץ ועוד לא עשיתי add": חזרה לגרסה האחרונה

$ git restore index.html

הקובץ חוזר למצב שלו ב-commit האחרון. זהירות: השינויים שלא נשמרו ב-commit יימחקו לתמיד.

2. "עשיתי add לקובץ שלא רציתי": הוצאה מאזור ההכנה

$ git restore --staged notes.txt

הקובץ יוצא מאזור ההכנה, אבל השינויים בו נשארים. כלום לא נמחק.

3. "טעות בהודעה של ה-commit האחרון" או "שכחתי קובץ"

$ git add forgotten-file.css
$ git commit --amend -m "Add navbar with styles"

‏--amend מחליף את ה-commit האחרון בגרסה מתוקנת. משתמשים בזה רק לפני push.

4. "commit ישן שבר משהו": ביטול בטוח עם revert

$ git log --oneline
d91c2e4 (HEAD -> main) Add about page
a7f03b8 Add skills heading
$ git revert a7f03b8

‏git revert יוצר commit חדש שמבטל את השינויים של commit ישן. ההיסטוריה לא נמחקת, ולכן זה בטוח גם אחרי push. ‏Git יפתח עורך עם הודעה מוכנה: שומרים וסוגרים.

5. רק להציץ בגרסה ישנה

$ git restore --source=3f2a9c1 index.html
# index.html חוזר לגרסה מאותו commit. אם זה מה שרציתם: add ו-commit
# אם לא: git restore index.html מחזיר למצב האחרון
מצבפקודהמוחק עבודה?
שינוי בקובץ שלא נוסף עם addgit restore קובץ⚠️ כן, את השינויים שלא נשמרו
קובץ נוסף עם add בטעותgit restore --staged קובץ✅ לא
תיקון ה-commit האחרון (לפני push)git commit --amend✅ לא
ביטול commit ישןgit revert hash✅ לא, נוצר commit חדש

באינטרנט תמצאו גם את git reset --hard. היא חזקה ומוחקת עבודה בלי אפשרות לשחזר. בשלב הזה של הקורס, אל תשתמשו בה.

כבר עשיתם push ל-GitHub, ואז גיליתם ש-commit מלפני שלושה ימים שבר את העיצוב. מה הדרך הבטוחה לבטל אותו?

  • למחוק את תיקיית .git ולהתחיל מחדש
  • git commit --amend
  • git revert עם ה-hash של אותו commit

‏revert מוסיף commit חדש שמבטל את הישן, בלי לשכתב היסטוריה שכבר נמצאת ב-GitHub. ‏--amend משנה רק את ה-commit האחרון, ומחיקת .git מוחקת את כל ההיסטוריה.

קבצים ש-Git צריך להתעלם מהם: .gitignore

יש קבצים שלא רוצים לשמור בריפו: קבצי מערכת (כמו .DS_Store ב-Mac), הגדרות אישיות של העורך, ובהמשך הקורס גם תיקיית node_modules הענקית וקבצי .env עם סיסמאות.

יוצרים בתיקייה הראשית של הפרויקט קובץ בשם .gitignore (עם נקודה בהתחלה, ובלי סיומת), וכותבים בו מה להתעלם ממנו, שורה לכל דבר:

# קבצי מערכת
.DS_Store
Thumbs.db

# הגדרות עורך
.vscode/

# נצטרך את אלה מהשיעור הרביעי
node_modules/
.env
  • שורה שמתחילה ב-# היא הערה.
  • / בסוף השם פירושו תיקייה.
  • *.log פירושו כל הקבצים שמסתיימים ב-.log.

אחרי שיוצרים את הקובץ, ‏git status כבר לא יציג את הקבצים האלה. את ה-.gitignore עצמו כן מוסיפים ל-commit:

$ git add .gitignore
$ git commit -m "Add gitignore"

סיסמאות ומפתחות לעולם לא נכנסים ל-Git. גם אם מוחקים אותם ב-commit מאוחר יותר, הם נשארים בהיסטוריה, וב-GitHub ציבורי כל אחד יכול למצוא אותם. נלמד לעבוד נכון עם סודות בשיעור 9.

Git בתוך VS Code

כל מה שעשינו בטרמינל אפשר לעשות גם בלחיצות ב-VS Code. חשוב להכיר את שתי הדרכים: הטרמינל עוזר להבין מה קורה, והממשק נוח לעבודה יומיומית.

  • צבעים בסייר הקבצים: קובץ חדש מסומן ב-U (Untracked, ירוק), וקובץ שהשתנה מסומן ב-M (Modified, צהוב-כתום).
  • לשונית Source Control (האייקון של הענף בסרגל הצד, או Ctrl+Shift+G): מציגה את כל הקבצים שהשתנו. לחיצה על קובץ מציגה diff, הישן מול החדש.
  • הסימן + ליד קובץ = git add לאותו קובץ.
  • תיבת ההודעה + הכפתור ✓ Commit = git commit -m.
  • הכפתור Sync Changes (או החצים בפינה השמאלית התחתונה) = git pull ואז git push.
  • פסים צבעוניים ליד מספרי השורות בעורך: ירוק = שורה חדשה, כחול = שורה שהשתנתה, משולש אדום = שורה נמחקה.

אם לוחצים Commit בלי לסמן קבצים עם +, ‏VS Code שואל אם להוסיף את כל השינויים. אפשר לענות Yes, או Always כדי שלא ישאל שוב.

GitHub: מעלים את הפרויקט לענן

עד עכשיו כל ההיסטוריה נמצאת רק במחשב שלכם. עכשיו נעלה אותה ל-GitHub.

1

פותחים חשבון

נרשמים ב-github.com/signup עם אותו מייל שהגדרתם ב-git config. בחרו שם משתמש מקצועי, למשל dana-cohen ולא dana_the_queen99. הוא יופיע בכתובות של כל הפרויקטים שלכם.

2

יוצרים ריפו חדש באתר

  1. לוחצים על + בפינה העליונה ← New repository.
  2. Repository name: שם קצר באנגלית, בלי רווחים, למשל profile-page.
  3. Public: כדי שאחרים (ומעסיקים) יוכלו לראות.
  4. חשוב: לא מסמנים "Add a README file", ‏.gitignore או license. כבר יש לנו ריפו מקומי, וריפו ריק ב-GitHub מונע התנגשויות.
  5. לוחצים Create repository.

‏GitHub יציג עמוד עם הוראות. מעניין אותנו החלק "…or push an existing repository from the command line".

3

מחברים את הריפו המקומי ל-GitHub

$ git branch -M main
$ git push -u origin main
פקודהמה היא עושה
git remote add origin URLשומרת את הכתובת של הריפו ב-GitHub תחת הכינוי origin. פעם אחת לכל פרויקט.
git branch -M mainמוודאת שהענף נקרא main. אם כבר הגדרתם init.defaultBranch, הפקודה לא משנה כלום, אבל לא מזיקה.

העתיקו את הכתובת מהעמוד של GitHub. בכתובת צריך להופיע שם המשתמש שלכם. אפשר לוודא שהחיבור נשמר:

origin  https://github.com/dana-cohen/profile-page.git (push)
4

התחברות (פעם ראשונה בלבד)

ב-push הראשון, ‏Git צריך לדעת שאתם באמת הבעלים של החשבון:

  • Windows: נפתח חלון של Git Credential Manager. בוחרים Sign in with your browser, מאשרים בדפדפן, וזהו. החיבור נשמר.
  • Mac / VS Code: בדרך כלל VS Code מציע "Sign in with GitHub" ופותח את הדפדפן. מאשרים, וזהו.
  • אם הטרמינל מבקש Username ו-Password: הסיסמה הרגילה של GitHub לא תעבוד (‏GitHub הפסיק לתמוך בזה). במקומה צריך Personal Access Token: ב-GitHub נכנסים ל-Settings ← Developer settings ← Personal access tokens ← Tokens (classic) ← Generate new token, מסמנים את repo, מעתיקים את הטוקן ומדביקים אותו בתור הסיסמה. רעננו את העמוד ב-GitHub: הקבצים וה-commits שלכם שם! לחצו על "commits" כדי לראות את ההיסטוריה.

README.md: כדאי להוסיף לכל פרויקט קובץ README.md שמסביר מה הפרויקט. ‏GitHub מציג אותו בעמוד הראשי של הריפו. הוא כתוב ב-Markdown, שפה פשוטה לעיצוב טקסט: # כותרת, ‏**מודגש**, ‏- פריט ברשימה.

ההתחברות היא המקום שבו רוב הכיתה נתקעת. כדאי לבקש מהסטודנטים לפתוח חשבון GitHub לפני השיעור, ולהקדיש לזה זמן בכיתה. אם מישהו נתקע על הסיסמה, להפנות ישר לפסקה על Personal Access Token. אפשרות חלופית ומהירה: git push מתוך VS Code, שמטפל בהתחברות דרך הדפדפן.

העבודה השוטפת: push ו-pull

אחרי החיבור הראשון, המעגל היומיומי גדל בשלב אחד:

# עורכים ושומרים...
$ git add .
$ git commit -m "Add skills cards"
$ git push

ומה אם עבדתם על הפרויקט במחשב אחר (למשל במעבדה), או ששיניתם משהו ישירות באתר של GitHub? לפני שמתחילים לעבוד, מושכים את השינויים:

$ git pull
Updating 8b41d07..c3e9a12
Fast-forward

 1 file changed, 2 insertions(+), 2 deletions(-)
פקודהכיווןמתי

git pullGitHub ← מחשבבתחילת כל סשן עבודה

הרגל טוב: מתחילים לעבוד עם git pull, ומסיימים עם git push. ככה GitHub תמיד מעודכן, ואתם אף פעם לא עובדים על גרסה ישנה.

עשיתם git commit אבל לא git push. מה רואים ב-GitHub?

  • את ה-commit החדש
  • את המצב שהיה לפני ה-commit: הוא קיים רק במחשב שלכם
  • הודעת שגיאה

‏commit שומר רק בריפו המקומי. ‏GitHub מתעדכן רק כשעושים git push.

להוריד פרויקט קיים: git clone

‏clone מוריד ריפו שלם מ-GitHub, כולל כל ההיסטוריה, ויוצר לו תיקייה. משתמשים בזה כשרוצים להמשיך לעבוד על הפרויקט שלכם במחשב חדש, או כשרוצים להוריד פרויקט של מישהו אחר (למשל קוד לדוגמה מהקורס).

ב-GitHub לוחצים על הכפתור הירוק <> Code ומעתיקים את כתובת ה-HTTPS. ואז:

$ cd ~/Documents
$ git clone https://github.com/dana-cohen/profile-page.git
Cloning into 'profile-page'...
remote: Enumerating objects: 9, done.
Receiving objects: 100% (9/9), done.
$ cd profile-page
$ git log --oneline
  • לא מריצים git init אחרי clone. הריפו כבר קיים, וגם ה-remote (origin) כבר מוגדר.
  • אם זה הריפו שלכם, אפשר מיד לעבוד, לעשות commit ו-push.
  • אם זה ריפו של מישהו אחר, ‏push לא יעבוד (אין לכם הרשאה), אבל אפשר לקרוא ולשנות מקומית.

ענפים (branches): היכרות ראשונה

ענף הוא קו פיתוח נפרד. נניח שאתם רוצים לנסות עיצוב חדש לגמרי לדף, אבל לא לשבור את הגרסה שעובדת. יוצרים ענף, מנסים בו, ואם זה מוצלח ממזגים אותו חזרה ל-main.

  main:        A ── B ── C ─────────── F   (מיזוג)
                          \           /
  dark-theme:              D ──── E ─
# יוצרים ענף חדש ועוברים אליו
$ git switch -c dark-theme
Switched to a new branch 'dark-theme'
# עובדים ועושים commits כרגיל...
$ git add .
$ git commit -m "Try dark theme"
# חוזרים ל-main: הקבצים בתיקייה חוזרים למצב של main!
$ git switch main
# ממזגים את הענף לתוך main
$ git merge dark-theme
# רואים את כל הענפים (הכוכבית מסמנת איפה אתם)
$ git branch
  dark-theme
* main

בשיעור הזה מספיק להכיר את הרעיון. בפרויקטים עצמם נעבוד בעיקר על main. בעבודת צוות (בפרויקט הסיום) ענפים הם הכלי המרכזי: כל אחד עובד בענף משלו, ובסוף פותחים Pull Request ב-GitHub כדי למזג.

פתרון התנגשות (merge conflict)

כשאותה שורה השתנתה גם אצלכם וגם ב-GitHub, ‏Git לא יודע איזו גרסה לבחור, ולכן משאיר את ההחלטה לכם. בקובץ יופיע:

<<<<<<< HEAD
    <h1>דנה כהן: מפתחת Full-Stack</h1>
=======
    <h1>דנה כהן: מפתחת ווב</h1>
>>>>>>> origin/main
  1. החלק שבין <<<<<<< HEAD ל-======= הוא הגרסה שלכם. החלק שבין ======= ל->>>>>>> הוא הגרסה מ-GitHub.
  2. עורכים את הקובץ כך שיישאר רק מה שרוצים, ומוחקים את שלוש שורות הסימון. ‏VS Code מציע כפתורים נוחים: Accept Current, ‏Accept Incoming או Accept Both.
  3. שומרים, ואז:
$ git add index.html
$ git commit -m "Resolve title conflict"
$ git push

כשמשהו לא ברור: מריצים git status. בדרך כלל Git כותב בדיוק מה המצב ואיזו פקודה להריץ. ואם עדיין תקועים, מעתיקים את הודעת השגיאה המדויקת לחיפוש בגוגל. כמעט תמיד מישהו כבר נתקל בה.

תרגול מסכם

תרגיל 1: מאפס ל-GitHub בינוני

  1. צרו בטרמינל תיקייה חדשה בשם git-practice והיכנסו אליה.
  2. צרו ריפו, וקובץ index.html עם מבנה HTML בסיסי וכותרת עם השם שלכם.
  3. צרו קובץ .gitignore שמתעלם מ-.DS_Store.
  4. עשו commit ראשון.
  5. צרו ריפו ריק ב-GitHub בשם git-practice, חברו אותו ועשו push.
  6. הוסיפו פסקה ל-index.html, ועשו commit ו-push נוספים. ודאו ב-GitHub שיש 2 commits.
הצגת פתרון 
$ cd ~/Documents/web-course
$ mkdir git-practice
$ cd git-practice
$ git init
$ touch index.html .gitignore
# ב-VS Code: כותבים את ה-HTML ב-index.html, ומוסיפים ל-.gitignore את השורה .DS_Store
$ git add .
$ git commit -m "Add basic page and gitignore"
$ git remote add origin https://github.com/YOUR-USERNAME/git-practice.git
$ git push -u origin main
# מוסיפים פסקה ושומרים
$ git add .
$ git commit -m "Add intro paragraph"
$ git push

תרגיל 2: ביטולים בינוני

  1. בריפו מתרגיל 1, מחקו את כל התוכן של index.html ושמרו. (אופס!) החזירו אותו עם פקודת Git אחת.
  2. צרו קובץ secret.txt, הריצו git add ., ואז הוציאו רק אותו מאזור ההכנה. לבסוף הוסיפו אותו ל-.gitignore.
  3. עשו commit עם הודעה עם שגיאת כתיב, ואז תקנו את ההודעה.
הצגת פתרון 
$ git restore index.html
$ touch secret.txt
$ git add .
$ git restore --staged secret.txt
# מוסיפים את השורה secret.txt לקובץ .gitignore ושומרים
$ git status
# secret.txt לא מופיע יותר. ‏.gitignore מופיע כ-modified
$ git add .
$ git commit -m "Ignroe secret file"
$ git commit --amend -m "Ignore secret file"
$ git log --oneline

תרגיל 3: מחשב שני מאתגר

נדמה עבודה משני מחשבים, בעזרת שתי תיקיות:

  1. בתיקייה אחרת (למשל ~/Desktop), עשו clone לריפו git-practice. זה "המחשב השני".
  2. ב"מחשב השני", שנו את הכותרת, ועשו commit ו-push.
  3. חזרו לתיקייה המקורית, ומשכו את השינוי. ודאו שהכותרת התעדכנה.
  4. בונוס: צרו התנגשות בכוונה: שנו את אותה שורה בשתי התיקיות, ‏commit בשתיהן, ‏push מאחת, ו-pull בשנייה. פתרו את ההתנגשות.
הצגת פתרון 
$ cd ~/Desktop
$ git clone https://github.com/YOUR-USERNAME/git-practice.git
$ cd git-practice
# משנים את ה-h1 ושומרים
$ git commit -am "Change title"
$ git push
$ cd ~/Documents/web-course/git-practice
$ git pull

‏git commit -am הוא קיצור של add ו-commit יחד, אבל הוא עובד רק לקבצים ש-Git כבר מכיר (לא לקבצים חדשים).

בונוס: אחרי ה-pull יופיע CONFLICT. פותחים את הקובץ ב-VS Code, בוחרים גרסה (או משלבים), מוחקים את הסימונים, ואז git add ., ‏git commit -m "Resolve conflict" ו-git push.

תרגיל 1 הוא החובה של השיעור, ומבוצע ממילא כחלק מהפרויקט. תרגילים 2 ו-3 לבית. תרגיל 3 מכין לעבודת צוות. כדאי לבקש מהסטודנטים להגיש קישור לריפו ב-GitHub ולאתר ב-Netlify, ולבדוק שיש כמה commits עם הודעות משמעותיות ולא commit אחד ענק.

סיכום

  • ‏Git שומר היסטוריה במחשב. GitHub שומר עותק בענן ומאפשר לשתף.
  • שלושה אזורים: עבודה ← (add) ← הכנה ← (commit) ← מאגר. ומשם (push) ל-GitHub.
  • המעגל היומיומי: pull ← עבודה ← status ← add . ← commit -m ← push.
  • אפשר לבטל כמעט הכול: restore, ‏--amend, ‏revert.
  • ‏.gitignore מונע שמירה של קבצים מיותרים ושל סודות.
  • ‏Netlify מחובר ל-GitHub: כל push מעדכן את האתר.
  • תקועים? git status, ואז טבלת התקלות.
