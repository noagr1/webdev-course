ה-DOM ואירועים

⏱️ 35 דק׳ בכיתה 📚 3–4 שעות לימוד עצמי 🧩 דרישת קדם: חלקים א׳ ו-ב׳ (מערכים, אובייקטים, map ו-filter)

עד עכשיו כל ה-JavaScript שכתבנו הדפיס לקונסול. משתמש אמיתי לא רואה את הקונסול. הוא רואה את הדף: כפתורים, טקסטים, רשימות וטפסים. בחלק הזה נחבר סוף סוף את JavaScript ל-HTML ול-CSS משיעור 1: נלמד לשנות טקסט בדף, להוסיף ולמחוק אלמנטים, ולהגיב כשהמשתמש לוחץ, מקליד או שולח טופס.

כשאומרים "Vanilla JavaScript" (JavaScript "וניל", כלומר בלי ספריות כמו React) ומדברים על דפי אינטרנט, מדברים בעיקר על ה-DOM. כך נבנו אתרים במשך שנים, וזה מה שקורה "מתחת למכסה המנוע" גם היום. בסוף החלק נבנה רשימת משימות שלמה בדרך הזו, ואז נבין בדיוק איזו בעיה React פותרת, ולמה כמעט כל אפליקציה מודרנית משתמשת בה או בספרייה דומה.

מטרות החלק

בסוף החלק תדעו:

  • להסביר מה זה ה-DOM ואיך הדפדפן הופך HTML לעץ של אובייקטים
  • לבחור אלמנטים מהדף עם querySelector ו-querySelectorAll
  • לשנות טקסט, תכונות (attributes) ומחלקות CSS של אלמנטים
  • ליצור אלמנטים חדשים, להוסיף אותם לדף ולמחוק אותם
  • להציג רשימה מתוך מערך בעזרת פונקציית render
  • להגיב לאירועים: לחיצה, הקלדה ושליחת טופס
  • לעבוד בתבנית "נתונים ← render": לשנות את המידע, ולצייר מחדש את הדף
  • להסביר למה הגישה הזו מסורבלת באפליקציות גדולות, ומה React עושה אחרת

איך לעבוד עם העמוד: בעורכים של החלק הזה יש שתי לשוניות: HTML ו-JS (ולפעמים גם CSS). כשלוחצים ▶ הרצה, הדף מופיע בחלון "התוצאה", והקונסול מתחתיו. אפשר ללחוץ על כפתורים ולהקליד בתוך הדף שבתוצאה, ממש כמו באתר אמיתי. אם העורך צר מדי, הכפתור "⤢ הרחבה" שם את הקוד ואת התוצאה אחד מעל השני.

מה זה ה-DOM? 5 דק׳

כשהדפדפן מקבל קובץ HTML, הוא לא שומר אותו כטקסט. הוא קורא אותו ובונה ממנו בזיכרון עץ של אובייקטים: אובייקט לכל תגית, ואובייקט לכל קטע טקסט. העץ הזה נקרא DOM, ראשי תיבות של Document Object Model, כלומר "מודל האובייקטים של המסמך".

קחו למשל את הדף הקטן הזה:

<body>
  <h1>הרשימה שלי</h1>
  <ul>
    <li>חלב</li>
    <li>לחם</li>
  </ul>
  <button>הוספה</button>
</body>

הדפדפן בונה ממנו עץ כזה. כל "ענף" הוא אובייקט, שאפשר לקרוא אותו ולשנות אותו מ-JavaScript:

document
 └── html
      ├── head
      └── body
           ├── h1 ─── "הרשימה שלי"
           ├── ul
           │    ├── li ─── "חלב"
           │    └── li ─── "לחם"
           └── button ─── "הוספה"

כמה מילים שנשתמש בהן כל הזמן:

מונחמה זהבדוגמה
צומת / nodeכל פריט בעץ: תגית או טקסטה-ul, וגם הטקסט "חלב"
אלמנט / elementצומת שהוא תגיתh1, ‏ul, ‏li, ‏button
הורה / parentהאלמנט שמכיל אלמנט אחרul הוא ההורה של שני ה-li
ילדים / childrenהאלמנטים שנמצאים ישירות בתוך אלמנטהילדים של body: ‏h1, ‏ul, ‏button
documentהאובייקט שבראש העץ. דרכו מגיעים לכל השארdocument.body, ‏document.title

הנקודה החשובה: מה שמוצג במסך הוא תמיד ה-DOM, ולא קובץ ה-HTML. אם JavaScript משנה את ה-DOM, המסך מתעדכן מיד, אבל הקובץ במחשב נשאר כמו שהוא. כשמרעננים את הדף, הדפדפן בונה את העץ מחדש מהקובץ, וכל השינויים נעלמים.

לראות את ה-DOM בכלי המפתחים

  1. פתחו כל אתר (גם את העמוד הזה) ולחצו F12, או ⌘+⌥+I ב-Mac.
  2. עברו ללשונית Elements. מה שרואים שם הוא לא קובץ ה-HTML המקורי, אלא ה-DOM כמו שהוא עכשיו. אפשר לפתוח ולסגור ענפים עם החצים הקטנים.
  3. לחצו פעמיים על טקסט כלשהו ב-Elements ושנו אותו. הוא משתנה מיד בדף. רעננו, והשינוי נעלם. בדיוק כך נעבוד מ-JavaScript.
  4. עברו ללשונית Console והקלידו document.title ואחר כך document.body. הקונסול מראה לכם את האובייקטים עצמם.

גם בעורך באתר יש document, והוא מייצג את הדף שבחלון התוצאה. הריצו, ואחר כך שנו את הכותרת בלשונית HTML והריצו שוב:

שימו לב: בלשונית HTML הכותרת היא עדיין "הרשימה שלי", אבל בדף שבתוצאה היא השתנתה. זה בדיוק ההבדל בין הקובץ (ה-HTML שכתבנו) לבין ה-DOM (מה שהדפדפן מציג עכשיו).

5 דק׳. מומלץ להתחיל בהדגמה חיה בכלי המפתחים: לשנות טקסט באתר חדשות מוכר ב-Elements, ואז לרענן. הסטודנטים מבינים מיד ש"הדף" הוא משהו חי בזיכרון ולא קובץ. אחר כך לכתוב בקונסול document.querySelector('h1').textContent = 'שלום' על אותו אתר. זה רגע ה"וואו" של השיעור.

בחירת אלמנטים: querySelector 5 דק׳

לפני שמשנים משהו בדף, צריך "לתפוס" אותו: לקבל משתנה שמצביע על האלמנט. הדרך המודרנית והנוחה היא document.querySelector. היא מקבלת בורר CSS, בדיוק כמו אלה שכתבתם בשיעור 1, ומחזירה את האלמנט הראשון שמתאים לו:

הקודמה הוא מחזיר
document.querySelector('h1')ה-h1 הראשון בדף
document.querySelector('.price')האלמנט הראשון עם class="price"
document.querySelector('#title')האלמנט עם id="title"
document.querySelector('nav a')הקישור הראשון שנמצא בתוך nav
document.querySelectorAll('li')כל ה-li בדף, ברשימה (NodeList)
document.getElementById('title')האלמנט עם id="title" (דרך ישנה יותר, בלי #)

נסו לשנות: הדפיסו את הקישור השני בעזרת document.querySelectorAll('nav a')[1]. ‏NodeList עובדת כמו מערך: יש לה length, גישה עם [0] ו-forEach.

NodeList היא לא בדיוק מערך. יש לה forEach, אבל אין לה map או filter. כשצריך אותם, הופכים אותה למערך: [...document.querySelectorAll('li')]. זה ה-spread מחלק א׳.

כשהאלמנט לא נמצא: null

אם אין בדף אלמנט שמתאים לבורר, querySelector לא זורקת שגיאה. היא מחזירה null, כלומר "כלום". השגיאה מגיעה רק בשורה הבאה, כשמנסים לעשות משהו עם ה"כלום" הזה. זו כנראה השגיאה הנפוצה ביותר בעבודה עם ה-DOM. הריצו וקראו את ההודעה:

ההודעה Cannot set properties of null אומרת: "ניסית לשנות משהו בתוך null". כשרואים אותה, הצעד הראשון הוא תמיד לבדוק את הבורר: האם יש שגיאת כתיב? האם שכחתם נקודה (.) לפני שם מחלקה, או סולמית (#) לפני id? תקנו את הבורר ל-'.main-title' והריצו שוב.

🤔 בדף יש <p id="msg">שלום</p>. איזו שורה תמצא אותו?

  • document.querySelector('msg')
  • document.querySelector('.msg')
  • document.querySelector('#msg')
  • document.querySelectorAll('p.msg')

נכון! ‏id מסמנים ב-#, בדיוק כמו ב-CSS. ‏'msg' בלי סימן מחפש תגית בשם <msg>, ו-'.msg' מחפש מחלקה. שתיהן יחזירו null.

נסו לשנות את items ל-5 ולהריץ. שימו לב שכל החישוב נעשה ב-JavaScript, וה-DOM רק מציג את התוצאה. זה רעיון שנחזור אליו הרבה.

למה לא innerHTML?

תראו באינטרנט הרבה דוגמאות עם מאפיין בשם innerHTML. הוא דומה ל-textContent, אבל הדפדפן מפרש את מה ששמים בו כ-HTML, ולא כטקסט רגיל. זה נשמע נוח, אבל זה מסוכן כשהתוכן מגיע מהמשתמש.

דמיינו אתר תגובות שמציג כל תגובה עם innerHTML. משתמש זדוני כותב "תגובה" שהיא בעצם תגית HTML עם קוד JavaScript בתוכה. מעכשיו, כל מי שנכנס לדף מריץ את הקוד שלו. הקוד יכול לגנוב את פרטי ההתחברות של הגולשים, או לשלוח הודעות בשמם. התקפה כזו נקראת XSS (Cross-Site Scripting), והיא מהנפוצות ברשת.

עם textContent זה לא יכול לקרות: גם אם מישהו כותב תגיות, הן יוצגו כטקסט רגיל, עם הסוגריים המשולשים, ולא ירוצו. נסו בעצמכם:

הכלל בקורס: לטקסט משתמשים תמיד ב-textContent. כשצריך מבנה HTML חדש (למשל פריט ברשימה), יוצרים אותו עם createElement, כמו שנלמד בעוד רגע. כך אין סיכון. גם React עובדת כך: כל טקסט שמכניסים ל-JSX מוצג כטקסט ולא כ-HTML, בדיוק בגלל XSS.

XSS: לא צריך להעמיק, אבל כדאי שהסטודנטים יצאו עם הכלל "textContent לטקסט". כדאי להזכיר שמנועי חיפוש מלאים בדוגמאות ישנות עם innerHTML, ושגם כלי AI מציעים אותו לעתים קרובות. כשרואים innerHTML = משהו שהמשתמש הקליד בקוד, זה סימן אזהרה.

תכונות (attributes)

נסו לשנות את buy.disabled ל-false. שימו לב איך הכפתור חוזר להיות לחיץ.

עיצוב: style מול classList

יש שתי דרכים לשנות עיצוב מ-JavaScript:

  • element.style: משנה מאפיין CSS אחד ישירות על האלמנט. שמות המאפיינים כתובים ב-camelCase: ‏background-color הופך ל-style.backgroundColor.
  • element.classList: מוסיף או מוריד מחלקת CSS. את העיצוב עצמו כותבים מראש בקובץ ה-CSS.

נסו להוריד את ההערה (//) מהשורה של toggle, ולהריץ. ה-toggle הוריד את המחלקה כי היא כבר הייתה. עכשיו הורידו גם את ההערה מ-remove ובדקו מה קורה.

למה classList עדיף? העיצוב נשאר בקובץ ה-CSS, ו-JavaScript רק מחליטה איזה מצב פעיל: "מודגש", "פתוח", "שגיאה", "מצב כהה". קל יותר לשנות את העיצוב בלי לגעת בקוד, ואפשר להחליף בבת אחת הרבה מאפיינים עם מחלקה אחת. ‏style מתאים בעיקר לערכים שמחושבים בקוד, כמו רוחב של פס התקדמות באחוזים.

🤔 רוצים שכפתור "מצב כהה" יחליף בין מצב כהה לבהיר בכל לחיצה. מה הכי מתאים?

  • document.body.style.background = 'black'
  • document.body.classList.add('dark')
  • document.body.classList.toggle('dark')
  • document.body.textContent = 'dark'

נכון! ‏toggle מוסיפה את המחלקה אם היא לא קיימת ומורידה אותה אם היא קיימת, כך שכל לחיצה מחליפה מצב. ‏add עובדת רק בכיוון אחד. ואת textContent של body אסור לשנות ככה: זה מוחק את כל הדף!

הצגת רשימה ממערך: פונקציית render 5 דק׳

באפליקציות אמיתיות המידע מגיע כמערך: מוצרים מהחנות, הודעות בצ׳אט, משימות. בחלקים הקודמים למדתם לעבוד עם מערכים ואובייקטים. עכשיו נציג מערך כזה בדף. הרעיון: כותבים פונקציה בשם render (מלשון "ציור") שעוברת על המערך, יוצרת אלמנט לכל פריט, ושמה את כולם בדף.

נסו להוסיף מנה למערך (למשל { name: 'מרק עדשים', price: 34 }) ולהריץ. לא נגעתם ב-HTML בכלל, וה-DOM התעדכן לבד. זה כוחה של פונקציית render: המידע נמצא במקום אחד (המערך), והדף נבנה ממנו.

🎯 אתגר 1: רשימת מוצרים קל

השלימו את הפונקציה render כך שתציג כל מוצר מהמערך products כ-li בתוך <ul id="products">. הטקסט של כל פריט צריך להיות בפורמט שם - ₪מחיר, למשל מחברת - ₪12. השתמשו ב-createElement וב-textContent.

render() הוא הרעיון המרכזי של החלק. כדאי לצייר על הלוח: מערך בצד אחד, הדף בצד השני, וחץ שעליו כתוב render. כל מה שנעשה מעכשיו (אירועים, טפסים, todo) הוא: לשנות את המערך, ולקרוא שוב ל-render. בשיעור 4 החץ הזה יקבל שם: React.

אירועים: להגיב למשתמש 7 דק׳

עד עכשיו הקוד רץ פעם אחת, כשהדף נטען. אבל דף אינטראקטיבי צריך לחכות למשתמש: לעשות משהו כשהוא לוחץ, כשהוא מקליד, כשהוא שולח טופס. כל דבר כזה נקרא אירוע (event).

כדי להגיב לאירוע, "רושמים" אצל האלמנט פונקציה שתרוץ כשהאירוע קורה. עושים את זה עם addEventListener, שמקבלת שני דברים:

button.addEventListener('click', handleClick);
//                       ↑ איזה אירוע   ↑ איזו פונקציה להריץ כשהוא קורה

זה בדיוק ה-callback שלמדתם בשיעור 2: מעבירים פונקציה לפונקציה אחרת, והיא תקרא לה מאוחר יותר. כאן "מאוחר יותר" הוא כשהמשתמש לוחץ.

הריצו, ואז לחצו על הכפתור בחלון התוצאה. שימו לב לסדר בקונסול: קודם "הקוד סיים לרוץ", ורק אחר כך, בכל לחיצה, "לחצו על הכפתור". הפונקציה לא רצה כשכתבנו את addEventListener. היא רק נרשמה, ומחכה.

הבאג הקלאסי: סוגריים מיותרים

זו טעות שכמעט כל מתחיל עושה, ולכן כדאי להכיר אותה מראש:

הקודמה קורה
✅ button.addEventListener('click', handleClick)מעבירים את הפונקציה עצמה. היא תרוץ בכל לחיצה.
❌ button.addEventListener('click', handleClick())הסוגריים מריצים את הפונקציה מיד, פעם אחת, ומעבירים את מה שהיא החזירה (undefined). הלחיצות לא יעשו כלום.

הריצו ולחצו על הכפתור כמה פעמים. "היי!" הודפס פעם אחת, מיד בהרצה, ואחר כך כלום. מחקו את הסוגריים אחרי sayHi, הריצו שוב, ולחצו.

טפסים: submit ו-preventDefault 5 דק׳

בשיעור 1 בניתם טפסים ב-HTML. כשלוחצים על כפתור השליחה, ההתנהגות הרגילה של הדפדפן היא לשלוח את הטופס לשרת ולטעון דף חדש. ככה עבדו אתרים לפני 20 שנה. היום אנחנו רוצים לטפל בטופס ב-JavaScript, בלי לטעון מחדש את הדף. בשביל זה:

  1. מאזינים לאירוע submit על ה-form (לא על הכפתור). כך הוא עובד גם בלחיצה וגם כשלוחצים Enter בשדה.
  2. בתחילת הפונקציה קוראים ל-event.preventDefault(), שאומר לדפדפן: "אל תעשה את מה שאתה עושה בדרך כלל (טעינה מחדש). אני אטפל בזה."
  3. קוראים את הערכים מהשדות, בודקים אותם, ועושים משהו.

נסו: שלחו את הטופס ריק, אחר כך עם אימייל בלי @, אחר כך עם גיל 12, ובסוף עם פרטים תקינים. שימו לב איך return עוצר את הפונקציה ברגע שמצאנו בעיה. זה ה-"early return" מהשיעור הקודם.

ולידציה ב-HTML מול JavaScript: לבדיקות פשוטות אפשר להשתמש בתכונות HTML כמו required, ‏type="email" ו-min="16", והדפדפן יציג הודעה בעצמו. ב-JavaScript כותבים בדיקות שה-HTML לא יודע לעשות, כמו "שתי הסיסמאות זהות", ושולטים בדיוק בהודעה ובמיקום שלה.

🤔 כתבתם מאזין ל-submit, אבל בכל שליחה הדף "מהבהב", ההודעה שלכם מופיעה לשנייה ונעלמת. מה חסר?

  • form.reset()
  • event.preventDefault() בתחילת המאזין
  • return בסוף המאזין
  • להאזין ל-click במקום ל-submit

נכון! בלי preventDefault הדפדפן ממשיך בהתנהגות הרגילה שלו: שולח את הטופס וטוען את הדף מחדש. הטעינה מוחקת את כל מה ש-JavaScript שינתה, ולכן ההודעה נעלמת.

התבנית החשובה: נתונים ← render 7 דק׳

עד עכשיו כל מאזין שינה את הדף ישירות: "תכתוב כאן טקסט", "תוסיף פה מחלקה". בדף קטן זה עובד. אבל כשיש הרבה כפתורים שמשנים את אותו מידע, קל מאוד להגיע למצב שהדף מראה דבר אחד והמשתנים אומרים דבר אחר.

הפתרון הוא תבנית עבודה פשוטה, ששווה לזכור כי זו בדיוק הדרך שבה React חושבת:

אירועלחיצה, הקלדה, שליחה ← משנים את הנתוניםstate: משתנה, מערך, אובייקט ← קוראים ל-render()מציירת את הדף מחדש לפי הנתונים
  1. state (מצב): המשתנים שמחזיקים את המידע של הדף. למשל let count = 0 או מערך משימות.
  2. render: פונקציה אחת שיודעת לקחת את ה-state ולהציג אותו. היא לא מחליטה כלום, רק מציגה.
  3. מאזינים: כל מאזין רק משנה את ה-state, ואז קורא ל-render(). הם לא נוגעים בדף בעצמם.

הנה מונה עם שני כפתורים שבנוי בדרך הזאת. שימו לב שרק render כותבת לדף:

היתרון: ההודעה "פופולרי" תמיד נכונה, לא משנה איזה כפתור לחצו, כי היא מחושבת מחדש מה-state בכל פעם. אם מחר נוסיף כפתור שלישי, הוא רק צריך לשנות את likes ולקרוא ל-render.

🎯 אתגר 5: מונה עם איפוס קל

השלימו את המונה: + מעלה ב-1, − מוריד ב-1, ו"איפוס" מחזיר ל-0. עבדו לפי התבנית: כל מאזין משנה את count וקורא ל-render(). בונוס: אל תתנו למונה לרדת מתחת ל-0.

🤔 לפי תבנית state ← render, מה צריך לעשות מאזין ללחיצה על כפתור "מחק"?

  • למצוא את ה-li בדף ולהפעיל עליו remove()
  • להוריד את הפריט מהמערך, ואז לקרוא ל-render()
  • לקרוא ל-render() בלבד
  • לטעון מחדש את הדף

נכון! המאזין משנה רק את הנתונים, ו-render דואגת שהדף יתאים להם. אם רק נמחק את ה-li, הפריט עדיין יהיה במערך ויחזור ברינדור הבא. ואם רק נקרא ל-render בלי לשנות את המערך, שום דבר לא ישתנה.

דוגמה פתורה: רשימת משימות 8 דק׳

עכשיו נחבר את כל מה שלמדנו לאפליקציה קטנה אחת: רשימת משימות שאפשר להוסיף אליה, לסמן משימה כבוצעה ולמחוק. זו "אפליקציית ה-Hello World" של עולם הפרונטאנד, ובשיעור 5 נבנה אותה שוב ב-React. נבנה אותה בשלושה צעדים.

צעד 1: ה-state וה-render

כל משימה היא אובייקט עם id (מספר ייחודי, כדי שנוכל לזהות אותה), ‏text ו-done. הפונקציה render מוחקת את הרשימה ובונה אותה מחדש מהמערך:

let todos = [
  { id: 1, text: 'לקנות חלב', done: false },
  { id: 2, text: 'לסיים את שיעור 3', done: true },
];

function render() {
  const list = document.querySelector('#list');
  list.replaceChildren(); // מנקים את מה שהיה

  todos.forEach((todo) => {
    const li = document.createElement('li');
    li.textContent = todo.text;
    if (todo.done) li.classList.add('done');
    list.append(li);
  });
}

צעד 2: הוספה עם טופס

מאזין ל-submit שיוצר אובייקט חדש, מוסיף אותו למערך וקורא ל-render. בתור id משתמשים ב-Date.now(), שמחזיר את מספר המילישניות מאז 1970, כך שהוא כמעט תמיד שונה:

form.addEventListener('submit', (event) => {
  event.preventDefault();
  const text = input.value.trim();
  if (!text) return; // לא מוסיפים משימה ריקה

  todos.push({ id: Date.now(), text, done: false });
  input.value = '';
  render();
});

צעד 3: סימון ומחיקה

לכל משימה יוצרים בתוך render גם כפתור מחיקה ותיבת סימון, ומחברים אליהם מאזינים. כל מאזין "זוכר" את ה-todo שלו, כי הוא נוצר בתוך ה-forEach. המחיקה משתמשת ב-filter מחלק ב׳: משאירים את כל המשימות חוץ מזו שה-id שלה שווה.

הנה הכול יחד. הריצו, הוסיפו משימות, סמנו ומחקו:

שימו לב לשורת הסיכום. אף מאזין לא מעדכן אותה. היא תמיד נכונה, כי render מחשבת אותה מחדש מהמערך בכל פעם. זה הכוח של התבנית: מוסיפים תצוגה חדשה במקום אחד, וכל הפעולות "מקבלות" אותה בחינם.

הדוגמה הזאת היא לב השיעור (כ-15 דק׳ יחד עם האתגר הבא). מומלץ לבנות אותה בלייב מאפס לפי שלושת הצעדים, ולהריץ אחרי כל צעד. לפני צעד 3 כדאי לשאול את הכיתה: "איך נדע איזו משימה למחוק?" ולהגיע יחד ל-id.

אחרי שהכול עובד, לשאול: "כמה פעמים כתבנו render()? מה היה קורה אם היינו שוכחים אחת?" זו הכנה ישירה ל"למה React" בהמשך העמוד: ב-React אין צורך לקרוא ל-render בעצמנו.

🎯 אתגר 6: רשימת קניות עם טופס מאתגר

ה-state והפונקציה render כבר כתובים. כתבו מאזין ל-submit על הטופס שעושה את כל אלה:

  1. מונע את טעינת הדף מחדש.
  2. קורא את הטקסט מ-#item ומוריד רווחים בצדדים (trim).
  3. אם הטקסט ריק: כותב ב-#error הודעה (למשל "נא לכתוב שם של פריט") ולא מוסיף כלום.
  4. אחרת: מוסיף את הטקסט למערך items, מנקה את השדה ואת הודעת השגיאה, וקורא ל-render().

איך מחברים JavaScript לדף אמיתי 3 דק׳

בעורך באתר הקוד שלכם רץ אחרי שה-HTML כבר מוכן. בפרויקט אמיתי ב-VS Code צריך לדאוג לזה בעצמכם. מבנה התיקייה הרגיל:

my-todo/
├── index.html
├── style.css
└── script.js

וב-index.html מחברים את הקובץ בתוך ה-head, עם המילה defer:

<!DOCTYPE html>
<html lang="he" dir="rtl">
<head>
  <meta charset="UTF-8">
  <title>המשימות שלי</title>
  <link rel="stylesheet" href="style.css">
  <script src="script.js" defer></script>
</head>
<body>
  <ul id="list"></ul>
</body>
</html>

למה defer? הדפדפן קורא את ה-HTML מלמעלה למטה. בלי defer, הסקריפט ירוץ ברגע שהדפדפן מגיע אליו, כשה-body עוד לא קיים. אז document.querySelector('#list') יחזיר null, ותקבלו את השגיאה המוכרת Cannot read properties of null. ‏defer אומר: "תוריד את הקובץ עכשיו, אבל תריץ אותו רק אחרי שכל ה-HTML נקרא".

בקוד ישן תראו לפעמים שתי דרכים אחרות לאותה בעיה: לשים את ה-<script> בסוף ה-body, או לעטוף את כל הקוד ב-document.addEventListener('DOMContentLoaded', () => { ... }). שתיהן עובדות, אבל defer הוא הפשוט והמודרני ביותר.

אז למה צריך React? 5 דק׳

בניתם עכשיו אפליקציה אמיתית רק עם JavaScript ("Vanilla JS", כלומר JavaScript "רגיל" בלי ספריות). זה עובד, אבל תסתכלו כמה עבודה ידנית עשינו:

  • חיפשנו כל אלמנט בעצמנו עם querySelector, וקיווינו שלא טעינו בשם.
  • יצרנו כל תגית בנפרד: createElement, ‏textContent, ‏append. שלוש שורות לכל li.
  • חיברנו מאזינים אחד-אחד, גם לכפתורים שנוצרים מחדש בכל רינדור.
  • היינו צריכים לזכור לקרוא ל-render() אחרי כל שינוי. שכחתם פעם אחת? הדף מראה מידע ישן.
  • ה-render שלנו מוחקת ובונה את כל הרשימה מחדש, גם כשהשתנתה משימה אחת. ברשימה של 5,000 פריטים זה כבר איטי.

‏React נולדה בדיוק בשביל הבעיות האלה. הנה אותה רשימת משימות כפי שתיכתב ב-React (לא צריך להבין עכשיו כל שורה, רק להתרשם):

function TodoApp() {
  const [todos, setTodos] = useState([
    { id: 1, text: 'לקנות חלב', done: false },
  ]);

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id} className={todo.done ? 'done' : ''}>
          {todo.text}
          <button onClick={() => setTodos(todos.filter((t) => t.id !== todo.id))}>
            🗑️
          </button>
        </li>
      ))}
    </ul>
  );
}

מה אתם כבר מזהים כאן? ‏map ו-filter מחלק ב׳, ‏arrow functions, ‏מערך של אובייקטים עם id, ומאזין ללחיצה (onClick). ומה נעלם? אין querySelector, אין createElement, ואין קריאה ל-render. כשקוראים ל-setTodos, ‏React מציירת מחדש בעצמה, ומעדכנת רק את מה שבאמת השתנה.

החדשות הטובות: התבנית state ← render שלמדתם כאן היא בדיוק הדרך שבה React חושבת. מי שהבין את רשימת המשימות בעמוד הזה, יבין את React הרבה יותר מהר. וגם ב-React עדיין תשתמשו ב-event.preventDefault(), ב-event.target.value ובאירועים כמו click ו-submit.

🤔 מה הבעיה העיקרית ש-React פותרת, לעומת מה שעשינו בעמוד הזה?

  • ב-Vanilla JS אי אפשר לבנות רשימת משימות
  • React מריצה JavaScript מהר יותר
  • ב-React מתארים מה הדף צריך להראות לפי ה-state, והיא מעדכנת את ה-DOM בעצמה
  • ב-React לא צריך לכתוב JavaScript

נכון! הכול אפשרי גם ב-Vanilla JS, כמו שראיתם. React חוסכת את העבודה הידנית: את ה-querySelector, את ה-createElement ואת הצורך לזכור לקרוא ל-render.

כ-5 דק׳, וחשוב לא לדלג. זה הגשר לשיעור 4. כדאי לשים את קוד ה-Vanilla ואת קוד ה-React זה לצד זה על המסך, ולבקש מהכיתה לסמן מה משותף (map, filter, id, אירוע לחיצה) ומה נעלם. המטרה היא שהסטודנטים ירגישו את "הכאב" של העבודה הידנית, כדי ש-React תיראה כפתרון ולא כעוד דבר ללמוד.

🤔 הקוד document.querySelector('#list').append(li) נכתב בקובץ script.js שמחובר ב-head בלי defer. מה יקרה?

  • הכול יעבוד כרגיל
  • ה-li יתווסף לסוף הדף
  • שגיאה, כי ברגע שהסקריפט רץ ה-ul עוד לא קיים ו-querySelector מחזיר null
  • הדפדפן יחכה אוטומטית עד שה-HTML ייטען

נכון! בלי defer הסקריפט רץ ברגע שהדפדפן מגיע אליו ב-head, לפני שהוא קרא את ה-body. ‏querySelector מחזיר null, ו-null.append זורק שגיאה.

סיכום

  • ה-DOM הוא העץ שהדפדפן בונה מה-HTML. JavaScript יכולה לקרוא אותו ולשנות אותו, והדף מתעדכן מיד.
  • ‏querySelector מוצא אלמנטים, ‏textContent ו-classList משנים אותם, ו-createElement + append יוצרים חדשים. ‏innerHTML לא משתמשים, כדי להימנע מ-XSS.
  • ‏addEventListener מחבר פונקציה לאירוע: click, ‏input, ‏submit. בטפסים תמיד event.preventDefault(), ו-value הוא תמיד מחרוזת.
  • התבנית state ← render: מאזינים משנים רק את הנתונים, ופונקציה אחת מציירת את הדף לפיהם.
  • React לוקחת את אותה תבנית ועושה בשבילכם את העבודה הידנית. זה מה שנתחיל בשיעור 4.
